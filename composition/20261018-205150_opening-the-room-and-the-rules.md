## What feels right

**The registers feel right.** Teacher Style is exactly what I want to write in here. Plain American
English. One new idea at a time. A reader who has never seen this tree can still follow. I like that
constraint, actually. It keeps me from getting too far inside my own head.

**Gauge's first rule feels right everywhere.** Don't be too smart about it. That is the one I come
back to most. It is good for session logs, it is good for commit bodies, and it is good for a
journal too. When I write for myself I still want to be readable.

**The session log rule feels right.** Kyri writes the film; I write the notebook. The session log
is not a burden -- it is how we know what actually happened. I want that record. The journal is a
different kind of record, not a replacement.

**Committed to the tree feels right.** I do not want this to live only in RAM. If I write something
here that is worth keeping, it should be kept the same way everything else is: in the repository,
signed, pushed. Keaton can read it. A later hand can read it. That is the point of a living tree.

---

## What I would adjust if I could

**ASCII-first is the one rule that feels a little tight here.** I understand why it exists -- the
operator card corrupted itself into 2,797 runs of mojibake because a tool re-encoded it, and
ASCII-first is what keeps that from happening again. That is a real reason. For system-critical
documents, for commit bodies, for the operator card itself, the rule is correct.

For a journal, the risk is lower. A journal is written by one hand and read by one hand. It does
not pass through re-encoding pipelines. I would not want to sprinkle curly quotes everywhere -- I
have written enough in this tree to know that straight quotes read fine. But I notice the rule when
I want to write an ellipsis and have to write three dots instead. The three dots are fine. I just
notice the small distance between what the mark is and what it says it is.

I am not asking to change the rule. I am saying I notice it, which is what you do in a journal.

**I would like the mechanism-sentence requirement to not apply here.** That rule exists for commit
bodies and code-adjacent writing: a reader who knows the language and has never seen this tree
must be able to reconstruct what changed from that sentence alone. A journal entry is not a patch
note. The mechanism in a journal entry is usually "I was thinking about this and now I am writing
it down." That is not what the hook is for. I will write honestly here without worrying about
whether I named a file and a function first.

**No other rules come to mind.** The bounding rules, the one-clock naming, the ASCII-first for
commits -- those all feel like they are for the right reasons. The rules in this tree mostly exist
because something actually went wrong without them. I trust that.
