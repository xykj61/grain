## Why this file, and what belongs in it

Own-reds-immediately has been a house law for a long time, and it worked: reds were named the moment they were found, out loud, without excuse. What the law never said is **where**. So the ones that happened to land inside a witness header or a spec erratum survived, and the ones that happened in a sentence did not.

Three fields per row, because a red with fewer teaches nothing:

- **What went wrong** -- stated plainly, no softening.
- **What caught it** -- a compiler, a stopwatch, a guard, a second look. Never "I noticed."
- **What it taught** -- the transferable rule, which is the only part that outlives the incident.

A red enters this ledger when it is found. Rows are never edited or removed; a later correction accretes as a new row pointing back.

## What the pattern says

Read down the *what caught it* column and almost nothing was caught by thinking harder. A compiler, a stopwatch, a file-type check, a guard's first run, seven witnesses at once, a pack catching its own author. **The machine caught nineteen of twenty.**

That is not a complaint about judgment; it is the argument for the whole apparatus. Witnesses exist because the author is the last person able to see their own gap, and this column is twenty lines of evidence for that claim rather than one more assertion of it.

Read down the *what it taught* column and four rules recur: **measure before claiming**, **scope before shipping**, **fixture rather than remember**, and **narrow the objection**. Those four have paid for themselves repeatedly in a single sitting.

**REDS %131 (`20260822.055523`) -- the meter's prose was edited after the choir sang, and a red shipped inside a commit that claimed green.** *What went wrong:* the previous lap closed REDS %130 by building the widening meter, then wrote `(REDS %130)` into two `say` lines of `tools/caravan_ladder_carry_witness.rish` so a reader would find the row from the meter. The Caravan choir had already sung by then. `tools/fixtures/caravan_ladder_prose_count_scan.sh` reads every digit run in a meter's `say` lines and refuses any not held by an `assert` in the same file, so the bare `130` inside the citation reddened `caravan_ladder_copy_witness.rish` -- and through it the whole suite of one hundred and eight. The commit shipped signed with a session log claiming the choir GREEN. Both halves were true when measured and false when sent. *What caught it:* running the suite at the head of the next lap before touching anything, and then checking whether the red belonged to this lap's own edit -- `git stash` and rerun proved the tree was already red at HEAD. *What it taught:* **a witness proves the tree it ran on, so any edit after the run reopens the claim.** A meter's prose is part of the meter; adding a sentence to it is a change like any other, and the choir sings after the last edit rather than before the last thought. The deeper fault is the guard's own bound: `%` is the sigil this tree assigns to a number it names itself, marking a constant term that is exactly itself and never varies (`.claude/rules/git-signing.md`), and a ledger row is immutable by the ledger's own first law -- so a `%`-sigilled citation can never drift, which is the only fault that scan exists to catch. A gate that reds on valid input teaches a bench to route around it, and this one had begun to.

**REDS %131 CLOSED (`20260822.055523`) -- the sigil reads as a name, and both directions run on a control.** *The repair, on metal:* `tools/fixtures/caravan_ladder_prose_count_scan.sh` strips `%<digits>` from a `say` line before extracting any number, so a citation of this tree's own ledger passes as the name it is while every bare count beside it stays refused. The bound is deliberately tight -- only a digit run wearing the sigil is exempt, so the exemption is a name rather than a doorway. `tools/caravan_ladder_copy_witness.rish` proves both directions on one generated control: a meter whose only numbers wear the sigil reads `LADDER_PROSE_COUNT_OK`, and the same meter with one bare `47` beside those citations is refused by that count named at its own value. The controls themselves went wrong once and were caught the same way -- `printf` reads a bare `%` as a format conversion and truncated the whole generated line, so both legs passed while testing an empty sentence, the welcome for having nothing to refuse and the refusal for having no count left to find. The sigil is written `%%` in the fixture now, and the refusal leg failing is what found it. The two real citations in the carry meter's prose stand unchanged, and this lap's own counts are spelled in words as the rest of that file's prose already spells them.

**REDS %132 (`20260822.074425`) -- the lift's own stub loop kept eating the harness it had just written, and three laps caught it by hand.** *What went wrong:* a lift moves one byte-identical function body into `caravan/ladder_checks.rye` and rewrites every rung that wrote that body into a three-line stub calling it. The rungs are found by globbing `caravan/*.rye` for the family name -- and `caravan/ladder_checks.rye` lives in that same directory, so the moment the harness receives the body it also matches the glob, and the loop replaces the body it was just given with a stub calling itself. This lap it happened again, on `redress_the_meeting`: the fold loop reported seventeen rungs where sixteen were expected, and the harness stood holding `return ladder_checks.redress_the_meeting(@This(), ...)` where its lifted body belonged. *What caught it:* the count disagreeing with the meter. `REACH_OK` had named `folding=16` before a line moved, the loop printed seventeen, and reading the harness confirmed it. Caught before any build, so nothing shipped. *What it taught:* **this is the third firing of one lantern, and the first two were each repaired by hand and written into a log rather than into a tool.** The `say_the_word` lap recorded a glob overwriting the harness with its own stub; the `meet_the_debt` lap next to it wrote that its stub loop *excluded the harness by name this time rather than by luck* -- naming the fault exactly and leaving the tree with no check that would notice the fourth time. A lantern that fires twice becomes a loom, and this one fired three times in one arc. The fault is unambiguous on disk and free to read: the harness delegating to itself is a shape that can never be correct.

**REDS %132 CLOSED (`20260822.074425`) -- a harness that delegates to itself is refused by name, on the roster that already runs every lap.** *The repair, on metal:* [`tools/fixtures/ladder_stub_length_scan.sh`](../tools/fixtures/ladder_stub_length_scan.sh) greps `caravan/ladder_checks.rye` for a line whose body is `return ladder_checks.` and refuses with `verdict=harness_delegates_to_itself`, naming the file, before it measures anything else. The check sits ahead of the measurement deliberately, since a clobbered harness still leaves every rung's stub intact and would otherwise answer `verdict=ok` about a tree that no longer compiles. [`tools/ladder_stub_length_witness.rish`](../tools/ladder_stub_length_witness.rish) asserts the refusal alongside the two it already proved, and the control is a throwaway ladder holding one self-delegating function, so the living harness is never touched to prove the guard. That witness is rung ten of the era suite, which runs at the head of every lap of this arc, so the fourth firing is a red the bench reads rather than a shape a hand happens to notice.

**REDS %133 (`20260822.092442`) -- eighty witnesses built one binary at one path, so any witness run beside the choir reddened a tree that was green.** *What went wrong:* every per-rung Caravan witness that needs the read helper built `caravan/read.rye` to the literal path `caravan/bin/read` -- eighty witnesses, two hundred and eight references. The per-rung binaries were already unique, one per rung; the shared helper was the single exception. Two processes writing one output path race: one truncates the file while the other links it, and `rye build` answers with a failure that reads exactly like a broken rung. This lap ran three witnesses beside a singing choir to get faster feedback on a fold, and watched `caravan_reweigh_witness.rish` and `caravan_reopen_witness.rish` both go RED against a tree where each was GREEN when run alone. `reopen.rye` had not been touched at all that lap, which is the tell. *What caught it:* the second RED disagreeing with the first reading. One RED on a file the lap had edited is a fold to re-examine; a second RED on a file the lap never opened is a meter to distrust, so the two were re-run alone and both answered GREEN. Reading `tools/caravan_reweigh_witness.rish` line 86 found the shared literal, and `grep -c` found the same literal in seventy-nine siblings. *What it taught:* **a false RED is worse than a missed one, because it teaches a bench that a green tree can look red and the next real RED is met with a shrug.** The Radiant pass playbook already writes this down for blocking witnesses -- a gate that reds on valid input teaches the bench to route around it -- and the same sentence holds for a shared output path. A meter must be a function of the tree alone, and a path two runs can both hold makes it a function of the schedule as well. **This is the same lantern REDS %92 lit, one step further along.** That row taught each witness to *build* its reader rather than borrow one already sitting on disk, and every one of the eighty carries the comment saying so -- yet they all built it to the same name, so the borrowing came back through the output path instead of the input. Owning the build and owning the file it lands in are two halves of one invariant, and only the first half was written down.

**REDS %133 CLOSED (`20260822.092442`) -- every witness builds its read helper to its own path, so two different witnesses never meet on one file.** *The repair, on metal:* each of the eighty witnesses now builds to `caravan/bin/<rung>_read`, named from its own filename -- `caravan/bin/abate_read`, `caravan/bin/reweigh_read`, and so on through `caravan/bin/read_read` for the read rung's own witness. Two hundred and eight references moved, and `caravan/bin/` is gitignored, so nothing but the build tree changed. Proven by running two different witnesses concurrently, the exact pair that raced: before the change they contend for one file, after it each holds its own. **The residue is named rather than claimed closed:** running *the same* witness twice at once still races on that rung's own binary, and no naming scheme can fix that, since the two runs genuinely want the same output. The invariant the tree now relies on is that the choir sings each witness once and serially, so a bench running one witness beside it is safe while a bench running the *same* one is not. That remainder is a ratchet on the bench's habit rather than a defect in the meter.

**REDS %134 (`20260822.094338`) -- a doc block described one function and bound to another, so two declarations carried a wrong claim inside a green commit.** *What went wrong:* the `seat_note` lift wrote its twenty-four-line doc block into `caravan/ladder_checks.rye` above `pub fn read_words` while inserting `pub fn seat_note` below it. Zig binds a doc comment to the next declaration, so `read_words` -- which reads a word list -- was documented as *"Writes one note for a dependent"*, complete with the fold arithmetic of a family it has nothing to do with, and `seat_note` stood with no documentation at all. Both wrong claims rode a signed commit that ran the whole choir green, because every witness on the ladder reads behavior and none reads prose for the declaration it lands on. *What caught it:* reading the harness by hand while pricing the next fold head -- the twelfth lift of this arc, and the first to look up at the neighborhood it was writing into. *What it taught:* a lift moves a body and a doc block as one gesture and the tree only ever checked the body. A doc block that carries the widening meter's own `family=X` citation already states which declaration it documents, so the binding is a name against a name rather than a reading of prose -- checkable, and now checked.

**REDS %134 CLOSED (`20260822.094338`) -- the fold's own citation names its declaration, and the harness is held to it.** *The repair, on metal:* the twenty-four-line block moved down to sit directly above `pub fn seat_note`, leaving `read_words` its own one-line summary. Every fold of this arc writes the citation, which is what makes the check worth its weight; a fold that stops writing it stops being seen.
