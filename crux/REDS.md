## Why this file, and what belongs in it

Own-reds-immediately has been a house law for a long time, and it worked: reds were named the moment they were found, out loud, without excuse. What the law never said is **where**. So the ones that happened to land inside a witness header or a spec erratum survived, and the ones that happened in a sentence did not.

Three fields per row, because a red with fewer teaches nothing:

- **What went wrong** -- stated plainly, no softening.
- **What caught it** -- a compiler, a stopwatch, a guard, a second look. Never "I noticed."
- **What it taught** -- the transferable rule, which is the only part that outlives the incident.

A red enters this ledger when it is found. Rows are never edited or removed; a later correction accretes as a new row pointing back.

## What the pattern says

Read down the *what caught it* column and almost nothing was caught by thinking harder. A compiler, a stopwatch, a file-type check, a guard's first run, seven witnesses at once, a pack catching its own author. **The machine caught nineteen of twenty.**

That is not a complaint about judgment; it is the argument for the whole apparatus. Witnesses exist because the author is the last person able to see their own gap, and this column is twenty lines of evidence for that claim rather than one more assertion of it.

Read down the *what it taught* column and four rules recur: **measure before claiming**, **scope before shipping**, **fixture rather than remember**, and **narrow the objection**. Those four have paid for themselves repeatedly in a single sitting.

**REDS %133 (`20260822.092442`) -- eighty witnesses built one binary at one path, so any witness run beside the choir reddened a tree that was green.** *What went wrong:* every per-rung Caravan witness that needs the read helper built `caravan/read.rye` to the literal path `caravan/bin/read` -- eighty witnesses, two hundred and eight references. The per-rung binaries were already unique, one per rung; the shared helper was the single exception. Two processes writing one output path race: one truncates the file while the other links it, and `rye build` answers with a failure that reads exactly like a broken rung. This lap ran three witnesses beside a singing choir to get faster feedback on a fold, and watched `caravan_reweigh_witness.rish` and `caravan_reopen_witness.rish` both go RED against a tree where each was GREEN when run alone. `reopen.rye` had not been touched at all that lap, which is the tell. *What caught it:* the second RED disagreeing with the first reading. One RED on a file the lap had edited is a fold to re-examine; a second RED on a file the lap never opened is a meter to distrust, so the two were re-run alone and both answered GREEN. Reading `tools/caravan_reweigh_witness.rish` line 86 found the shared literal, and `grep -c` found the same literal in seventy-nine siblings. *What it taught:* **a false RED is worse than a missed one, because it teaches a bench that a green tree can look red and the next real RED is met with a shrug.** The Radiant pass playbook already writes this down for blocking witnesses -- a gate that reds on valid input teaches the bench to route around it -- and the same sentence holds for a shared output path. A meter must be a function of the tree alone, and a path two runs can both hold makes it a function of the schedule as well. **This is the same lantern REDS %92 lit, one step further along.** That row taught each witness to *build* its reader rather than borrow one already sitting on disk, and every one of the eighty carries the comment saying so -- yet they all built it to the same name, so the borrowing came back through the output path instead of the input. Owning the build and owning the file it lands in are two halves of one invariant, and only the first half was written down.

**REDS %133 CLOSED (`20260822.092442`) -- every witness builds its read helper to its own path, so two different witnesses never meet on one file.** *The repair, on metal:* each of the eighty witnesses now builds to `caravan/bin/<rung>_read`, named from its own filename -- `caravan/bin/abate_read`, `caravan/bin/reweigh_read`, and so on through `caravan/bin/read_read` for the read rung's own witness. Two hundred and eight references moved, and `caravan/bin/` is gitignored, so nothing but the build tree changed. Proven by running two different witnesses concurrently, the exact pair that raced: before the change they contend for one file, after it each holds its own. **The residue is named rather than claimed closed:** running *the same* witness twice at once still races on that rung's own binary, and no naming scheme can fix that, since the two runs genuinely want the same output. The invariant the tree now relies on is that the choir sings each witness once and serially, so a bench running one witness beside it is safe while a bench running the *same* one is not. That remainder is a ratchet on the bench's habit rather than a defect in the meter.

**REDS %134 (`20260822.094338`) -- a doc block described one function and bound to another, so two declarations carried a wrong claim inside a green commit.** *What went wrong:* the `seat_note` lift wrote its twenty-four-line doc block into `caravan/ladder_checks.rye` above `pub fn read_words` while inserting `pub fn seat_note` below it. Zig binds a doc comment to the next declaration, so `read_words` -- which reads a word list -- was documented as *"Writes one note for a dependent"*, complete with the fold arithmetic of a family it has nothing to do with, and `seat_note` stood with no documentation at all. Both wrong claims rode a signed commit that ran the whole choir green, because every witness on the ladder reads behavior and none reads prose for the declaration it lands on. *What caught it:* reading the harness by hand while pricing the next fold head -- the twelfth lift of this arc, and the first to look up at the neighborhood it was writing into. *What it taught:* a lift moves a body and a doc block as one gesture and the tree only ever checked the body. A doc block that carries the widening meter's own `family=X` citation already states which declaration it documents, so the binding is a name against a name rather than a reading of prose -- checkable, and now checked.

**REDS %134 CLOSED (`20260822.094338`) -- the fold's own citation names its declaration, and the harness is held to it.** *The repair, on metal:* the twenty-four-line block moved down to sit directly above `pub fn seat_note`, leaving `read_words` its own one-line summary. [`tools/fixtures/ladder_doc_attachment_scan.sh`](../tools/fixtures/ladder_doc_attachment_scan.sh) then reads every doc block in the harness that cites `family=X` -- seven of them, the citation wrapping across lines where the prose wrapped -- and refuses any block whose family differs from the `pub fn` beneath it, with `verdict=doc_names_another_declaration`. [`tools/ladder_doc_attachment_witness.rish`](../tools/ladder_doc_attachment_witness.rish) proves three legs on generated controls: a block citing `seat_note` above `pub fn read_words` is refused in the exact shape the red wore, a harness carrying no citation refuses rather than blessing its own blindness, and a correctly attached block is welcomed -- because a gate that reds on valid input teaches a bench to route around it. GREEN on metal at `cited=7 docs_adrift=0`. **The residue is named rather than papered over:** the guard binds only blocks carrying a `family=` citation, so a doc block written without one is checked by a reader alone. Every fold of this arc writes the citation, which is what makes the check worth its weight; a fold that stops writing it stops being seen.

**REDS %135 (`20260822.102337`) -- a one-clock stamp cited in a meter's prose was refused as a recited count, and the same lantern had already fired once.** *What went wrong:* the widening column split landed, and `tools/caravan_ladder_carry_witness.rish` updated its queue prose to cite the design read behind it -- `active-designing/20260822-101058_what-a-widening-costs-a-rungs-door.md`. `tools/fixtures/caravan_ladder_prose_count_scan.sh` reads every digit run in a `say` line and refuses any not held by an `assert` in the same file, so the stamp's `20260822` and `101058` both reddened `tools/caravan_ladder_copy_witness.rish` and through it the whole choir of one hundred and eight. Neither digit run is a count. A one-clock stamp is fixed by `context/specs/20260627-102012_one-clock-naming-law.md` at the moment a file is named and can never drift, which is the only fault that scan exists to catch. *What caught it:* running the full Caravan choir after the split rather than only the witness the split touched. The copy witness named the file, the line, and both values. *What it taught:* **this is REDS %131 arriving a second time in a different shape, and the first repair was written narrower than its own reasoning.** That row exempted a `%`-sigilled row name because `%` marks a constant term that is exactly itself and never varies -- yet the sentence it was really proving is that **a digit run belonging to a name cannot drift, so it is not a count**. Written as `%`-only, the rule covered one of the two immutable-name shapes this tree writes and left the other to fire. A lantern that fires twice becomes a loom, so the exemption is now stated at the level of the reasoning rather than at the level of the one example that prompted it.

**REDS %135 CLOSED (`20260822.102337`) -- both one-clock shapes read as names, and a bare number beside a stamp still refuses.** *The repair, on metal:* [`../tools/fixtures/caravan_ladder_prose_count_scan.sh`](../tools/fixtures/caravan_ladder_prose_count_scan.sh) strips the two shapes the naming law defines -- `YYYYMMDD-HHMMSS_` in a filename and `YYYYMMDD.HHMMSS` in a body field -- from a `say` line before extracting any number, exactly as it already strips `%<digits>`, and the comment beside the strip now names the reasoning both shapes share rather than the sigil alone. The bound stays as tight as the sigil's: only a **full** stamp is exempt, so a bare eight-digit number is still a count named at its own value. Two legs prove it on generated controls in [`../tools/caravan_ladder_copy_witness.rish`](../tools/caravan_ladder_copy_witness.rish), sitting directly beneath the sigil pair whose reasoning they extend: a meter citing a dated path and a body stamp reads `LADDER_PROSE_COUNT_OK`, and the same sentence with a bare `20260822` beside the stamp is refused at that value -- one refusal, on the bare number alone, which is what proves the exemption is a name rather than a doorway.
