# e187 — Q51 · tend doctrine: what tending touches, and what it never touches

**Stamp:** `20260801.140138` · **Voice:** Riyo · **Seat:** J4 Q51 · **Status:** GREEN

**Tending is weaving, never removal.** A tend lap takes orphaned dated
artifacts and gives them a living thread to hang from — an index row, a
season page mention, a `current-as-of:` header accreted per the oldness
cycle — so relevancy travels by accretion, never by rename and never by
deletion. The census names candidates; the lap touches only the classes
and rooms Keaton's word names; and every tended file remains byte-identical
in history, provable by the tend witness that Q54 owes.

**What tending never touches, by standing law:** any SAFE.md row · any
dated artifact's body (headers accrete above, bodies stay sealed) · keys,
custody, wire vocabulary · `PERSONALIZE.brix`, `first_season_answers.brix`,
`key-card.conf` · anything shred-shaped — the instruments hold shred RED
and tending gives no one a reason to ask them otherwise. A tend that would
make a file harder to find is not a tend; a tend that deletes is a breach
wearing the wrong name, and this doctrine refuses it the room.

**The lap's own gate, restated:** Q53 begins only at Keaton's
class-and-rooms word — the word names which classes (for instance:
session-log greens · elder waymarks · consumed recursions) in which rooms,
and the lap weaves exactly those and nothing more, reporting a reach delta
with zero losses.
