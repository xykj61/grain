## What this is

A picture in Grain is **verified bytes that decode, deterministically and within named bounds, to a pixel grid** — and everything a keeper does with that picture is a pure, bounded function over the grid, the source never mutated. No network is asked to read a pixel; no key, no funds, no permission. An image is yours the way a page in a notebook is yours: held in your own hand, decoded by code small enough to read whole, addressed by its own content so a tampered byte refuses **by name** rather than painting garbage.

This module is the floor beneath Season A's **parts marketplace** and its **Photos app**. It answers the plainest question a device family can ask — *can the person who holds it also hold every picture on it?* — with yes, proven on metal.

## The three arcs, each closed whole

### Open Image — the codec and its guarantees (HUNK0–HUNK3)

- **`qoi.rye`** — a whole open **QOI** codec, encode and decode, so `decode(encode(pm))` recovers a pixmap **byte-for-byte** across all six chunk kinds (rgb · rgba · index · diff · luma · run). Real compression, and five corruptions each refusing by name rather than reading past the end. Witness: `tools/hunk_qoi_witness.rish`.
- **`../pond/apps/image_artifact.rye`** — an image becomes a content-addressed **Tablecloth** artifact. `store_image` beads a picture under a name that pins a SHA3 content address; `fetch_image` reassembles it, proving **every bead against its digest first**, so a tampered bead refuses `DigestMismatch` and an unknown name refuses `UnknownArtifact` — each *before the codec reads a single pixel*. Same image under two names stores once (the dedup dividend). Witness: `tools/hunk_artifact_witness.rish`.
- **`../brushstroke/image_skate.rye`** — the decoded grid meets **Skate**: `down_map` averages each block to the nearest of a seven-color anchor palette and wears it over a full-block glyph, so a picture paints on the glass surface. Witness: `tools/hunk_skate_witness.rish`.
- **`photos.rye` — `crop`** — the first Photos verb, pure and bounded: read a rectangle, return a fresh smaller image, source untouched; coordinates checked in `u64` so a rectangle can never wrap. Witness: `tools/hunk_photos_witness.rish`.

### The parts marketplace — McMaster-Carr's one-sheet trick, with honest facts (HUNK4–HUNK7 · HUNK71–HUNK93)

One decoded sheet serves a whole catalog. `sprite.rye` binds each product name to a bounded **window** into a single decoded image and renders it by reusing `photos.crop` — every window bound-checked in `u64` at **add time**, so a render can never fail on bounds. `../pond/apps/sprite_store.rye` gives the sheet a content-addressed identity; `sprite_catalog.rye` lets the index itself travel as a flat-Bron `format sprite-catalog-v1` record, so `render(parse(render(x)))` is a fixed point. Disjoint windows never leak a neighbor's bytes; the sheet is shared and unmutated across every render.

A part is a picture *with its facts*. `part_catalog.rye` binds each product's window to a **part number**, a **material**, and a **price in cents** — recorded as a `u64` fact, never a balance the tree can move — so a `PartCatalog` holds one `SpriteIndex` (the pictures) and one record per product (the facts) in the same order, grown together so a part is never a window without facts. The whole catalog travels as `format part-catalog-v1`, a fixed point over *both* halves. `../pond/apps/part_store.rye` gives the catalog a content address: `store_catalog` beads its text, `open_catalog` fetches it back **verified before the parser reads a window or a price**, so a whole marketplace — pictures and prices — reproduces from cold out of *(sheet, catalog address)*, a tampered catalog refusing `DigestMismatch`. Witnesses: `tools/hunk_sprite_*_witness.rish`, `tools/hunk_part_catalog_witness.rish`, `tools/hunk_part_store_witness.rish`.

A keeper searches the catalog by its facts, and the **boolean query algebra stands whole** (HUNK75–HUNK85). `part_filter.rye` reads a single `key:value` clause over the stored facts; `part_query.rye` parses it; `part_and.rye` narrows a line of clauses to the **intersection** (a match-all empty line), `part_or.rye` widens it to the **union** (a match-none empty line) — the two true De Morgan duals, OR always a superset of AND. `part_facets.rye` joins them into the canonical faceted query — **OR within a facet** (values joined by `|`), **AND across facets** (groups by space), so `material:stainless-304|material:brass max:100` means *(stainless or brass) and under a dollar*; a `|`-free line is exactly HUNK78's conjunction, a strict superset that disturbs nothing. On glass, `../brushstroke/part_and_search.rye`, `../brushstroke/part_or_search.rye`, and `../brushstroke/part_facets_search.rye` draw exactly the narrowed, widened, or faceted page — *what a keeper types is what a keeper sees* — a price clause **comparing** a recorded cent count, never moving one (custody gate #3 untouched). Above the shelf, `../brushstroke/part_search_header.rye` (the pure AND) and `../brushstroke/part_facets_header.rye` (the whole faceted grammar) **echo the canonical query and its *N results* count**, stacked into one screen a keeper reads top to bottom — the echo a **fixed point of the parser**, so the header shows the query the machine understood, never a hopeful transcript, and its count is exactly the number of parts drawn beneath it (no drift). `../brushstroke/part_facets_paged.rye` carries the page into that header — ***page N of M*** above the very page of parts it names, a zero-result line carrying no page at all. `../brushstroke/part_facets_sort.rye` sorts the result **cheapest-first** — `sort_by_price` reorders the parts a query kept by their recorded cent count, ascending, ties keeping held order (a **stable** sort, a **permutation** of the result — same parts, only reordered), and `facets_sorted_shelf` draws that page least dear at the top, a price still **compared and reordered by, never moved** (custody gate #3 untouched). `../brushstroke/part_facets_sorted_screen.rye` closes the arc — `format_sorted_header` appends **`sorted by price`** to the paged header (only when a result exists) and `facets_sorted_screen` stacks it over the sorted shelf, so a keeper reads *what I asked · how many · which page · that it is sorted by price* above the cheapest-first parts, the word naming the order it sits over (no drift). `../brushstroke/part_facets_sort_desc.rye` turns the sort **both ways** — `sort_by_price_desc` reads the same result **dearest-first**, ties still kept in **held order** (so descending is not a naive reversal; on distinct prices it is the exact reverse of ascending), and `facets_sorted_desc_shelf` draws that page high to low, answering *what is the best they have* beside *what can I afford*. `../brushstroke/part_facets_sort_dir.rye` names the direction over the page — a `SortDir` drives both the header tail (**`sorted by price low to high`** or **`high to low`**) and the shelf it sits over, so `facets_sorted_screen_dir` can never let the label disagree with the order (the `high to low` header sits over the dearest part first, `low to high` over the cheapest), and the two directions read as exact reverses on a distinct result. `../brushstroke/part_facets_sort_query.rye` hands the direction to the keeper — a **`sort:price-asc`** or **`sort:price-desc`** directive anywhere in the typed line is lifted out (default ascending when absent, `UnknownSortValue` on a bad value, `DuplicateSort` on a second), and the stripped rest rejoins as the faceted query byte-for-byte, so `facets_sorted_query_screen` draws the keeper's chosen direction from one honest line — a strict superset of HUNK92 (a line with no directive behaves exactly as ascending). Witnesses: `tools/hunk_part_filter_witness.rish`, `tools/hunk_part_and_witness.rish`, `tools/hunk_part_or_witness.rish`, `tools/hunk_part_facets_witness.rish`, `tools/hunk_part_and_search_witness.rish`, `tools/hunk_part_or_search_witness.rish`, `tools/hunk_part_facets_search_witness.rish`, `tools/hunk_part_search_header_witness.rish`, `tools/hunk_part_facets_header_witness.rish`, `tools/hunk_part_facets_paged_witness.rish`, `tools/hunk_part_facets_sort_witness.rish`, `tools/hunk_part_facets_sorted_screen_witness.rish`, `tools/hunk_part_facets_sort_desc_witness.rish`, `tools/hunk_part_facets_sort_dir_witness.rish`, `tools/hunk_part_facets_sort_query_witness.rish`.

### The Photos app — edit without ever losing the original (HUNK8–HUNK70)

Named plainly **Photos**, built entirely on the module above. Every gesture is a pure verb over the grid, added **additively** beside `crop`:

- **Orient** — `flip_h`, `flip_v`, `rotate_quarter`, proven by the algebra they obey (four quarter-turns are identity; a mirror is its own inverse).
- **Resample** — `scale` (nearest-neighbor), `scale_bilinear` (smooth), and `scale_area` (clean downscale), each refusing a zero-dimension or over-ceiling target before it allocates.
- **Soften** — `blur` (`box_blur`, `box_blur_h`, `box_blur_v`), the separable box mean the whole soft-image family stands on — a drop shadow, a frosted panel, a gentler photo — bounded by `blur_max_radius` and deterministic byte-for-byte; and `gaussian` (`gaussian_blur`, `gaussian_blur_passes`), the smooth blur a stack of box means gives by the central limit theorem — a point spreads into a rounded **peak** where a single box left a plateau, the shape frosted glass and a soft shadow both want.
- **Crispen** -- `sharpen` (`sharpen`, `unsharp_mask`), the image minus its own blur: the classic **unsharp mask** adds back the detail (`orig - gaussian_blur`) so every edge the blur eased is made steeper, with `amount` a percent of the detail (0 the identity, 100 full strength). A flat field has zero detail and stays exactly itself, so a sharpen crispens edges without manufacturing noise; a strong amount overshoots and clamps to a rail rather than wrapping. The crispening a resized thumbnail or a scanned page wants.
- **Detect** -- `edges` (`edges`, `edge_magnitude`), the **Sobel** operator: two signed directional kernels estimate the image's gradient, and the edge strength is the integer L1 magnitude `|gx| + |gy|` (no float, no square root) so a boundary lights and a flat interior stays dark. Measured per color channel with `gain` a percent lift for faint edges; alpha is carried from the source, so the edge map stays visible exactly where the source was. The first step of every outline, mask, and shape-finding pass.
- **Filter** -- `convolve` (`convolve`, `emboss`, `laplacian`), the **general signed 3x3 kernel** the specific convolutions descend from: nine signed weights over the window, a `divisor` that normalizes the sum, and a `bias` added after, so `clamp((sum(weight*window) / divisor) + bias)` per color channel is one line that embosses, finds a Laplacian outline, or runs a keeper's own filter. The **identity** kernel reproduces the source byte-for-byte -- the general contains the special. `convolve_n` widens it to a general **NxN** kernel at any odd radius (a 5x5 box mean, a 5x5 Gaussian, a motion blur), a radius-1 `KernelN` reproducing the 3x3 verb byte-for-byte. `separable` runs the **fast path** for the many kernels that are an outer product of a 1D horizontal and a 1D vertical kernel (every box, every Gaussian, a motion blur) in **two 1D passes** at `2*(2r+1)` taps rather than `(2r+1)^2` -- the two-pass result byte-for-byte the one-pass `convolve_n`, because both normalizations defer to a single divide and the clamp-to-edge border is itself separable.
- **Reshape** -- `morphology` (`dilate`, `erode`, `open`, `close`), the first **nonlinear** rank filter beyond the convolution floor: where a convolution returns a weighted **sum** of its window, morphology returns the window's **max** (dilate) or **min** (erode) over a square structuring element, a rank no linear kernel can express. Dilate grows a bright mark and fills a dark speck; erode shrinks a bright mark and wipes a bright speck; `open` (erode then dilate) removes a speck smaller than the element and `close` fills a gap smaller than it. Separable exactly as the box blur is, so a square dilate is a horizontal max pass then a vertical -- byte-for-byte a full-window reference max. Two laws make the pair one primitive: **duality** (`erode(x)` equals `255 - dilate(255 - x)`) and **idempotent opening** (opening an opened image changes nothing). Every channel including alpha, so it grows or shrinks a mask; the shape cleanup a surface runs for a thicker outline, a filled speck, or a trimmed halo.
- **Outline** -- `morphology_gradient` (`gradient`, `gradient_outer`, `gradient_inner`), the **detect** verb of the morphology floor, the rank-filter twin of `edges`: dilate and erode disagree exactly at a **transition**, so their difference `dilate(x) - erode(x)` is the **thickness** of the boundary at each pixel -- dark on a flat interior or exterior, bright at every edge, measured with no float and just a subtraction. One subtraction over three operand pairs: the full `gradient` (a boundary two pixels thick) decomposes exactly into the **outer** ring (`dilate - src`, just outside a shape) plus the **inner** ring (`src - erode`, the shape's own edge), two disjoint halves of the one boundary whose sum is the full gradient byte-for-byte. Extensivity (`dilate >= src >= erode`) keeps every difference a real byte, so no channel underflows and the ring sum never saturates; a pure difference image, so a flat-alpha source reads a zero alpha channel. The outline, mask border, and contour a surface reaches for the day it wants a shape's edge.
- **Residue** -- `morphology_tophat` (`white_tophat`, `black_tophat`), the **residue** verbs of the morphology floor: where the gradient lights a shape's boundary, the top-hat lights a shape's **small features** -- exactly the detail an opening or a closing removes. The **white** top-hat `src - open(src)` recovers the bright peaks an opening erases (a highlight, a bright scratch, text brighter than its page); the **black** top-hat `close(src) - src` recovers the dark valleys a closing fills (a dust speck, a dark crack, text darker than its page). One subtraction over two operand pairs, both non-negative bytes by the ordering laws: opening is anti-extensive (`open(src) <= src`) so `src - open >= 0`, closing is extensive (`close(src) >= src`) so `close - src >= 0`, neither ever underflowing. The two are **duals** under complement -- `black_tophat(x)` equals `white_tophat(complement(x))` byte-for-byte, one primitive seen from both sides -- and each is a pure difference image, so a flat-alpha source reads a zero alpha channel. The uneven-illumination correction, small-feature detection, and background flattening a surface reaches for the day it wants to lift text off a page or a fleck off a photo.
- **Reshape (any element)** -- `structure` (`dilate_se`, `erode_se`), the **general** the square morphology is one shape of: dilate (max) and erode (min) over an **arbitrary set of `(dx, dy)` offsets**, not only a `(2r+1)x(2r+1)` box. A square offset set reproduces the separable `morphology` verbs byte-for-byte (the **general contains the special**, exactly as `convolve_n`'s widest kernel reproduces `convolve`), so nothing is lost; yet the shape is now free. A **cross** grows a dot into a plus and leaves the diagonal corners untouched where a square would fill them; a **line** is a directional element that widens along one axis and leaves the other whole; a **disk** leaves a round footprint; the paired templates a **hit-or-miss** transform reads are two such sets. One gather serves both verbs and every shape (a comptime `is_max` chooses the rank), each offset clamped at the border so no read leaves the buffer, and erode and dilate stay **duals** under complement for any element symmetric through its center. The offset count is bounded (`structure_max_offsets`, a 256x256 ceiling); a **wide square** still runs faster through the separable `morphology` verbs, so the general path is for the arbitrary shapes those cannot express.
- **Detect (template)** -- `hitmiss` (`hit_or_miss`), the **exact-configuration** detector the general element opens: mark every pixel where a **foreground** template fits the shape AND a disjoint **background** template fits the ground around it. It composes as two `structure.erode_se` fits intersected -- `erode(A, fg) AND erode(complement(A), bg)` -- so a pixel lights only where every foreground offset lands on shape and every background offset lands on ground. An **isolated point** (foreground the center, background the eight neighbors) lights a lone pixel with no neighbor; a convex **corner** (foreground the corner and its two inward neighbors, background the three outward ones) lights a true corner. When the two templates share an offset no pixel can match (a cell cannot be both shape and ground), so the result is empty -- the **disjointness law**. The output is a binary image, opaque **white** at a match and opaque **black** elsewhere; the plane pins alpha opaque so the complement never turns a solid mask transparent, and a pixel counts as shape when its red channel is at least 128. The floor **thinning**, **skeletonization**, and endpoint / junction detection all descend from, each a hit-or-miss with a chosen pair of templates.
- **Thin (to a skeleton)** -- `thin` (`thin_once`, `thin`), the thinning floor **skeletonization**, pruning, and endpoint detection descend from: iterate the hit-or-miss transform and **subtract** every match until a whole pass changes nothing. One step is a **set difference** -- `thin_once(A, fg, bg) = A AND NOT hit_or_miss(A, fg, bg)` -- so a step can only remove a pixel, never add one (**anti-extensive**, `thin_once(A) <= A`). Iterating shrinks the on-set monotonically to a **fixed point**: feed the classic skeleton template pair and its rotations and a shape reduces to its one-pixel medial line; feed a directional edge template and it peels a shape from one side (a 4-wide block under the right-edge peel template thins to its single leftmost column over three productive passes, then converges). Termination is a **bound**, not a hope -- each productive pass removes at least one foreground pixel, so the pass count is at most the initial foreground count, and the driver asserts that ceiling. The shape of the thinning is the caller's template, exactly as `structure` leaves the shape of the element to the caller; the driver owns only the set difference and the loop, `hitmiss` owns the match beneath it.
- **Skeleton (Golay pack)** -- `skeleton` (`skeletonize`, `thinning_pack`), the medial-axis skeleton the general thinning driver was built to run: sweep the **classic eight** hit-or-miss pairs -- the two Golay structuring elements (an **edge** template and a **corner** template), each in its four rotations -- in order, each `thin.thin_once` subtracting its match, until a whole sweep changes nothing. The pack is chosen so a skeleton **preserves** a shape's medial structure rather than eroding it away: a one-pixel-wide line or cross matches no template -- every pair needs a full three-cell foreground side or an L of foreground, which a thin line never presents -- so a line **survives** a sweep untouched (a one-pixel plus is a fixed point in zero productive sweeps) where a plain **erosion** would delete it, while a solid block thins to a strictly smaller, non-empty, connected medial figure and then holds it. Termination is a **bound** -- each productive sweep removes at least one foreground pixel, so the sweep count is at most the initial foreground count. Compose not braid: this rung owns only the template geometry and the multi-pair sweep loop; `thin` owns the set-difference step, `hitmiss` the match, `structure` the fit gather.
- **Endpoints (skeleton tips)** -- `endpoints` (`detect_endpoints`, `endpoint_pack`), the topological detector the skeleton opens: mark every **endpoint** of a mask -- a foreground pixel of **degree one** (exactly one foreground neighbor), the tip where a thinned figure ends. It is exactly a hit-or-miss with an **eight-template** pack -- an **edge** base (center plus one edge neighbor) and a **diagonal** base (center plus one corner neighbor), each in its four rotations, covering the eight single-neighbor directions -- **unioned** by a per-channel **max**, exactly as `hitmiss` ANDs its two fit planes by a min. A one-pixel line lights its **two** tips and not its degree-two middle; a plus lights its **four** arm tips while its degree-four center stays dark; a **lone dot** of degree zero lights **nothing** (an endpoint is degree exactly one, never zero). The floor **pruning** descends from -- a pruning pass sheds a skeleton's short spurs by detecting the spur tips and peeling them, so the tips must be nameable first. Compose not braid: this rung owns only the endpoint template geometry and the union loop; `hitmiss` owns each match, `structure` the fit gather. **Branch / junction** detection (degree three or more) is the named sibling.
- **Prune (shed short spurs)** -- `prune` (`prune`, `prune_max_length`), the cleanup pass the endpoint detector opens: shed every parasitic branch no longer than a chosen `length`, then restore the surviving branches whole. The classic two-phase morphological prune (Gonzalez & Woods) composes exactly from the rungs already standing -- **strip** endpoints `length` times to peel every free end (a spur of length <= `length` **vanishes**, its whole run eaten), then **restore** by seeding the surviving skeleton's own ends and **conditionally dilating** them `length` times within the original figure (`X3 <- (X3 dilate 3x3) AND A`), so a real branch longer than `length` regrows exactly the pixels the strip took and returns **whole**. A long diagonal line with a short diagonal spur off its center junction keeps its whole length while the spur vanishes entirely (the spur a clean degree-two chain the strip peels, the junction well past `2*length` from each end so the reconstruction never reaches the spur base); the same diagonal with no spur is a **fixed point** of pruning. The one honest subtlety is the reconstruction's reach -- a spur whose base sits within `length` of a surviving end can partly regrow (the textbook approximate result), so clean removal is proven for a branch longer than `4*length`. Compose not braid: this rung owns only the binary set algebra (union, intersect, difference), the 3x3 restore element, and the two-phase control flow; `endpoints` owns the endpoint set, `structure` the dilation gather, `qoi` the buffers.
- **Branch / junction (degree three or more)** -- `branch` (`detect_branches`, `branch_min_crossing`), the other half of skeleton topology beside the endpoint detector: mark every **junction** of a mask -- a foreground pixel where **three or more** branches meet, a Y, a T, a plus, an X-crossing. Where an endpoint is degree one (eight configs, so `endpoints` reads a template pack), a junction is degree three or more -- 219 configs, far too many to enumerate -- and a naive neighbor **count** is wrong too, since it false-flags the pixels flanking an orthogonal junction (the pixel just below a plus's center is 8-adjacent to the center's two arm pixels, so a count reads degree four there too). The right tool is the **crossing number** (the Rutovitz connectivity number): walk the eight neighbors in a ring and count the foreground **arcs** -- an endpoint has one arc, a path pixel two, a junction three or more; a lone dot and the solid interior of a blob have zero. So a diagonal Y lights its one meeting point (crossing number three) and a one-pixel plus lights only its degree-four center, while the four pixels flanking that center -- naive degree four, crossing number **two** -- correctly stay dark. An out-of-bounds neighbor is **ground**, never a phantom, so a pixel at the image edge counts only its real neighbors (the honest topology for a degree measure, diverging on purpose from the rank-filter clamp `structure` uses). Compose not braid: this rung owns only the crossing-number gather (the eight-neighbor ring and its arc count) and the degree threshold; `hitmiss` decides the binary meaning of a pixel (one source of truth shared with the endpoint detector), `qoi` owns the buffers.
- **Zhang-Suen (parallel thinning)** -- `zhang_suen` (`skeletonize`), the classic 1984 medial-axis thinning most references teach, the parallel counterpart to `thin`'s hit-or-miss subtraction: delete every **removable boundary point** in two alternating sub-iterations, all deletions decided from the same input plane and applied **together**, until a whole cycle removes nothing. A foreground pixel is removable when it has **two to six** foreground neighbors (a real boundary pixel, neither a speck nor deep interior), a **crossing number of one** (image/branch.rye's `A(P1)` -- exactly one foreground arc, so the pixel is *simple* and deleting it cannot disconnect its neighbors), and the sub-iteration's directional pair leaves a corner open; sub-iteration one peels the south-east corner, sub-iteration two the north-west, so the shape thins symmetrically toward its center line. The crossing-number condition is exactly why a **one-pixel line survives** where a plain erosion would eat it: an interior line pixel has two arcs, a line end one neighbor, so neither is ever removable -- the skeleton keeps its length and its tips (a solid 3x3 block reduces to its single center pixel, the true medial point, in one productive cycle; a one-pixel horizontal line is a fixed point). Termination is a **bound** -- each productive cycle removes at least one pixel, so the cycle count is at most the initial foreground count. Compose not braid: this rung owns only the neighbor-count `B`, the two directional conditions, and the parallel loop; `branch` owns the ring gather and the crossing number `A` (one source of truth for the connectivity test), `qoi` the buffers.
- **Label (connected components)** -- `label` (`label_components`, `colorize`, `LabelMap`), the segmentation floor every blob count, region filter, and character isolation descends from: partition a mask's whole foreground into its maximal **8-connected** pieces and give each its own dense, raster-ordered label (0 background, 1..count each a component). The topology rungs so far read a shape's **local** structure (where a skeleton ends, where it branches); this rung reads its **global** structure -- how many marks a mask holds and which pixels belong to the same one. Two foreground pixels share a component when a chain of **8-adjacent** foreground pixels joins them, so pixels touching only at a **corner** are one piece, not two -- the decisive difference from 4-connectivity, and the natural match to the 8-neighbor topology `branch` and `zhang_suen` already use. The algorithm is the classic **two-pass** labeling with **union-find** equivalence resolution (Rosenfeld & Pfaltz, 1966): a raster sweep gives each foreground pixel a provisional label, taking the minimum of its four already-visited 8-neighbors and **unioning** them, so a component that opens two labels before the sweep learns they meet (the two arms of a U, joined only at the bottom) is recorded as one; a second pass resolves each provisional label to its root and **compacts** the roots to a gap-free range 1..count in raster order of first appearance, so the labels a caller reads are small and deterministic. `colorize` is the natural render -- background black, each component a distinct bright palette color -- so a labeling is a real image the open QOI codec round-trips byte-for-byte. Everything is bounded before a byte is allocated: a component can never open more than one label per pixel, so the union-find parent array is sized to the pixel count and `TooManyLabels` guards the impossible overflow by name. Compose not braid: this rung owns only the union-find, the two-pass sweep, and the raster-order compaction; `branch`'s `is_on` decides the binary meaning of a pixel (one door shared with `hitmiss`, `endpoints`, and `zhang_suen`), `qoi` owns the buffers.
- **Distance (chamfer transform)** -- `distance` (`distance_chamfer`, `colorize`, `DistanceMap`), the metric floor a distance-based erode/dilate, a watershed, and a shape-thickness reader all descend from: measure every foreground pixel of a mask to the nearest **background** pixel, so background is 0, a pixel one step from the edge is small, and the heart of a thick shape is large -- the field whose local maxima trace a shape's spine, exactly what `skeleton` and `zhang_suen` thin a shape down toward. Where `label` reads a mask's **global** topology (which pixels form one piece), this rung reads its **metric** structure (how deep inside the foreground each pixel lies). The algorithm is the classic **chamfer 3-4** transform (Borgefors, 1986), a two-pass integer approximation of the Euclidean distance with no floating point and no square root: it weights an **orthogonal** step 3 and a **diagonal** step 4 (the ratio 4/3 = 1.33 approximating sqrt(2) = 1.41 at one third the true scale), a **forward** raster pass relaxing each pixel against its four already-visited neighbors (W, NW, N, NE) and a **backward** reverse-raster pass against the other four (E, SE, S, SW). Two passes suffice because every shortest chamfer path is monotone in one sweep direction, so the backward pass carries in exactly the distances the forward could not see (a background pixel down-and-right of a mark reaches it only on the second pass). `colorize` renders the field to a real image -- background black, depth ramped dark-to-bright -- that the open QOI codec round-trips byte-for-byte. Everything is bounded before a byte: a chamfer distance never exceeds `dist_diagonal * max(width, height)` = 32768, so `dist_far` (the "no background reached yet" sentinel) sits far above any real distance and below `maxInt(u32)`, leaving room to add a step weight without overflow. Compose not braid: this rung owns only the chamfer weights, the two-pass min-relaxation sweep, and the render ramp; `branch`'s `is_on` decides the binary meaning of a pixel, `qoi` owns the buffer, `color`'s `mix` blends the ramp.
- **Reshape (true radius)** -- `distance_morph` (`erode_radius`, `dilate_radius`), the true-radius morphology the distance field opens: erode and dilate a mask by a disk of `r` pixels read in one pass off the chamfer field (`distance`), not gathered over a structuring element. **Erosion** keeps the foreground pixels whose distance to the nearest background **exceeds** `r * dist_orthogonal`, so a solid 3x3 block erodes by radius 1 down to its single center; **dilation** runs the same transform on the **complement** mask and keeps every pixel **within** that threshold, so a lone dot grows into a **plus** -- its four orthogonal neighbors lit at chamfer 3 and its four diagonal corners dark at chamfer 4, a true **Euclidean disk** of radius 1 where a square-element `morphology`/`structure` dilate lights the corners too. One transform, two thresholds, and the two verbs are **exact duals** by construction (`erode(A)` equals the render-complement of `dilate(complement(A))` byte-for-byte). It runs in the distance transform's two linear passes **no matter how large the radius**, where a structuring-element gather costs the element's whole area -- the reason to reach for it when the radius is large. The output is a binary mask (opaque white on, opaque black off) that reads foreground through the same `branch.is_on` door, so a reshaped mask feeds straight back into the family; the radius is bounded, and a zero radius, an over-max radius, and an empty source refuse by name. Compose not braid: this rung owns only the radius-to-threshold scale and the keep/drop threshold; `distance` owns the transform, `branch.is_on` the binary meaning, `qoi` the buffers.
- **Regions (size and bounding box)** -- `regions` (`measure_regions`, `filter_min_area`, `render_mask`, `Region`), the measurement floor a blob filter, a size histogram, and a character isolator descend from: the natural consumer of `label`. Where the labeler answers **how many** marks a mask holds and **which** pixels share one, this rung answers **how big** each piece is and **where** it sits. `measure_regions` reads a LabelMap in one raster pass and returns one `Region` per component -- its **area** (foreground pixel count) and its tight **bounding box** (the smallest axis-aligned rectangle enclosing it, corners inclusive). The box is a genuinely different fact from the area: an L or a diagonal fills far fewer pixels than the rectangle around it (an L of three pixels sits in a two-by-two box of four cells), so a surface tells a compact blob from a sprawling one by comparing the two. `filter_min_area` is the measurement's first payoff -- the **despeckle** a segmentation reaches for: drop every component below an area threshold to background and **recompact** the survivors to a dense 1..count, so a mask flecked with single-pixel noise comes back clean with only its real marks, still raster-ordered. `render_mask` closes the loop -- it renders a labeling back to a plain binary mask (foreground white, background black, opaque), read through the same `branch.is_on` door, so a despeckled labeling feeds straight back into `label`, `distance`, `morphology`, or the paint rungs. Everything is bounded before a byte: the region slice is sized to the label count and the survivor remap to count + 1; an empty source refuses by name. Compose not braid: this rung owns only the per-label accumulation, the survivor remap, and the binary render; `label` owns the LabelMap, `branch.is_on` the binary meaning, `qoi` the buffer.
- **Medial axis (distance ridge)** -- `medial_axis` (`medial_mask`, `colorize`, `medial_axis_of`, `is_ridge`), a shape's metric **spine** read as the **ridge of local maxima** of the chamfer distance field, the natural consumer of `distance` and the complement of `zhang_suen`'s thinning. A foreground pixel is on the medial axis when **no eight-neighbor holds a strictly greater distance** -- it sits at the crest of the field, no neighbor deeper. This reaches the same medial figure `zhang_suen` thins toward, by a different route with a different guarantee: **thinning** peels boundary points to a guaranteed **unit-width** skeleton that keeps topology yet loses the thickness; the **distance ridge** keeps the thickness -- every ridge pixel still carries its own distance, the radius of the maximal disk that fits there, so the ridge plus its depths **reconstructs** the shape (the medial axis transform). A solid 3x3 block reads depth 6 at its center and 3 around its ring, so the medial axis is that single center spine pixel; a one-pixel line reads a uniform depth so the ridge keeps it **whole** (the anti-erosion property thinning also has). The honest cost, named plainly rather than hidden: the ridge is **not guaranteed unit-width** -- an even-thickness bar reads one depth across its whole cross-section, so its entire width is a local maximum and the ridge comes back two pixels wide, where `zhang_suen` would thin it to a single row. The two routes are complements, neither the other's replacement. `medial_mask` renders the ridge to a plain binary white-on-black mask the family consumes through the same `branch.is_on` door; `colorize` renders the **medial axis transform** -- the spine alone, each pixel ramped dark-to-bright by its depth, a non-ridge foreground pixel black -- a real image the open QOI codec round-trips byte-for-byte. Compose not braid: this rung owns only the local-maximum ridge test and the two renders; `distance` owns the field, `branch.is_on` the binary meaning, `qoi` the buffer, `color`'s `mix` the depth ramp; an off-image neighbor is ground never a phantom, and an empty field refuses by name.
- **Watershed (marker flood)** -- `watershed` (`watershed`, `colorize`, `watershed_color`, `is_watershed`), the segmentation move `label` cannot make: **separate touching blobs** a connected-component labeler reads as one. Two objects that touch share an 8-connected component, and no local test can split them; this rung treats the distance field (`distance`) as **terrain**, seats a source at each object's deep center (a **marker**, exactly the medial ridge `medial_axis` reads), and **floods** outward -- where two floods meet, a thin **watershed line** falls, the cut that tells the two apart. The algorithm is **Meyer's ordered flooding** (the marker-controlled watershed, F. Meyer 1991), an immersion of the **inverted** distance field: the markers sit deepest (highest distance, the object centers), so flooding from those minima processes the deepest foreground first and the shallowest last. A **hierarchical (bucket) queue** keyed by terrain height gives the flood a strict, deterministic order in linear time -- each foreground pixel enters the queue at most once and the water level only rises. When a pixel is reached, its already-labeled neighbors decide it: one basin among them claims it, **two** different basins make it a watershed pixel, and a watershed pixel never floods its own neighbors, so the line is one pixel thin and holds the basins apart. A single solid bar the labeler calls **one** component, seated with a marker at each end, comes back **two** basins with a line between them; one marker floods a lone blob whole with no line. The result is a `LabelMap` whose basins are the markers' own labels 1..count, a watershed pixel marked `wshed_mark`, and background 0; `colorize` paints the basins their palette colors (reusing `label`'s palette), the watershed line white, the background black -- a real image the open QOI codec round-trips byte-for-byte. Everything is bounded before a byte: the queue threads through a `next` array sized to the pixel count; an empty field, a wrong-size marker map, no markers, and a depthless field each refuse by name. Compose not braid: this rung owns only the ordered flood (terrain inversion, bucket queue, one-basin/two-basins decision); `distance` owns the terrain, `label` owns the marker and output types and the palette, `branch`'s `is_on` the binary door, `qoi` the buffer.
- **Segment (auto watershed)** -- `segment` (`segment`, `auto_markers`, `markers_of_field`), the capstone the topology arc climbed toward: **segment a bare mask into its separated objects** with no hand-seated markers. Where `watershed` separates two touching objects by flooding from a marker at each object's deep center, it asks the caller to seat those markers by hand; this rung finds them automatically. The heart of a thick object reads deepest in the chamfer distance field (`distance`), so every distinct object shows as its own **peak** -- exactly the medial ridge `medial_axis` reads -- and giving each connected ridge component its own basin label (`label`) is **one marker per distance peak, seated at the deepest place**, with no hand at all. Then flood: the pipeline is distance field -> regional-maxima markers -> Meyer's flood, and a bare mask comes back segmented. The crux, proven on metal: two 3x3 blocks touching only at a **corner** are **one** 8-connected component a labeler reads as a single object, yet the distance field has **two** peaks, so `auto_markers` finds two markers (one at each block's deep center, the shallow corner touch never seeded) and `segment` returns **two** basins with a watershed line between them -- the two blocks told apart **from a bare mask**. `segment` equals `distance` -> `markers_of_field` -> `watershed` byte-for-byte (the marker-selection wiring proven, not a black box). The honest boundary, named rather than hidden: a lone block has one peak and stays **whole**; the very 9-wide bar `watershed` splits into two with **hand** markers comes back **one** basin under auto-markers, since a uniform bar has one connected ridge and no second object to find (auto-markers respects true structure, never inventing a cut); and a single object with several distinct distance peaks can **over-segment** -- the h-maxima remedy that keeps only significant peaks is the named horizon this rung composes toward. `watershed.colorize` renders a segmentation to a real image the open QOI codec round-trips byte-for-byte; a zero-size source refuses `EmptySource` and a mask with no foreground refuses `NoMarkers` by name. Compose not braid: this rung owns only the marker-selection choice and the end-to-end wiring; `distance` owns the terrain, `medial_axis` the ridge, `label` the ridge-component labeling and the marker/output type, `watershed` the flood and its colorize.
- **H-maxima (shallow-peak suppression)** -- `hmaxima` (`hmaxima`, `markers_hmax`, `segment_hmax`), the named remedy the segment capstone composes toward: keep only the **significant** distance peaks so a lumpy single object stops **over-segmenting**. Where `segment` seeds one marker per distance peak -- right when every peak is a real object, over-reaching when one object has several bumps -- this rung suppresses every peak whose **prominence** (its rise above the highest saddle connecting it to a taller peak) falls below a threshold `h`. The tool is the **h-maxima transform** (Soille): lower the field to `distance - h` (clamped at 0), then reconstruct it back up **under** the original field by **geodesic dilation** -- grow the marker by a 3x3 flat dilation capped pixelwise at the mask, repeated until it stops changing (Vincent's forward/backward hybrid). A shallow peak is absorbed; a tall peak survives, lowered by `h` yet still a distinct crest. The crux, proven on metal: a 5x5 lobe fused by a one-pixel neck to a 3x3 lobe is **one** 8-connected component, yet the raw field has **two** unequal peaks so `segment` over-cuts it into two basins; `hmaxima` at a threshold above the shallow lobe's prominence and below the deep lobe's keeps exactly **one** significant marker on the deep lobe, so `segment_hmax` returns **one whole basin** with no watershed line. Suppressing by `h=0` is the identity (the field unchanged byte-for-byte); reconstruction never rises above the mask and background stays 0. The honest bound, named plainly: `h` is a **caller's knob** -- too small and a bumpy object still over-segments, too large and two genuine objects merge; there is no single right `h` for every image, and the caller owns the choice. `markers_hmax` and `segment_hmax` are the same pipelines `segment` runs with this suppression spliced in before the seeding; `distance.colorize` renders the suppressed field the open QOI codec round-trips byte-for-byte. Compose not braid: this rung owns only the transform (marker subtraction, geodesic dilation capped at the mask, iterate-to-stability); `distance` owns the terrain, `medial_axis` reads the maxima, `label` the components, `segment` the seeding, `watershed` the flood.
- **Reshape (true disk element)** -- `disk` (`disk_offsets`, `dilate_disk`, `erode_disk`, `open_disk`, `close_disk`), the round element the general gather was built to carry: the offset set `{(dx, dy) : dx^2 + dy^2 <= r^2}`, built once and reshaped through `structure`'s general dilate (max) and erode (min). A disk of radius 1 is exactly the four-neighbor **cross** (5 cells), so dilating a dot grows a plus with dark diagonals byte-for-byte equal to a cross dilation; a disk of radius 2 (13 cells) reaches two pixels along each axis and lights the near diagonal, yet leaves the **far corner** `(2,2)` dark where a 5x5 **square** lights it -- true-disk morphology has **no square footprint**, the whole reason a round element exists. Its payoff is the isotropic cleanup: **`open_disk`** (erode then dilate) removes a bright speck smaller than the disk while leaving a blob's bulk, and **`close_disk`** (dilate then erode) fills a dark gap smaller than the disk while leaving the outline. Opening obeys its two laws on metal -- **anti-extensive** (an opened image sits inside the original) and **idempotent** (opening an opened image changes nothing) -- and closing is its **extensive** dual; the symmetric disk keeps the duality `erode(x)` equals `255 - dilate(255 - x)`. This is an honest sibling of `distance_morph`, not a rival: `distance_morph` erodes or dilates a **binary mask** by a true radius in two linear passes off the chamfer field, cheap at any radius yet only a mask transform; this rung reshapes **any RGBA** image (every channel including alpha, so grayscale morphology and real open/close) as a reusable geometric element, at the cost of the disk's area per pixel. The radius is bounded by `disk_max_radius` (whose lattice disk stays within `structure_max_offsets`, so the general gather never refuses it); an over-max radius, an empty source, or an empty element refuses by name. Compose not braid: this rung owns only the round geometry (the offset set, the count-then-fill); `structure` owns the max/min gather, `qoi` the pixel grid.
- **Residue (round brush)** -- `tophat_disk` (`white_tophat_disk`, `black_tophat_disk`), the **isotropic** top-hat: the residue verbs of `morphology_tophat` drawn with a true **disk** rather than a square, so a recovered small feature carries no directional bias a box would leave. The **white** top-hat `src - open_disk(src)` recovers the bright features a disk opening erases, the **black** top-hat `close_disk(src) - src` the dark ones a disk closing fills; both non-negative bytes by the same ordering laws (opening anti-extensive, closing extensive), and duals under complement (`black_tophat_disk(x)` equals `white_tophat_disk(complement(x))` byte-for-byte, since the symmetric disk makes `close_disk` the complemented `open_disk` of the complement). The isotropy shows plainest against the square: a solid 5x5 block's square **corners** read as small features the round disk cannot hold, so the disk top-hat lights the far corner `(2,2)` while a 5x5 square top-hat opens the block whole and stays blank. Compose not braid: this rung owns only the per-channel subtraction; `disk` owns `open_disk`/`close_disk`, `qoi` the pixel grid. The uneven-illumination correction and small-fleck detection a surface reaches for the day it wants a round brush rather than a boxy one.
- **Size structure (largest, smallest, histogram)** -- `region_stats` (`largest_region`, `smallest_region`, `size_histogram`), the **query** floor a blob picker and a size distribution descend from, the natural consumer of `regions`: where `measure_regions` turns a segmentation into measurement (one `Region` per component, its area and box), this rung turns the measurement into a **question**. `largest_region` and `smallest_region` are the two argmax/argmin picks -- the biggest blob a keeper keeps, the smallest speck a keeper drops -- ties broken by the **earliest label** so the pick is deterministic (the regions are raster-ordered, so the first-appearing component of a tied area wins). `size_histogram` buckets every region's area into `bucket_count` buckets each `bucket_width` wide -- bucket `i` covers areas `i * bucket_width + 1 .. (i + 1) * bucket_width`, and the **last bucket absorbs** every area past its high edge, so a big blob is counted, never dropped out of range -- and the counts sum to the region count exactly. Four components of areas 16, 9, 2, 1 histogrammed over four buckets three wide read 2, 0, 1, 1 (area 16 clamped into the last bucket); a one-bucket histogram absorbs every area; two equal-area specks make a tie both pickers break to the earliest label. Everything is bounded before a byte: the bucket count is capped by `region_stats_max_buckets`; an empty region slice refuses `EmptyRegions`, a zero bucket count or width refuses `BadBucketing`, each having allocated nothing. Compose not braid: this rung owns only the two reductions and the bucketing -- no gather, no blend, no codec, no color, not even a pixel loop; `regions` owns the `Region` type and its area.
- **Centroid (center of mass)** -- `centroid` (`centroids`, `nearest_region`, `Centroid`), the **placement** floor a label anchor, a marker seed, and object tracking descend from, the first-moment companion of `regions`: where `measure_regions` reads a component's area and box, this rung reads **where its center of mass sits**. The centroid is the mean of a component's pixel coordinates -- `(sum_x / area, sum_y / area)` rounded to the nearest pixel -- a genuinely different fact from the bounding-box center: an L or a comma leans its mass to one side, so its centroid sits **off** the middle of its box, exactly where a surface wants to drop a label or seat a marker (an L of pixels at (5,0), (5,1), (6,1) centers at (5,1) where its box center sits at row 0). `centroids` reads a LabelMap in one raster pass and returns one `Centroid` per component (its center and area); `nearest_region` answers the click a surface fields -- which blob's center lies closest to a point -- by **squared distance**, ties broken by the **earliest label** so the pick is deterministic. Everything is bounded before a byte: the coordinate sums run in `u64` so a full-image component can never wrap, the centroid slice is sized to the label count; an empty source refuses `EmptySource` and a nearest search over no regions refuses `NoRegions`, each having allocated nothing. Compose not braid: this rung owns only the first-moment accumulation and the nearest-center search -- no gather, no blend, no codec, no color, not even a pixel-writing loop; `label` owns the LabelMap.
- **Threshold (automatic, Otsu)** -- `threshold` (`histogram`, `otsu_threshold`, `threshold_mask`, `threshold_mask_at`), the **front door** the whole segmentation family opens from: every reader above (`label`, `distance`, `regions`, `centroid`, `watershed`, `segment`) begins from a binary **mask**, and this rung is the one that **makes the mask from a real image** -- by an automatic threshold read from the image's own tones, not a fixed cut chosen in advance. The measurement is the **histogram**: one 256-bin tally of each pixel's Rec.601 luma (weights that sum to 256, so a gray pixel maps to its own value). The algorithm is **Otsu's method** (N. Otsu, 1979): read the tally as two classes split at a threshold `t` (background luma at most `t`, foreground above it) and choose the `t` that **maximizes the between-class variance** `w0 * w1 * (mu0 - mu1)^2` -- the split that drives the two class means as far apart as their weights allow, which for a two-humped histogram falls squarely in the valley between the humps. One incremental pass over the 256 bins finds it (the class weight and sum accrue as `t` rises), and among equally-optimal thresholds the **lowest** wins, so the pick is deterministic. This adapts where the skeleton binarizers' **fixed** mid-gray cut cannot: a dark image whose two tones (gray-40 and gray-90) both sit **below** 128 is called all-background by a fixed cut, yet Otsu splits at 40 so the bright hump alone lights; a bright image (gray-160 and gray-220) both **above** 128 is called all-foreground by a fixed cut, yet Otsu splits at 160. A single-tone image has no valley, so Otsu returns 0 (the honest degenerate: no split exists). `threshold_mask` renders the family's own mask -- opaque **white** where a pixel is foreground, opaque **black** where it is background, alpha pinned so a translucent source can never punch a hole -- read downstream through `branch.is_on`; `threshold_mask_at` is the same renderer at a caller's chosen threshold, the door both paths share. Everything is bounded before a byte: the histogram is a fixed 256-bin array, the class sums run in `u64` so a full-image tally can never wrap; an empty source refuses `EmptySource` having allocated nothing. Compose not braid: this rung owns only the luma projection, the histogram tally, and the between-class-variance search -- no blend, no codec, no gather; `qoi` owns the RGBA buffers.
- **Moments (orientation and eccentricity)** -- `moments` (`moments`, `orientation_radians`, `eccentricity`, `Moment`), the **shape** reader a text baseline, an object tracker, and a shape classifier descend from, the **second-moment companion** of `centroid`: where the centroid reads **where** a blob's mass sits (the first moment), this rung reads **which way it leans and how much** (the second). It measures the second central moments about that center -- `mu20 = sum (x-cx)^2`, `mu02 = sum (y-cy)^2`, and the **signed** cross moment `mu11 = sum (x-cx)(y-cy)` -- and from them a blob's **orientation** (the angle of its long axis, `0.5 * atan2(2*mu11, mu20 - mu02)`, folded to (-90, 90] degrees) and its **eccentricity** (how elongated it is, `sqrt(1 - lambda_min / lambda_max)` over the two eigenvalues of the symmetric matrix `[[mu20, mu11], [mu11, mu02]]`, from 0 for a round blob toward 1 for a thin line). This is the fact no earlier reader can see: a **diagonal** stroke and an **anti-diagonal** stroke of the same five pixels share an area (5), a bounding box (5x5), and a center (2,2), yet their cross moments are +10 and -10, so one leans +45 degrees and the other -45 -- the lean that tells them apart. A flat 7x1 bar reads orientation 0 and a standing 1x7 bar +90 degrees, each eccentricity 1; a solid 5x5 square is **isotropic** (its x and y spread equal with no lean), so its orientation is undefined (reported 0) and its eccentricity 0 -- the second moment honestly cannot orient a shape with no long axis. Everything is bounded before a byte: the squared-deviation sums run in `u64` and the signed cross moment in `i64` so a full-image component can never wrap, the moment slice is sized to the label count; an empty source refuses `EmptySource` and a canvas with no marks measures to zero regions, each having allocated nothing. Compose not braid: this rung owns only the second-moment accumulation and the closed-form geometry -- no image written, no color, no codec; `label` owns the LabelMap and `centroid` owns the first-moment center each deviation is taken about.
- **Hu moments (rotation, scale, and mirror invariants)** -- `hu_moments` (`hu_moments`, `HuSet`), the **shape fingerprint** a text reader, an icon matcher, and a part recognizer descend from, the **rotation-and-scale-invariant companion** of `moments`: where orientation and eccentricity still **move** when a mark is turned or resized, these seven numbers stay (near) **constant** under translation, rotation, and scale (M-K. Hu, 1962). They are read off the normalized central moments up to order three, taken about the **true** (real-valued) centroid so a mark and its turned or mirrored copy match tightly. Invariants **i1..i6** hold under translation, rotation, and reflection; **i7** holds under rotation and scale yet **flips sign under reflection** -- so its sign tells a shape from its **mirror image**, the chirality no area, box, center, second moment, or orientation can see. This is the decisive fact: a chiral **right triangle** (unequal legs) and its **left-to-right mirror** share i1..i6 exactly (agreeing to 1e-16) yet carry i7 of **opposite sign** (i7 and -i7 to 1e-20); the same triangle turned 90 degrees reads all seven unchanged (rotation preserves i7, reflection flips it); a symmetric **plus** is its own mirror, so its i7 is **exactly zero** -- the achiral control that proves i7 measures chirality, not mere nonzero-ness. Everything is bounded before a byte: the raw moments run as exact `i64` integers (the largest, `m30 = sum x^3`, stays under `2^20 * 8192^3 = 2^59` for a full-image component so the accumulation can never wrap), the invariant slice is sized to the label count; the normalization divides by a mass of at least one, so a single pixel reads seven zeros rather than a division by zero; an empty source refuses `EmptySource` and a canvas with no marks measures to zero regions, each having allocated nothing. Compose not braid: a **sibling** of `centroid` and `moments`, not a consumer -- each reads the same pixels for a different fact; `label` owns the LabelMap.
- **Contour (ordered outer boundary)** -- `contour` (`trace_contour`, `perimeter`, `paint_contour`, `Contour`, `Point`), the **ordered-outline** floor a perimeter, a Freeman chain code, a corner detector, and a polygon simplifier descend from, the **boundary companion** of `regions`, `centroid`, and `moments`: where every reader above returns an **unordered reduction** (an area, a box, a center, a lean, an invariant fingerprint), this rung hands back the one fact a surface needs the moment it wants to **draw or measure a shape's edge** -- the **ordered clockwise ring** of boundary pixels, walked around the component so consecutive points are 8-adjacent and the last closes back to the first. The algorithm is **Moore-neighbor** boundary tracing: start at the component's topmost-then-leftmost pixel (an extreme point whose west neighbor is never the same label), then from each boundary pixel sweep the eight neighbors **clockwise** beginning just past the cell backed in from -- the first same-label neighbor is the next boundary pixel -- until the sweep returns to the start. What the outer contour reads is the **outline**, a fact distinct from the fill: a solid 3x3 block (**area 9**) and the same block carved to a hollow ring (**area 8**) share the **identical** outer contour point-for-point, so the outer boundary is **blind to an interior hole** exactly as a centroid is a different fact from a box center; the interior pixels a contour encloses are never on it (a solid 5x5 block traces to its **16-pixel** ring, its 9 interior pixels excluded). The **perimeter** the ring counts is a shape fact area alone cannot express -- two components of **equal area 16** carry different outlines, a compact 4x4 block reading 12 (a 2x2 interior it encloses) and a spread 2x8 block reading 16 (all boundary). Everything is bounded before a byte: a boundary walk visits at most one distinct point per pixel so the point slice is sized to the pixel ceiling, and a hard step ceiling guards the walk `BoundaryTooLong` by name; an empty source refuses `EmptySource` and a label outside 1..count refuses `BadLabel`, each having allocated nothing. Compose not braid: this rung owns only the boundary walk and the perimeter it counts -- no gather, no blend, no codec, no color in the trace; `label` owns the LabelMap, and the one render `paint_contour` paints a ring white on black that the open QOI codec round-trips byte-for-byte.
- **Polygon (Douglas-Peucker simplify)** -- `polygon` (`simplify`, `Polygon`), the **corner** reader a vector outline, a shape matcher, and a corner detector descend from, the **shape-descriptor companion** of `contour`: where the contour hands back **every pixel** on a shape's edge (a 5x5 block traces to a **16-point** ring), this rung reads the few **vertices** that actually define the shape -- the four corners a human eye sees where the ring lists sixteen boundary pixels. The algorithm is **Douglas-Peucker** (Ramer 1972, Douglas & Peucker 1973) adapted to a **closed** ring: anchor the ring at its start and at the point farthest from it (splitting the loop into two open chains), then for each chain keep the interior point of greatest **perpendicular distance** to the chord between its anchors whenever that distance exceeds a chosen **tolerance**, dropping every collinear run to its endpoints. A straight edge (every point zero distance from its own chord) collapses regardless of length, so a solid 5x5 block's sixteen-pixel ring reduces at tolerance 0.5 to **exactly** its four corner vertices (1,1)(5,1)(5,5)(1,5), and a spread 2x8 strip likewise to four -- the sixteen boundary pixels named by the four points that draw the shape. What the polygon reads is the shape's **corner count**, a fact no area, box, center, moment, or ring length can express: an **L-shape** at the same tolerance reduces to **more than four** vertices where the rectangle reduced to four, so the polygon tells the two shapes apart by their real vertices. The **tolerance** is the knob -- larger keeps fewer vertices, and past the shape's own extent every chain collapses to its two anchors, the **two-vertex floor** a closed ring can never fall below. Everything is bounded before a byte: the kept-vertex set and the Douglas-Peucker work stack are both sized to the ring length (itself bounded by the pixel ceiling), the stack guarding `PolygonTooComplex` by name; an empty ring refuses `EmptyContour` and a negative tolerance refuses `BadTolerance`, each having allocated nothing. The recursion is unrolled onto an explicit stack -- no unbounded call depth. Compose not braid: this rung owns only the vertex-selection choice (the anchor split, the perpendicular distance, the keep-or-drop decision) -- no gather, no blend, no codec, no color, not even a pixel-writing loop, a **reading** like `centroid` and `moments`, not a render; `contour` owns the ordered ring and its `Point` type. The edge-drawing render (Bresenham lines between consecutive vertices) is the named next sibling.

- **`text_layout.rye`** -- the **measure half** that makes the corpora usable: given an atlas and a byte string of codepoints, it places each glyph along a line at its running pen origin and sums the advances into a total width. `layout_line` returns one `PlacedGlyph` (codepoint, pen origin, atlas glyph) per byte; `measure_width` sizes a line without a buffer; `covers` asks whether the atlas carries every byte; `wrap_lines` breaks a paragraph into lines that stay within a max width, at space boundaries, so each wrapped span (`WrapLine`: start, len, width) lays out directly and its stated width equals a fresh measure of it -- a word wider than the max takes its own line whole (word-boundary wrapping, never a mid-word split). It is pure geometry -- no pixel is touched, so like `color.rye` it is floor code that waits on nothing, and painting the placed coverage into an RGBA grid is the rung it prepares. A byte with no glyph is a named refusal (`UncoveredCodepoint`), a zero max width a named refusal (`MaxWidthTooSmall`), never a silent hole, so a caller composing with `font5x7_ascii.rye` lays out and wraps any printable string and learns of a gap at once. Witness: `tools/text_layout_witness.rish`.

- **`text_paint.rye`** -- the **paint half** that `text_layout.rye` named as the rung it prepares: it turns a laid-out string from measured geometry into a string **seen** on an image. Single-stranded composition over four free parts, braiding none of them: `text_layout` places each glyph, `glyph.rye` hands each a coverage grid (one byte per cell, 0 no ink .. 255 full ink), `color.rye` composites an ink color over the destination (Porter-Duff src-over), and `qoi.rye` owns the RGBA target. A coverage byte is the ink's alpha at that cell (scaled by the ink's own alpha), so full ink over an opaque ink writes the ink exactly, no ink leaves the destination untouched, and a partial cell blends true through `color.over`. `paint_placed` paints an already-placed line; `paint_line` lays out and paints in one call; `solid` mints a one-color canvas to paint on. The line's painted box is bound-checked **once** up front, so the inner loop is proven in-bounds and an overrunning paint refuses `PaintOutOfBounds` by name rather than writing outside the buffer. Where a surface would rather show the visible part of a too-wide label than field a refusal, `paint_placed_clipped` paints only the cells that land inside the target and drops the rest, returning the count it painted; it composites an in-bounds cell **identically** to `paint_placed` (both share one `composite_cell` routine), matches the strict paint pixel-for-pixel where they overlap, and degrades to a clean no-op when the whole line sits off-canvas. `paint_paragraph` wraps a block to a max width and paints each line stepping down, all-or-nothing against the target (`ParagraphOutOfBounds` by name), and `paint_paragraph_aligned` sets that block **left, centre, or right** by a pure sideways offset within each line's slack -- alignment moves ink without adding or dropping a pixel, so the up-front box check and the changed-pixel count hold whatever the alignment, `.left` reproduces `paint_paragraph` byte-for-byte, and `.center`/`.right` match a hand-composed line-by-line offset paint exactly. And `paint_paragraph_clipped` is the paragraph's clip companion to `paint_placed_clipped`: where `paint_paragraph` refuses a block that overruns, this one paints as much of it as a fixed box holds -- a line inside lands identically to the strict paint, a line straddling the bottom lands its visible rows, a line entirely below is skipped -- so a bounded panel shows the text that fits rather than refusing the whole block, returning the count of cells painted (a box the block fits in clips byte-for-byte the strict paint; a box one line-box tall paints just the first line where the strict painter would refuse; a box below the block is a clean no-op). And `paint_paragraph_boxed` is the **vertical** companion to `paint_paragraph_aligned`'s sideways set: given a box taller than the block, it places the whole stack **top, middle, or bottom** by a pure downward offset of the origin, then delegates the wrap-stack-paint to the aligned painter unchanged -- so vertical placement moves the stack down as one, adding no pixel and dropping none (`.top` reproduces the plain paragraph at the box origin; `.middle`/`.bottom` match a plain paint at the shifted origin; the changed-pixel count holds across every set), refusing `ParagraphBoxTooShort` by name when the block is taller than the box (the strict all-or-nothing companion to the clipping painter). And `paint_paragraph_in_box` is the family's 2-D capstone -- a real text region: it positions the content block within a box on **both** axes at once, one `h` set choosing left/centre/right for the block's place in the box *and* each line's set within it, one `v` set choosing top/middle/bottom, delegating the vertical half to `paint_paragraph_boxed` unchanged so every axis stays in one place. Each corner equals a plain aligned paint at the box offset (placement moves the block as one, adding no pixel and dropping none), refusing `ParagraphBoxTooNarrow` on a box narrower than the block and `ParagraphBoxTooShort` on one too short -- all-or-nothing on both axes. No new storage, codec, palette, or geometry -- only the join. Witness: `tools/text_paint_witness.rish`.

- **`shape.rye`** -- the **geometry floor** beneath the paint rungs: two bounded rectangle verbs over an RGBA grid, the shapes a surface frames a picture with before it paints a glyph. Where `text_paint.rye` paints **glyphs** onto a `qoi.Pixmap`, this rung paints **plain area** -- `fill_rect` fills a rectangle, `stroke_rect` draws a rectangle outline (a frame) -- the shapes a panel, a selection highlight, a crop overlay, a table cell, or a progress-bar track are drawn from. Pure geometry over two public APIs, braiding neither: `color.rye` composites the paint over the destination (src-over), `qoi.rye` owns the RGBA target. An opaque paint writes the colour exactly; a translucent paint blends true through `color.over`, so a panel tint reads through to the picture beneath. Every rectangle's box is bound-checked **once** up front (in `u64` so the sum can never wrap), so an overrun refuses `RectOutOfBounds` by name rather than writing outside the buffer, and `stroke_rect` paints its border ring in a **single pass** (a pixel belongs to the ring when it lies within the thickness of any edge), so a corner is composited **exactly once** -- a translucent frame reads uniform, never a darker corner where two edge bands would overlap. `fill_rect` refuses `BadRectDims` on a zero extent; `stroke_rect` refuses `BadThickness` on a zero frame and `StrokeTooThick` when two borders would overrun a side; `ring_cells` predicts the painted ring count before a pixel is drawn. Witness: `tools/shape_witness.rish`.
- **`gradient_paint.rye`** -- the rung where the **color ramp meets the pixels**: the twin of what `text_paint.rye` did for the font family (it turned laid-out glyphs into pixels; this turns a positioned gradient into pixels). `paint_gradient_h` paints a **horizontal** positioned gradient into a rectangle -- each column is the color `color_ramp_stops.rye` samples at that column's global position (`c * pos_max / (w-1)`), painted down the whole height -- so a keeper who names a stop list reads back a gradient strip a surface can show; `paint_gradient_v` is the **vertical** twin with the axes swapped (each row the color at its global position, painted across the width, the ramp running top to bottom); `paint_gradient_diag` and `paint_gradient_adiag` are the **diagonal** pair that finish the linear-gradient family (main diagonal: pixel `(cx, cy)` maps to `(cx + cy) * pos_max / ((w-1) + (h-1))`, so the top-left corner is the first control exactly and the bottom-right the last, each anti-diagonal band one constant color; the anti-diagonal twin runs top-right to bottom-left, that painting mirrored left-to-right -- the CSS `linear-gradient(to bottom right, ...)` shape, refusing `StripTooSmall` on a single-pixel box). Compose not braid over three public APIs: `color_ramp_stops` decides each column's color, `qoi.rye` owns the RGBA target, `color.rye` composites src-over (so a translucent gradient tints the picture beneath), and this rung only **routes** each column to its position. The leftmost column is the first control exactly and the rightmost the last, byte-for-byte down the whole height; a mid column carries both channels (a true blend) constant vertically; uneven positions bend the painted strip where even spacing cannot; the strip round-trips through the open QOI codec byte-for-byte; a sub-rectangle paints only its own columns (the gutters stay ground). All-or-nothing -- the whole box is bound-checked once up front (in `u64` so a far edge can never wrap) and the ramp validated once before any pixel, so a `StripTooNarrow` (width under two), `BadStripDims` (zero height), `GradientStripOutOfBounds`, or any `color_ramp_stops` ramp refusal leaves the target untouched. Witness: `tools/gradient_paint_witness.rish`.
- **`radial_paint.rye`** -- the **circle** beside the line: the sibling of `gradient_paint.rye` for the other major CSS gradient shape. Where a linear gradient maps a pixel to its distance **along** one axis, `paint_gradient_radial` maps a pixel to its distance **from** the box center -- the center is the first control exactly and every corner the last, each ring between one constant color (the CSS `radial-gradient(circle, ...)` shape, its default `farthest-corner` extent). Compose not braid, unchanged: `color_ramp_stops` decides each pixel's color, `qoi.rye` owns the RGBA target, `color.rye` composites src-over, and this rung only **routes** each pixel to its radial position. The routing stays integer fixed-point so a disc is deterministic: coordinates are doubled (`2*cx - (w-1)`) so the center lands exactly on a pixel for odd dimensions and exactly between two for even ones without a fraction; a pixel's squared distance from the center `d2 = dx2*dx2 + dy2*dy2`, the farthest corner `max_d2 = (w-1)^2 + (h-1)^2` away, and the position `p = isqrt(d2 * pos_max^2 / max_d2)` (a bounded integer square root, no float), so the center (`d2 == 0`) reads 0 and a corner (`d2 == max_d2`) reads `pos_max` exactly. The four edge midpoints share one constant ring color (a true circle); the position grows with the radius; uneven positions bend the disc where even spacing cannot; the disc round-trips through the open QOI codec byte-for-byte; a non-square box still centers and corners exactly. All-or-nothing -- the whole box is bound-checked once up front (in `u64`) and the ramp validated once before any pixel, so a `BadStripDims` (zero dimension), `StripTooSmall` (single-pixel box), `RadialOutOfBounds`, or any `color_ramp_stops` ramp refusal leaves the target untouched. Witness: `tools/radial_paint_witness.rish`.

- **`conic_paint.rye`** -- the **sweep** beside the line and the ring: the third and last shape of the CSS gradient triad. Where a linear gradient maps a pixel to its distance **along** an axis and a radial gradient to its distance **from** the center, `paint_gradient_conic` maps a pixel to its **bearing** around the center -- the first control sits at the top (12 o'clock) and the ramp sweeps **clockwise** through east, south, and west back to the top (the CSS `conic-gradient(from 0deg at center, ...)` shape), every ray from the center one constant wedge color, the first and last controls meeting in a single seam at the top. Compose not braid, unchanged: `color_ramp_stops` decides each pixel's color, `qoi.rye` owns the RGBA target, `color.rye` composites src-over, and this rung only **routes** each pixel to its angular bearing. The routing needs no trigonometry: coordinates are doubled (`2*cx - (w-1)`) so the center is exact, and the bearing is an integer **pseudo-angle** -- the four quadrants around the center split the turn into four, and within a quadrant the position grows linearly with the ratio of the two coordinates (`(q*s + numer) * pos_max / (4*s)`, `s = |dx2| + |dy2|`), a monotonic function of the true angle. So the top reads 0, east `pos_max/4`, south `pos_max/2`, west `3*pos_max/4`, each exact. The bearings ascend strictly clockwise; each ray is one constant wedge; the top is the first/last seam; the sweep round-trips through the open QOI codec byte-for-byte; uneven positions bend the sweep where even spacing cannot; a non-square box still tops and seams exactly. All-or-nothing -- the whole box is bound-checked once up front (in `u64`) and the ramp validated once before any pixel, so a `BadStripDims` (zero dimension), `StripTooSmall` (single-pixel box), `ConicOutOfBounds`, or any `color_ramp_stops` ramp refusal leaves the target untouched. Witness: `tools/conic_paint_witness.rish`.

- **`repeat_paint.rye`** -- the **ramp that tiles**: the fourth shape of the CSS gradient family, beside the three that run their ramp once. Where a linear gradient runs the ramp **once** from edge to edge, `paint_gradient_repeat_h` runs it over a fixed **period** of columns and **tiles** it across the strip (the CSS `repeating-linear-gradient` shape) -- one tile of `period` cells carries the full ramp (the first control at its start, the last at its end), and the next tile starts over, so the pattern reads first..last, first..last with a hard seam at each boundary; `paint_gradient_repeat_v` is the **vertical** twin, tiling the ramp down the rows. Compose not braid, unchanged: `color_ramp_stops` decides each cell's color, `qoi.rye` owns the RGBA target, `color.rye` composites src-over, and this rung only **routes** each cell to its position **within its tile** via one integer modulo (`(c % period) * pos_max / (period - 1)`). The **period** carries the direction, not the width, so a strip may be any size >= one cell -- a strip narrower than one period shows the ramp's opening, a wider strip shows several tiles. An 8-wide strip over period 4 reads `0,85,170,255` twice; the tile repeats exactly (column 0 equals column `period`); each tile ascends then seams hard (the last cell drops straight back to the first); a horizontal repeat is constant down each column and the vertical twin constant across each row; the tiling round-trips through the open QOI codec byte-for-byte; a wider period spreads the ramp over more cells where a narrow one wraps. All-or-nothing -- the whole box is bound-checked once up front (in `u64`) and the ramp validated once before any pixel, so a `BadStripDims` (zero dimension), `PeriodTooSmall` (period under two), `PeriodTooLarge` (period past the dimension ceiling), `RepeatOutOfBounds`, or any `color_ramp_stops` ramp refusal leaves the target untouched. Witness: `tools/repeat_paint_witness.rish`.

- **`repeat_radial_paint.rye`** -- the **rings that tile**: the radial twin of `repeat_paint.rye` and the repeating sibling of `radial_paint.rye`. Where the single radial gradient runs its ramp **once** from the center to the farthest corner, `paint_gradient_repeat_radial` runs it over a fixed radial **band** of pixels and **tiles** it outward as concentric rings (the CSS `repeating-radial-gradient` shape) -- the center is the first control, a ring `band-1` cells out the last, and the next ring wraps back with a hard seam. Compose not braid, unchanged: `color_ramp_stops` decides each pixel's color, `qoi.rye` owns the RGBA target, `color.rye` composites src-over, and this rung only **routes** each pixel to its position **within its ring** (`(radius % band) * pos_max / (band - 1)`). The routing is integer: the center sits at the **integer** cell `((w-1)/2, (h-1)/2)` -- floored for even dimensions, unlike `radial_paint.rye`'s doubled center, so a pixel's radius is a whole number and every ramp position appears at full resolution along an axis; the radius is a bit-by-bit integer square root of the squared distance (no float). A black-to-white ramp over band 4 makes the center read 0 and the row outward `85,170,255,0` -- the ramp tiles as concentric rings; the ring ascends then seams hard; the four points one cell out share one ring color (a true circle); the rings round-trip through the open QOI codec byte-for-byte; a wider band spreads the ramp over more rings where a narrow one wraps. All-or-nothing -- the whole box is bound-checked once up front (in `u64`) and the ramp validated once before any pixel, so a `BadStripDims` (zero dimension), `StripTooSmall` (single-pixel box), `BandTooSmall` (band under two), `BandTooLarge` (band past the dimension ceiling), `RepeatRadialOutOfBounds`, or any `color_ramp_stops` ramp refusal leaves the target untouched. Witness: `tools/repeat_radial_paint_witness.rish`.

- **`repeat_conic_paint.rye`** -- the **sweep that tiles**: the sixth and last shape of the CSS gradient family, closing the set the linear, radial, conic, repeating-linear, and repeating-radial rungs began. Where the single conic gradient runs its ramp **once** around the turn, `paint_gradient_repeat_conic` winds it `reps` times and **tiles** it (the CSS `repeating-conic-gradient` shape) -- `reps` identical pie wedges, a hard seam at each tile boundary, every ray from the center still one constant wedge color. Compose not braid, unchanged: `color_ramp_stops` decides each pixel's color, `qoi.rye` owns the RGBA target, `color.rye` composites src-over, and this rung only **routes** each pixel to its position **within its angular tile**. The routing needs no trigonometry: coordinates are doubled (`2*cx - (w-1)`) so the center is exact, the bearing is held at full precision as the turn fraction `T/D` (`T = q*s + numer`, `D = 4*s`, `s = |dx2| + |dy2|`), and tiling winds and reduces it -- `tile = (T*reps) mod D`, scaled `tile * pos_max / D`. So a black-to-white ramp over reps 2 makes the top read 0, east 127, south 0, west 127 -- the ramp cycles twice around the turn, top and south sharing the first control where the single conic never could; each tile ascends clockwise then seams hard; each ray is one constant wedge; more tiles pack more wedges (reps 4 wraps the east bearing to 0 where reps 2 read 127); the sweep round-trips through the open QOI codec byte-for-byte; a non-square box still tops and wraps exactly. All-or-nothing -- the whole box is bound-checked once up front (in `u64`) and the ramp validated once before any pixel, so a `BadStripDims` (zero dimension), `StripTooSmall` (single-pixel box), `RepsTooSmall` (reps under two -- that is the plain conic), `RepsTooLarge` (reps past the dimension ceiling), `RepeatConicOutOfBounds`, or any `color_ramp_stops` ramp refusal leaves the target untouched. Witness: `tools/repeat_conic_paint_witness.rish`.
- **`palette_paint.rye`** -- the **discrete sibling** of the gradient: where `gradient_paint.rye` paints a **continuous** ramp (every column a fresh blend), this rung paints a row (or column) of solid color **swatches** -- the palette legend a design surface shows beside a picker, a color scale, or a gradient. `paint_palette_h` tiles the width with `n` swatches, swatch `i` filling the columns `[i*w/n, (i+1)*w/n)` down the whole height; `paint_palette_v` is the vertical twin, stacking the swatches top to bottom. Compose not braid: `shape.rye` `fill_rect` **owns** the fill (a solid color composited src-over), `qoi.rye` owns the RGBA target, and this rung only **routes** each swatch to its cell -- no new color math, no new codec. The cells tile the strip **exactly**: an integer partition where cell 0 starts at the left edge and cell `n` ends at the right edge, the cells contiguous and disjoint (no gap, no overlap, a hard edge at each boundary), their widths differing by at most one when `n` does not divide the extent evenly (width 8 over 3 swatches -> widths 2,3,3, tiling 8 exactly). Each cell is its color exactly byte-for-byte; a translucent swatch blends src-over uniform across its cell; the palette round-trips through the open QOI codec byte-for-byte; a sub-rectangle paints only its own columns (the gutters stay ground). All-or-nothing -- the whole box is bound-checked once up front (in `u64`) and the palette validated once before any pixel, so an `EmptyPalette` (no swatch), `PaletteTooManyColors` (past `palette_max_swatches`, 256), `BadStripDims` (zero dimension), `PaletteStripTooNarrow`/`PaletteStripTooShort` (a strip too small to give every swatch one unit), or `PaletteOutOfBounds` leaves the target untouched. Witness: `tools/palette_paint_witness.rish`.

- **`checker_paint.rye`** -- the **discrete 2D sibling** of `palette_paint.rye`: where the palette tiles **one** axis with a row of solid swatches, this rung tiles **both** axes with an alternating two-color grid -- the **checkerboard** a design surface draws as the **transparency ground** behind a translucent picture (the light-and-white squares an image editor shows so an alpha hole reads as a hole, not as white). `paint_checkerboard` fills the rectangle with `cell`-sized squares, cell `(col, row)` painted its color by `(col + row)` parity so cell `(0, 0)` is the first color, its orthogonal neighbors the second, its diagonal neighbors the first again -- a true checkerboard; `paint_alpha_ground` is the one-call convenience over it with the conventional light/white shades and cell size 8. Compose not braid: `shape.rye` `fill_rect` **owns** the fill, `qoi.rye` owns the RGBA target, and this rung only **routes** each cell to its color -- no new color math, no new codec. The cells tile the box **exactly**: an integer partition where the first cell starts at the corner and a boundary cell the cell size does not divide evenly is simply **clipped** to the rectangle edge (no gap, no overlap, no seam). Each cell is its color exactly byte-for-byte; a translucent color blends src-over uniform; the checker round-trips through the open QOI codec byte-for-byte; a sub-rectangle paints only its own box (the gutters stay ground). All-or-nothing -- the whole box is bound-checked once up front (in `u64`), so a `BadCheckerDims` (zero dimension), `BadCellSize` (zero cell), or `CheckerOutOfBounds` leaves the target untouched. Witness: `tools/checker_paint_witness.rish`.

- **`compose.rye`** -- the **compositing verb** the whole surface family leans on: where `shape.rye` composites a **solid color** over the grid and `checker_paint.rye` draws the transparency **ground**, this rung draws the **picture itself** -- a **source image composited over a target image**, each source pixel blended src-over its target pixel, so a translucent photo laid over the checker ground reads as a photo with holes. Two gestures, one verb: `paint_over` lays a whole picture at a point; `paint_over_region` lays a **sub-rectangle** of a larger picture -- the **single-sprite render** an index-into-one-image surface uses (a marketplace that web-hosts one big sprite and draws each product as a window into it, the McMaster-Carr speed trick). Compose not braid: `color.rye` `over` **owns** the blend, `qoi.rye` owns both RGBA buffers, and this rung only **routes** each source pixel to its target pixel -- no new blend math, no new codec, no new color. An opaque source overwrites exactly its footprint and leaves the gutters untouched; a translucent source blends src-over, equal to neither the source nor the ground; a window of a sprite sheet renders exactly the indexed tile; the composited image round-trips through the open QOI codec byte-for-byte. All-or-nothing -- the source window and the destination box are bound-checked once up front (in `u64` so a far edge can never wrap), so a `BadComposeDims` (zero-size window), `SourceOutOfBounds` (a source window past the source edge), or `ComposeOutOfBounds` (a destination window past the target edge) leaves the target untouched. Witness: `tools/compose_witness.rish`.

- **`compose_tiled.rye`** -- the **background-repeat** sibling of `compose.rye`: where `compose` lays **one** picture over a target at a point, this rung lays **many** -- it **tiles** a small source pattern across a rectangle edge to edge, the way a surface repeats a texture, a wallpaper, or a small motif to fill a panel (the CSS `background-repeat` gesture). `paint_tiled` paves the box with copies of the pattern from the corner, a boundary tile the pattern size does not divide evenly simply **clipped** to the box edge (its top-left window) so the fill covers the whole box with no gap and no seam. Compose not braid: `compose.rye` `paint_over_region` **owns** the blit (a source window composited src-over), `qoi.rye` owns both buffers, and this rung only **routes** each tile to its window and its clip -- no new blend math, no new codec, no new color, not even a new pixel loop. An evenly-dividing pattern paves an exact grid of copies (each pixel its pattern color by the pure `(tx % pw, ty % ph)` modulo); a non-dividing box clips the last band and still paves the whole box; a translucent pattern tiles src-over uniform; the tiled image round-trips through the open QOI codec byte-for-byte; a sub-rectangle paves only its own box; a pattern larger than the box is itself clipped. All-or-nothing -- the whole box is bound-checked once up front (in `u64`), so a `BadTileDims` (zero dimension), `EmptyPattern` (a pattern with no extent), or `TileOutOfBounds` leaves the target untouched. Witness: `tools/compose_tiled_witness.rish`.

- **`place_paint.rye`** -- the **background-position** sibling of `compose_tiled.rye`: where `compose_tiled` **tiles** a pattern edge to edge to fill a box (the CSS `background-repeat` gesture), this rung places **one** copy and **anchors** it -- a single source seated at a named corner, edge, or center of a box (the CSS `background-position` with `no-repeat` gesture: an icon pinned top-right in a panel, a logo centered in a card, a badge in a bottom corner). `paint_placed` takes a box, a source, and a horizontal and vertical `Anchor` (`start`, `center`, `end`) and composites one window of the source at the anchored spot, the box's remaining area left as the ground beneath. Two axes, one rule (`axis_window`, all unsigned): when the source **fits** the box the whole source is drawn at an anchored offset (start at 0, center on the slack, end flush to the far edge); when the source **overflows** the box a box-sized window of the source is drawn from the box corner, the anchor choosing which window shows -- so an oversize source is **clipped** to the box with no spill. Compose not braid: `compose.rye` `paint_over_region` **owns** the blit, `qoi.rye` owns both buffers, and this rung only **routes** the anchor to its one window and its one clip -- no new blend math, no new codec, no new color, not even a new pixel loop. A fitting source seats on the slack (center), flush to a corner (start / end), or at a mixed corner; an oversize source is clipped by its anchor; a translucent source blends src-over uniform; the placed image round-trips through the open QOI codec byte-for-byte. All-or-nothing -- the box is bound-checked once up front (in `u64`), so a `BadPlaceDims` (zero dimension), `EmptySource` (a source with no extent), or `PlaceOutOfBounds` leaves the target untouched. Witness: `tools/place_paint_witness.rish`.

- **`space_paint.rye`** -- the **background-repeat: space** sibling that completes the repeat family: where `compose_tiled` tiles a pattern edge to edge and **clips** the boundary copy (`repeat`), and `place_paint` places **one** copy at an anchor (`no-repeat`), this rung tiles only **whole** copies and never clips one -- it fits as many whole patterns as the box holds, pins the first and last flush to the two edges, and shows the leftover as **even ground gaps** between them (the CSS `background-repeat: space` gesture: a row of evenly-spaced badges, a strip of logos gapped to the margins, a motif that fills a panel without a seam **and** without a cut). `paint_spaced` takes a box and a pattern and composites each whole copy at its spaced offset, the ground showing between and never through them. One pure per-axis rule (`plan_axis` / `axis_offset`, all unsigned): `count` is `floor(box / unit)` whole copies, and copy `i` seats at `i*unit` plus its share of the total gap (`i*total_gap / (count-1)`, integer-rounded), so copy 0 pins flush at 0 and copy `count-1` flush at `box - unit`, the copies always disjoint. Two honest edges: when only **one** whole copy fits it seats at the start with the leftover trailing as ground; when the pattern is **larger** than the box a single copy is clipped to the box (its top-left window), so the family's oversize rule holds here too. Compose not braid: `compose.rye` `paint_over_region` **owns** the blit, `qoi.rye` owns both buffers, and this rung only **routes** each whole copy to its spaced offset -- no new blend math, no new codec, no new color, not even a new pixel loop. An exact fit fills with no ground; a leftover axis shows the gap as ground; a translucent copy blends src-over uniform; the spaced image round-trips through the open QOI codec byte-for-byte; a sub-rectangle spaces only its own box. All-or-nothing -- the box is bound-checked once up front (in `u64`), so a `BadSpaceDims` (zero dimension), `EmptySource` (a pattern with no extent), or `SpaceOutOfBounds` leaves the target untouched. Witness: `tools/space_paint_witness.rish`.

- **`round_paint.rye`** -- the **background-repeat: round** member that completes the quartet, the one the resize floor unlocked: where `compose_tiled` tiles a pattern and **clips** the boundary copy (`repeat`), `space_paint` tiles whole copies and leaves ground **gaps** (`space`), and `place_paint` places **one** anchored copy (`no-repeat`), this rung tiles whole copies and **scales** each so a whole count paves the box exactly -- **no gap and no clip** (the CSS `background-repeat: round` gesture: a texture stretched a hair so the tiles land flush, a motif that fills a panel with whole copies and no seam, an oversize badge **shrunk** to fit rather than cropped). `paint_rounded` takes an allocator, a box, and a pattern; it fits the nearest whole `count` of copies per axis (`round_count`: `round(box / unit)`, at least one), splits the box into that many contiguous cells whose extents differ by at most one pixel (a fair integer partition, exactly as `palette_paint` splits a strip), resizes each distinct cell size **once** (at most four tiles across the two axes), and blits each cell its matching resized copy. Compose not braid: `scale.rye` `scale_nearest` **owns** the resize, `compose.rye` `paint_over` **owns** the blit, `qoi.rye` owns the buffers, and this rung only **routes** the box into whole cells -- no new blend math, no new codec, no new color, no new resample. The oversize rule is round's own: a pattern **larger** than the box becomes **one** copy **shrunk** to the box (`count` one), never a clipped window. An exact fit rounds to a clean identity repeat; a non-dividing box scales the copies so the whole box is paved with no gap and no clip; an oversize pattern shrinks to one copy sampling across its whole extent; a translucent copy blends src-over uniform; the rounded image round-trips through the open QOI codec byte-for-byte; a sub-rectangle rounds only its own box. All-or-nothing -- the box is bound-checked once up front (in `u64`) **before** any tile is resized, so a `BadRoundDims` (zero dimension), `EmptySource` (a pattern with no extent), or `RoundOutOfBounds` leaves the target untouched and allocates nothing. Witness: `tools/round_paint_witness.rish`.

- **`scale.rye`** -- the **resize floor** the paint rungs lean on, the verb a surface reaches for whenever a box and a picture disagree on extent: a thumbnail shrunk from a photo, a pixel-art sprite doubled to read at arm's length, a logo fit to a card, a responsive image scaled to its column. Where `compose.rye` lays one picture over another at its **native** size, `scale_nearest` **remakes** the picture at a named `dst_w` x `dst_h` -- each destination pixel takes the color of the **nearest** source pixel, so an upscale doubles whole pixels into clean blocks and a downscale samples one source pixel per destination cell, never inventing a between-color. Nearest, not blended: this rung owns the one new verb the family lacked -- a per-axis integer map from a destination index to its source index (`src_index`: `sx = dx * src_w / dst_w`, the classic nearest-neighbor floor, seen once per axis so a resize is the same rule twice) -- and writes each destination pixel by **copying** its nearest source pixel whole, so it adds no color math (nothing is mixed), no codec, no blend; `qoi.rye` owns the buffers, and this rung only **routes** each destination pixel to its nearest source pixel. Integer only: no float ever enters the map, so a resize is deterministic byte-for-byte. An identity resize reproduces the source byte-for-byte; a 2x upscale doubles the four source pixels into four clean 2x2 blocks; a 2x downscale samples the nearest source columns (0 and 2), never an average; a non-integer 2-to-3 scale bends the map so the middle cell repeats the first source column; a translucent source keeps its exact alpha byte through the scale (carried, never blended); the scaled image round-trips through the open QOI codec byte-for-byte. All-or-nothing -- the whole destination is bound-checked once up front (its pixel count against the module's named ceiling, its dims against the codec's max) **before** any allocation, so a `BadScaleDims` (zero dimension), `EmptySource` (a source with no extent), or `ScaleTooLarge` (a target past the codec max or the pixel ceiling) refuses by name having allocated nothing. This is the nearest-neighbor path the Photos **Resample** family named; `scale_bilinear.rye` now stands beside it, and the area-average path grows next. Witness: `tools/scale_witness.rish`.

- **`scale_bilinear.rye`** -- the **smooth resize** beside the nearest one, the verb a **photo** reaches for where a sprite wanted the hard blocks. Where `scale_nearest` copies the one nearest source pixel whole (clean blocks, no between-color), `scale_bilinear` reads the **four** source pixels around each destination sample and blends them by how near the sample falls to each, so an upscale grows a **gradient** between the source colors rather than doubling hard blocks. Separable, not braided: the whole verb is **one** per-axis map (`axis_sample`: a destination index yields its lower source index, its upper neighbor, and a blend weight `t` in `0..255`, seen once per axis) and **one** existing blend -- `color.rye` `mix`, the linear two-color lerp the palette family already leans on -- so each destination pixel is three mixes (the top pair by the horizontal weight, the bottom pair by the same, then those two by the vertical) and this rung adds **no** new color math, no codec, no premultiply; `qoi.rye` owns the buffers, `color.rye` owns the blend, and this rung only **routes** four source pixels and a weight into it. Integer only: the fractional sample position rides a fixed `1/255` subpixel scale (`color.mix`'s own `t` range), no float ever enters the map, so a resize is deterministic byte-for-byte; center-aligned, so an identity resize (weight 0 everywhere) reproduces the source byte-for-byte and both edges clamp to the border pixel rather than reading past it. An identity resize reproduces the source byte-for-byte; a 2px black-to-white row eased to 4px grows a **strictly ascending gradient** carrying true between-colors nearest refuses to invent; a solid image eases to the same solid color with no ringing; a two-alpha row blends its **alpha** through the middle (alpha read as a fourth channel, the honest difference from nearest's whole-byte carry); the resized image round-trips through the open QOI codec byte-for-byte. Honest scope: bilinear reads a 2x2 neighborhood, so it eases an upscale and a mild downscale beautifully while a downscale far below half-size still samples two taps per axis and will alias -- the **area-average** path is the verb for that, and stands now in `scale_area.rye`. All-or-nothing -- the whole target is bound-checked once up front **before** any allocation, so `BadScaleDims` (zero dimension), `EmptySource` (a source with no extent), or `ScaleTooLarge` (a target past the codec max or the pixel ceiling) refuses by name having allocated nothing. Witness: `tools/scale_bilinear_witness.rish`.

- **`scale_area.rye`** -- the **clean downscale** beside nearest and bilinear, the verb a picture reaches for when it is **shrinking** far. Where nearest samples one source pixel per cell and bilinear reads a 2x2 neighborhood, `scale_area` reads **every** source pixel a destination cell covers and takes their coverage-weighted **mean**, so a deep shrink keeps every source pixel's contribution rather than dropping the pixels between the taps -- the reason a downscale wants area over the other two: nearest and bilinear sample too few taps, so a deep shrink **aliases** (a fine texture turns to moire, a page of text to speckle), while area sees the whole box and the thumbnail reads clean. Exact integer coverage, not a float box: the resize is **one** per-axis coverage map seen twice -- a destination cell covers the source span `[dst_i/dst_extent, (dst_i+1)/dst_extent)`, scaled into whole subunits so the weight of source pixel `i` is the **integer overlap** of two spans (`axis_weight`), no float, so a resize is deterministic and a partial edge pixel carries its true fractional share rather than being counted whole or dropped. The per-axis weights each sum to `src_extent`, so the two axes multiply to a constant total weight `W = src.width * src.height`, and every output channel is the box sum over `W` with half-up rounding; this rung owns the box **mean**, the averaging verb the family lacked, and adds no blend, no codec, no premultiply -- `qoi.rye` owns the buffers, the mean is the sampling rule itself. An identity resize reproduces the source byte-for-byte; a 2x2 pattern shrunk to 1x1 takes the true **average** of all four corners (64 per channel) rather than picking one; a 4x4 black/white checker shrunk to 1x1 reads a true **mid-gray** (128) rather than aliasing to a single extreme; a solid image decimates to the same solid color; a 3px-to-2px downscale carries **partial edge coverage** (the shared middle pixel split fractionally between the two outputs); alpha averages like any other channel; the resized image round-trips through the open QOI codec byte-for-byte. Honest scope: area averaging is the **downscale** verb -- on an upscale each cell falls within a single source pixel, so it degenerates to blocky replication like nearest (bilinear is the smooth-upscale verb). All-or-nothing -- the covered box is bounded by the source's pixel count and the whole target bound-checked once up front, so `BadScaleDims`, `EmptySource`, or `ScaleTooLarge` refuses by name having allocated nothing. Witness: `tools/scale_area_witness.rish`.

- **`blur.rye`** -- the **convolution floor** the whole soft-image family stands on, the first rung beside the resamplers that changes an image's **detail** rather than its **size**. Where a resample remakes a picture at a new extent, a blur softens it at the same extent: each output pixel is the **mean** of the square window of source pixels around it, so a sharp edge eases into a ramp and fine speckle settles toward its local average. This is the verb a drop shadow (a blurred silhouette), a frosted-glass panel (a blurred backdrop), a Gaussian (a box mean run a few times), and a sharpen (the image minus its own blur) all reduce to -- grow the box mean once and each becomes a sibling. **Separable**, so the 2D box is two 1D passes: `box_blur` blurs every row horizontally (`box_blur_h`), then every column of **that** vertically (`box_blur_v`), and because the `(2r+1)x(2r+1)` window is a product of a horizontal and a vertical span, the two passes equal the full window mean at a fraction of the work. Integer only -- a pure box mean with **half-up** rounding (the bias `r` over the odd window `2r+1`), so a blur is deterministic byte-for-byte; edges **clamp** -- a window that reaches past the border reads the nearest border pixel, so the window stays full and a solid image stays exactly solid at its edges rather than darkening toward a phantom margin. Every channel including alpha is averaged the same way. This rung owns the box mean and leans only on `qoi.rye` for the grid -- no blend, no codec, no color math, no premultiply; `box_blur_h` and `box_blur_v` are the single-axis passes a directional (motion) blur reaches for, and `box_blur` is exactly their composition, freeing its row-blurred intermediate before return so only the caller's result outlives the call. Radius 0 is the identity byte-for-byte; a horizontal box mean spreads a step `[0,0,240]` into a ramp `[0,80,160]` and the vertical pass mirrors it down a column; a solid stays solid edge to edge; the two single-axis passes are directional (a vertical edge blurs horizontally yet stays sharp vertically); a single center pixel spreads into a symmetric flat-top plateau (the box signature) with the far corners untouched; alpha averages like any other channel; the blurred image round-trips through the open QOI codec byte-for-byte. All-or-nothing -- the source and radius are guarded once up front, so an over-max radius (`BlurRadiusTooLarge`) or an empty source (`EmptySource`) refuses by name having allocated nothing. Witness: `tools/blur_witness.rish`.

- **`gaussian.rye`** -- the **smooth blur** above the box floor, the second convolution rung and the shape a designer actually reaches for: frosted glass, a soft drop shadow, gentle depth-of-field. A single box mean softens **bluntly** -- it spreads a point of light into a flat-top **plateau** and leaves a faint boxy ring on a straight edge; a Gaussian spreads that point into a rounded **peak** that falls off evenly on every side with no plateau and no ring. The whole trick is that a Gaussian needs **no Gaussian kernel and no float**: by the **central limit theorem**, a box mean run a few times converges to a Gaussian -- one box is a flat window, two boxes convolve to a triangle (one peak), three round that into a bell indistinguishable from a true Gaussian for display work. So this rung owns **no new pixel math** -- `gaussian_blur_passes` composes `blur.box_blur` `passes` times (each pass reading the last, each intermediate freed as the next replaces it), and `gaussian_blur` is the three-pass standard (`gaussian_default_passes`); every property the box proved (separable, integer-only, deterministic byte-for-byte, clamped edges, alpha averaged) carries up unchanged. A single pass degenerates to `box_blur` byte-for-byte -- the general verb contains the box as its 1-pass special case. The crux, proven on metal: a lone white dot on a 9px row spreads to the exact bell `[0,9,28,57,66,57,28,9,0]`, a strictly monotonic peak, where the **same** row under one box blur is the flat-top plateau `[0,0,0,85,85,85,0,0,0]` (centre tied to neighbour) -- same input, two signatures; the 2D peak is symmetric on both axes and strictly above its neighbour; a solid image stays solid edge to edge; alpha blurs into a peak like any channel; the blurred image round-trips through the open QOI codec byte-for-byte. All-or-nothing -- the source, radius, and pass count are guarded once up front, so an over-max radius (`GaussianRadiusTooLarge`), a zero or over-max pass count (`GaussianPassesOutOfRange`), or an empty source (`EmptySource`) refuses by name having allocated nothing. Witness: `tools/gaussian_witness.rish`.

- **`sharpen.rye`** -- the **unsharp mask**, the first rung that reads its own blur back, standing on `gaussian.rye`. Where a blur softens detail, a sharpen restores it: the classic unsharp mask adds back the difference between an image and a blurred copy of itself, so every edge the blur eased is made **steeper** than it began -- the crispening a designer reaches for the moment a resized thumbnail or a scanned page reads a touch soft. The math is one honest line per channel: the **detail** (the high-pass) is `orig - gaussian_blur`, positive on the bright side of an edge and negative on the dark side, and the sharpened pixel is `orig + amount * detail`, clamped to a real byte. `amount` is a **percent** over `sharpen_amount_scale` (100) -- amount 0 adds no detail (the identity), 100 adds the full detail once, 200 doubles it. This rung owns **one** new operation (the signed detail added back with a clamp) and composes it over `gaussian.gaussian_blur`; because a flat region has zero detail, a sharpen amplifies **nothing** on smooth areas -- only edges move, so it never manufactures noise on a clear sky. The crux, proven on metal: a midtone step `64 -> 192` gains an under/overshoot **halo** where the dark side darkens below 64, the bright side brightens above 192, and the contrast across the edge expands past 128 while the flat interior holds; the sharpen equals a hand-composed unsharp mask byte-for-byte (this rung owns no hidden blur or blend); a flat field gains no detail even at max amount; a strong amount drives the overshoot past the rails and each lands exactly on 0 or 255 (clamp, no wrap); alpha is sharpened like any channel; the sharpened image round-trips through the open QOI codec byte-for-byte. All-or-nothing -- the source, radius, and amount are guarded once up front, so an over-max radius (`SharpenRadiusTooLarge`), an over-max amount (`SharpenAmountTooLarge`), or an empty source (`EmptySource`) refuses by name having allocated nothing. `unsharp_mask` is the general verb; `sharpen` is the `sharpen_default_amount` (100) convenience. Witness: `tools/sharpen_witness.rish`.

- **`edges.rye`** -- the **Sobel edge detector**, the convolution floor's **detect** verb, the third pillar beside `blur.rye`/`gaussian.rye` (which smooth) and `sharpen.rye` (which enhances detail). Where those change an image's softness, an edge detector measures how fast the image is **changing** at each pixel -- it lights the boundaries where one region meets another and leaves the flat interiors dark, the first step of every outline, mask, and shape-finding pass: a photo becomes a line drawing of its own contours, a sprite becomes its silhouette. The math is the **Sobel** operator -- two small signed kernels estimate the gradient, one per axis: `Gx = [[-1,0,1],[-2,0,2],[-1,0,1]]` measures the left-to-right change, `Gy = [[-1,-2,-1],[0,0,0],[1,2,1]]` the top-to-bottom, each a weighted difference so a flat field returns zero. The edge **strength** is the integer L1 magnitude `|gx| + |gy|` (the Manhattan stand-in for `sqrt(gx*gx + gy*gy)`), so an edge is found with **no float and no square root** -- deterministic byte-for-byte; a `gain` percent scales the magnitude before the clamp, so faint edges lift into view (100 the raw magnitude, 300 triples it, 0 darkens the map). This rung owns **one** new operation (the signed directional gradient combined by magnitude) and leans only on `qoi.rye` for the grid -- no blur, no blend, no codec, no color model. The gradient is measured per color channel, each independently, and the **alpha is carried** from the source unchanged rather than edge-detected, so the edge map stays visible exactly where the source was (an opaque photo yields an opaque outline; a sprite's transparent ground stays transparent). Window edges **clamp** to the border, exactly as the blur family does, so the 3x3 kernel is always full and a 1x1 image (which has no edges) yields black. The crux, proven on metal: a flat field has no edges and stays black with its alpha carried; a vertical edge lights a horizontal gradient to 255 at the boundary while the flat interior stays dark, and a horizontal edge is its mirror; a dim corner drives **both** gradients so the magnitude is 64 (`|gx| + |gy|`) where a single kernel or a max would report only 32; gain scales the magnitude before the clamp (64 lifts to 192 at gain 300, clamps to 255 at gain 500, darkens to 0 at gain 0); alpha is carried not detected; the edge map round-trips through the open QOI codec byte-for-byte. All-or-nothing -- the source and gain are guarded once up front, so an over-max gain (`EdgeGainTooLarge`) or an empty source (`EmptySource`) refuses by name having allocated nothing. `edge_magnitude` is the general verb; `edges` is the `edge_default_gain` (100) convenience. Witness: `tools/edges_witness.rish`.

- **`convolve.rye`** -- the **general signed 3x3 convolution kernel**, the floor the specific convolutions descend from. `blur.rye`/`gaussian.rye` **smooth** (a fixed averaging window), `sharpen.rye` **enhances** (the image minus its own blur), and `edges.rye` **detects** (the Sobel gradient magnitude); each is a hand-built special case of one idea -- slide a small weighted window across the image and replace every pixel with a weighted sum of its neighbors. This rung names that idea outright, so a surface can emboss, find a Laplacian outline, or run a keeper's own filter without a new module for each. A `Kernel3` is nine signed weights over the window (row-major, `dx = k%3 - 1`, `dy = k/3 - 1`), a **divisor** that normalizes the sum, and a **bias** added after, so the whole filter is one honest line: `clamp((sum(weights[k] * window[k]) / divisor) + bias)` per color channel. The divisor lets an averaging kernel hold the image's brightness (nine 1s over a divisor of 9 is the mean, not nine times it), and the bias lets a zero-sum kernel read at mid-gray instead of black (an emboss centers its relief on 128). The weights are **signed**, so a kernel subtracts as well as adds -- what turns a plain average into an edge finder or a sharpener. Five named kernels ship as proof the general contains the special: the **identity** (a single 1 at the center) reproduces the source byte-for-byte; the **box mean** (nine 1s over 9) averages a window, its brightness held by the divisor; the **Laplacian** (`[[0,-1,0],[-1,4,-1],[0,-1,0]]`, zero-sum) lights a boundary and leaves a flat field black; the **emboss** (a zero-sum diagonal relief with bias 128) reads a flat field as mid-gray and a diagonal edge as a raised line; the **sharpen kernel** (`[[0,-1,0],[-1,5,-1],[0,-1,0]]`, the single-kernel Laplacian sharpen, distinct from `sharpen.rye`'s Gaussian unsharp mask) crispens an edge in one pass. This rung owns **one** new operation (the general signed weighted-window sum, normalized and biased) and leans only on `qoi.rye` for the grid -- no blur, no blend, no codec, no color model. Like `edges.rye`, the convolution is measured per color channel and the **alpha is carried** from the source unchanged, so the filtered image stays visible exactly where the source was; window edges **clamp** so the 3x3 kernel is always full and a 1x1 image reads its own pixel; the arithmetic is integer-only (i32 intermediate, truncated toward zero) so a filter is deterministic byte-for-byte, and the clamp lands an over/undershoot exactly on 0 or 255 rather than wrapping. The crux, proven on metal: the identity kernel reproduces the source byte-for-byte; the box mean normalizes so a flat field of 100 stays 100; the Laplacian lights a bright point to 255 and darkens its neighbors while a flat field stays black; the emboss centers a flat field on mid-gray 128 and raises a diagonal edge above it, where a bias of 0 leaves the same emboss black; a negative result clamps to 0 and an over result to 255 with no wrap; alpha is carried not convolved; the filtered image round-trips through the open QOI codec byte-for-byte. All-or-nothing -- the source and kernel are guarded once up front, so a zero divisor (`ZeroDivisor`), an over-max divisor (`DivisorTooLarge`), bias (`BiasTooLarge`), or weight (`WeightTooLarge`), or an empty source (`EmptySource`) refuses by name having allocated nothing. `convolve` is the general verb; `emboss` and `laplacian` are the named convenience verbs. Witness: `tools/convolve_witness.rish`.
- **`convolve_n.rye`** -- the **general signed NxN convolution kernel**, the general of the general. `convolve.rye` names the 3x3 convolution outright, yet a 3x3 window is itself a special case -- a wider smooth, a motion blur, a large custom kernel all want a window bigger than three. This rung names the fully general form, a signed weighted window of **any odd size**, so the 3x3 verb becomes the radius-1 case of one idea and no filter is ever gated by the window's width again. - **`separable.rye`** -- the **separable convolution fast path**, the efficiency floor beneath the general NxN kernel. `convolve_n.rye` runs the fully general window at any radius, yet it pays `(2r+1)^2` taps per pixel -- 1089 for a 33x33 window. A great many of the kernels a surface actually reaches for are **separable**: the 2D weight is the outer product of a horizontal 1D kernel and a vertical 1D kernel, `K[dy][dx] = v[dy] * h[dx]`. A box mean, every Gaussian, and a motion blur are all separable, and for those the 2D convolution equals **two 1D passes** -- convolve every row by `h`, then every column of that by `v` -- at `2*(2r+1)` taps per pixel: **66** taps for the same 33x33 window a general pass spends **1089** on, the wide-kernel work dropping from square to linear. A `SeparableKernel` is a horizontal 1D weight slice and a vertical 1D weight slice (each `2r+1` signed weights), a `divisor` that is the **product** of the two 1D normalizations, and a `bias` added after. The crux, proven byte-for-byte on metal: the two-pass filter reproduces `convolve_n.rye`'s output at the outer-product kernel **exactly**, with no rounding drift, on two conditions this rung holds -- both 1D normalizations are **deferred** so the horizontal pass keeps the raw weighted sum and the single divisor divides **once** at the end (making the integer window sum identical), and the **clamp-to-edge border is itself separable** so clamping x in the row pass and y in the column pass lands the identical border pixel a single 2D clamp would. On metal: the two-pass 5x5 Gaussian and 5x5 box mean reproduce `convolve_n`'s one-pass output byte-for-byte on a checker and on a colored translucent field (the fast path is the **same image**, not an approximation); the 5x5 Gaussian spreads a dot into a strictly descending symmetric bell and holds a flat field flat; a **directional (motion)** kernel -- a horizontal box with a vertical identity -- blurs across only, leaving a vertical line sharp down its columns; a 1x1 image keeps its pixel under both passes; alpha is carried not convolved; the filtered image round-trips through the open QOI codec byte-for-byte. Witness: `tools/separable_witness.rish`.
