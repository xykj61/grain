## What this is

A picture in Grain is **verified bytes that decode, deterministically and within named bounds, to a pixel grid** — and everything a keeper does with that picture is a pure, bounded function over the grid, the source never mutated. No network is asked to read a pixel; no key, no funds, no permission. An image is yours the way a page in a notebook is yours: held in your own hand, decoded by code small enough to read whole, addressed by its own content so a tampered byte refuses **by name** rather than painting garbage.

This module is the floor beneath Season A's **parts marketplace** and its **Photos app**. It answers the plainest question a device family can ask — *can the person who holds it also hold every picture on it?* — with yes, proven on metal.

It is pure geometry -- no pixel is touched, so like `color.rye` it is floor code that waits on nothing, and painting the placed coverage into an RGBA grid is the rung it prepares. A byte with no glyph is a named refusal (`UncoveredCodepoint`), a zero max width a named refusal (`MaxWidthTooSmall`), never a silent hole, so a caller composing with `font5x7_ascii.rye` lays out and wraps any printable string and learns of a gap at once. Witness: `tools/text_layout_witness.rish`.

- **`text_paint.rye`** -- the **paint half** that `text_layout.rye` named as the rung it prepares: it turns a laid-out string from measured geometry into a string **seen** on an image. Single-stranded composition over four free parts, braiding none of them: `text_layout` places each glyph, `glyph.rye` hands each a coverage grid (one byte per cell, 0 no ink .. 255 full ink), `color.rye` composites an ink colour over the destination (Porter-Duff src-over), and `qoi.rye` owns the RGBA target. A coverage byte is the ink's alpha at that cell (scaled by the ink's own alpha), so full ink over an opaque ink writes the ink exactly, no ink leaves the destination untouched, and a partial cell blends true through `color.over`. `paint_placed` paints an already-placed line; `paint_line` lays out and paints in one call; `solid` mints a one-colour canvas to paint on. The line's painted box is bound-checked **once** up front, so the inner loop is proven in-bounds and an overrunning paint refuses `PaintOutOfBounds` by name rather than writing outside the buffer. Where a surface would rather show the visible part of a too-wide label than field a refusal, `paint_placed_clipped` paints only the cells that land inside the target and drops the rest, returning the count it painted; it composites an in-bounds cell **identically** to `paint_placed` (both share one `composite_cell` routine), matches the strict paint pixel-for-pixel where they overlap, and degrades to a clean no-op when the whole line sits off-canvas. `paint_paragraph` wraps a block to a max width and paints each line stepping down, all-or-nothing against the target (`ParagraphOutOfBounds` by name), and `paint_paragraph_aligned` sets that block **left, centre, or right** by a pure sideways offset within each line's slack -- alignment moves ink without adding or dropping a pixel, so the up-front box check and the changed-pixel count hold whatever the alignment, `.left` reproduces `paint_paragraph` byte-for-byte, and `.center`/`.right` match a hand-composed line-by-line offset paint exactly. And `paint_paragraph_clipped` is the paragraph's clip companion to `paint_placed_clipped`: where `paint_paragraph` refuses a block that overruns, this one paints as much of it as a fixed box holds -- a line inside lands identically to the strict paint, a line straddling the bottom lands its visible rows, a line entirely below is skipped -- so a bounded panel shows the text that fits rather than refusing the whole block, returning the count of cells painted (a box the block fits in clips byte-for-byte the strict paint; a box one line-box tall paints just the first line where the strict painter would refuse; a box below the block is a clean no-op). And `paint_paragraph_boxed` is the **vertical** companion to `paint_paragraph_aligned`'s sideways set: given a box taller than the block, it places the whole stack **top, middle, or bottom** by a pure downward offset of the origin, then delegates the wrap-stack-paint to the aligned painter unchanged -- so vertical placement moves the stack down as one, adding no pixel and dropping none (`.top` reproduces the plain paragraph at the box origin; `.middle`/`.bottom` match a plain paint at the shifted origin; the changed-pixel count holds across every set), refusing `ParagraphBoxTooShort` by name when the block is taller than the box (the strict all-or-nothing companion to the clipping painter). And `paint_paragraph_in_box` is the family's 2-D capstone -- a real text region: it positions the content block within a box on **both** axes at once, one `h` set choosing left/centre/right for the block's place in the box *and* each line's set within it, one `v` set choosing top/middle/bottom, delegating the vertical half to `paint_paragraph_boxed` unchanged so every axis stays in one place. Each corner equals a plain aligned paint at the box offset (placement moves the block as one, adding no pixel and dropping none), refusing `ParagraphBoxTooNarrow` on a box narrower than the block and `ParagraphBoxTooShort` on one too short -- all-or-nothing on both axes. No new storage, codec, palette, or geometry -- only the join. Witness: `tools/text_paint_witness.rish`.

- **`shape.rye`** -- the **geometry floor** beneath the paint rungs: two bounded rectangle verbs over an RGBA grid, the shapes a surface frames a picture with before it paints a glyph. Where `text_paint.rye` paints **glyphs** onto a `qoi.Pixmap`, this rung paints **plain area** -- `fill_rect` fills a rectangle, `stroke_rect` draws a rectangle outline (a frame) -- the shapes a panel, a selection highlight, a crop overlay, a table cell, or a progress-bar track are drawn from. Pure geometry over two public APIs, braiding neither: `color.rye` composites the paint over the destination (src-over), `qoi.rye` owns the RGBA target. An opaque paint writes the colour exactly; a translucent paint blends true through `color.over`, so a panel tint reads through to the picture beneath. Every rectangle's box is bound-checked **once** up front (in `u64` so the sum can never wrap), so an overrun refuses `RectOutOfBounds` by name rather than writing outside the buffer, and `stroke_rect` paints its border ring in a **single pass** (a pixel belongs to the ring when it lies within the thickness of any edge), so a corner is composited **exactly once** -- a translucent frame reads uniform, never a darker corner where two edge bands would overlap. `fill_rect` refuses `BadRectDims` on a zero extent; `stroke_rect` refuses `BadThickness` on a zero frame and `StrokeTooThick` when two borders would overrun a side; `ring_cells` predicts the painted ring count before a pixel is drawn. Witness: `tools/shape_witness.rish`.

- **`text_panel.rye`** -- the first rung that **joins** the geometry floor with the text family: a framed text panel is the bordered card a surface draws when it wants readable text -- a dialog, a label chip, a callout, a captioned table cell. `paint_text_panel` fills the background (`shape.fill_rect`), strokes the border ring (`shape.stroke_rect`), and places a wrapped, aligned paragraph inside the inner content box (`text_paint.paint_paragraph_in_box`) -- the inner box the panel inset on every side by border thickness **plus** a padding gap. The crux is **containment**: the frame ring and the inked cells are disjoint by construction, so every ring pixel reads the border colour exactly and every ink pixel lies strictly inside the inner box (the text is sealed within the card). All-or-nothing -- the whole panel is bound-checked once up front and the wrapped block is proven to fit **before** any pixel is committed, so a panel that cannot hold its text refuses by name (`BadPanelDims` - `PanelOutOfBounds` - `PanelTooSmall` - `PanelContentTooTall`) having painted nothing; a borderless panel (thickness 0) skips the ring. Witness: `tools/text_panel_witness.rish`.
- **`text_caption.rye`** -- the rung where the framed panel first composites onto **moving video**: a caption panel over video is the **lower third** a broadcast draws -- a fixed, readable card pinned to one place while the picture moves beneath it. It renders a mostly-still ground with one small block stepping across it (real motion), then composites one fixed **opaque** caption panel (`text_panel.paint_text_panel`) onto every frame at the same lower-third place, and assembles the result as a clip. The crux is the **static overlay** over moving video: because the panel is opaque and painted at the identical rectangle every frame, its pixels are **byte-identical** across the whole reel while the background outside it genuinely moves -- steady where the eye reads, live everywhere else, and measurable (within the panel rectangle every frame equals frame zero byte for byte; outside it at least one consecutive pair differs). The composited reel round-trips **byte for byte** through both open codecs (`frames.rye` gfv1, `frames_delta.rye` gfd1); the delta/keyframe mix is reported, never claimed, yet on a mostly-still shot the pinned caption and the still ground contribute zero delta, so the inter-frame gfd1 genuinely wins (41 frames of 96x48: gfd1 16329 bytes vs gfv1 23977). Witness: `tools/text_caption_witness.rish`.
- **`text_subtitle.rye`** -- the **timing** rung above the caption: where `text_caption.rye` pins **one** fixed card over a moving reel, a subtitle track pins a **sequence** of cards, each shown only during its own span of frames. That timing is the whole difference between a lower-third and a subtitle -- the panel place holds still while the text inside it changes as the clip plays, and between two cues nothing is shown at all. A track is a bounded list of `Cue` spans (`start`..`end`, half-open), validated ordered and disjoint before a pixel is painted (`EmptyTrack` - `TooManyCues` - `CueEmptySpan` - `CueBeyondReel` - `CuesOverlap` by name); `active_cue(track, k)` is the whole reader a surface needs. The crux is that a cue is shown **exactly** over its span and nowhere else, measured against the plain no-subtitle background as ground truth: a **gap** frame equals the background byte for byte (no panel where no cue is active), a **shown** frame differs from the background **only within the panel rectangle** (the subtitle touches the card and nothing else), within one cue's span the panel is **byte-steady** frame to frame, and two different cues render **different** panels (the text really changed). The composited reel round-trips **byte for byte** through both open codecs; the delta/keyframe mix is reported, never claimed (REDS #82). Pure composition over `text_caption`'s proven approach; invents no storage, codec, palette, glyph, or font (default track: 3 cues over 24 frames of 96x48, 17 shown + 7 gap; gfd1 8196 bytes vs gfv1 10271). Witness: `tools/text_subtitle_witness.rish`.

- **`scrubber.rye`** -- the **timed-geometry** rung beside the subtitle track: where a subtitle pins timed **text** over a moving reel, a scrubber pins timed **geometry** -- the playback progress bar a video player draws along the bottom edge, its elapsed portion growing left to right as the clip plays. `image/shape.rye`'s own docstring names "a progress-bar track" as a shape `fill_rect`/`stroke_rect` exist to draw; this rung makes it literal, braiding nothing beneath. The crux is that the elapsed fill is a **monotone, data-driven** function of the frame index: `elapsed_width(inner_w, k, frame_count)` runs 0 at the first frame to `inner_w` at the last, computed in u64 and narrowed once proven in range, so **no float** ever enters. The fill count is non-decreasing frame to frame and strictly grows from **empty** (frame zero paints zero elapsed pixels) to **full** (the last frame fills the whole inner track), a scrubbed frame differs from the plain no-scrubber background **only within the scrubber rectangle** (the moving picture beneath it untouched), and the reel round-trips **byte for byte** through both open codecs (`BadScrubberDims` - `ScrubberBorderTooThick` - `ScrubberTooSmall` - `ScrubberOutOfBounds` by name; default: elapsed fill grows 0->328 px over 24 frames of 96x48, gfd1 4651 bytes vs gfv1 4627). Witness: `tools/scrubber_witness.rish`.
- **`timecode.rye`** -- the **timed-text** companion to the scrubber's timed geometry: where a scrubber pins a progress **bar** whose fill width is a pure function of the frame index, a timecode pins a **readout** whose text is a pure function of the frame index -- the "0:07" clock a video player burns into a corner, ticking one step per second. The crux, and the one primitive this rung adds, is `format_timecode`: a total-seconds count turned into "M:SS" (or "MM:SS") digit bytes by pure u32 division and modulo, so **no float** ever enters and the clock is exact at every second. It is proven by **known answer** (0 -> "0:00", 65 -> "1:05", 5999 -> "99:59"), then **bound to pixels** -- an independently painted expected-text badge matches the reel's badge byte for byte, so the digits seen are the digits the formatter produced. The readout **ticks** with playback (the badge rectangle is byte-steady within a whole second and changes at each second boundary, measured against `timecode_seconds` as the tick oracle), a stamped frame differs from the plain no-badge background **only within the badge rectangle**, the elapsed seconds are monotone non-decreasing, and the reel round-trips **byte for byte** through both open codecs (default: 24 frames of 96x48, 1 tick + 22 steady pairs, gfd1 8111 bytes vs gfv1 8087). Pure composition over `paint_text_panel` and both codecs; invents no storage, codec, palette, glyph, or font. Witness: `tools/timecode_witness.rish`.

- **`player_hud.rye`** -- the **capstone** of the timed-overlay family: the scrubber and the timecode **composed** on one reel, the way a real video player shows a progress bar along the bottom and a clock in the corner at once. It braids nothing -- it calls `scrubber.paint_scrubber` and `timecode.paint_timecode`, the very verbs their own witnesses proved, and adds only the composition and the disjointness that makes it honest. The crux is that composition is **clean**: the two overlay rectangles are proven **disjoint** before a pixel is painted (a bar clashing the badge is refused `HudOverlaysOverlap` by name, so the paint order cannot matter), a HUD frame differs from the plain no-HUD background **only within the union** of the badge and the bar (the moving picture between and around them untouched), and each overlay **keeps its own invariant under composition** -- the scrubber's fill still runs empty to full, the timecode's badge still ticks once per second. The reel round-trips **byte for byte** through both open codecs (default: 24 frames of 96x48, fill 0->328 px, 1 tick + 22 steady pairs, gfd1 9143 bytes vs gfv1 9119). Pure composition over the two overlay verbs and both codecs; invents no storage, codec, palette, glyph, or font. Witness: `tools/player_hud_witness.rish`.

## The invariants this module keeps

- **Prove before you paint.** A content-addressed picture is verified against its digest *before* the codec touches a pixel — a tampered or unknown artifact refuses by name.
- **Pure over the grid.** Every Photos verb returns a fresh image and leaves the source unmutated; an edit is data replayed, never a destroyed original.
- **Bounded everywhere.** Coordinates and samples run in `u64` so no rectangle or resample can wrap; every list names a maximum; every failure has a name.
- **No network to read a picture.** No key, no funds, no permission asked — custody-first, all the way down.
