## What this plan gives

Two things the maintainer asked for, joined:

1. **Rankings** — a 27-slot emphasis rota over the living corpus (`context/rankings.kyri`), generalizing the elder priority cycle from *practices* to *documents*.
2. A **pregenerated, deterministic itinerary** — every round of a season computed from its number alone, with carry-over folded into the next round's responsibilities. No hand-written list of 256 entries; a formula that *is* the itinerary, so any round's plan is reproducible from the number.

## The calendar, restated

`context/LEXICON.md` → **calendar**: nesting by powers of two.

- **Round** — one lap.
- **Quest** — 4 rounds.
- **Journey** — 16 rounds (4 quests).
- **Equinox** — 64 rounds (4 journeys).
- **Season** — 256 rounds (4 equinoxes = four compass directions).

## The deterministic itinerary formula

Let `r` be the **round index within a season**, `r = 0 … 255`. Every field below is a pure function of `r` — nothing hidden, nothing random.

```
equinox(r)        = r / 64            # 0..3  → the season's four themed equinoxes
journey(r)        = r / 16            # 0..15 → four journeys per equinox
quest(r)          = r / 4             # 0..63 → four quests per journey
round_in_quest(r) = r % 4            # 0..3
ranking(r)        = rankings[r % 27]  # the emphasis target this round (context/rankings.kyri)
```

**A round's itinerary** is therefore, deterministically:

- **Coords** — `season · equinox(r) · journey(r) · quest(r) · round_in_quest(r)`.
- **Theme** — the equinox's waymark and holds (below).
- **Emphasis** — tend `ranking(r)`: freshen that living target, run its witness, apply its discipline, and record any drift.
- **Carry-over** — see the rule below.

Because `256 mod 27 ≠ 0`, the ranking emphasis **drifts** across the calendar (≈9.48 revolutions per season): a ranking never sticks to one journey or equinox, so the whole corpus is tended no matter where the calendar sits. That drift is the point, not a flaw.

## The carry-over rule

Each round's responsibilities are **its own emphasis plus whatever the round before did not finish**:

```
responsibilities(r) = { tend ranking(r); advance the equinox theme }
                      ∪ { any responsibility of round r-1 not marked done }
```

A responsibility is *done* only when its witness is GREEN or its edit is shipped; anything else rolls forward into `r`. So the itinerary is pregenerated **and** self-healing — an unfinished round is never dropped, it becomes the next round's named debt. This mirrors reds-first: a red found books the remainder of the journey before new work opens.

## Season 1 — the Compass Season (the four directions)

The four equinoxes are already seated as waymarks (`.claude/rules/waymark-ladders.md`):

| Equinox (r range) | Waymark | Theme — its holds |
|---|---|---|
| 0 (r 0–63) | **SOON** | The Language — Glow runes · stdlib/PLEAC · Brix-infuse · pipeline |
| 1 (r 64–127) | **JARL** | Identity & Network — Kumara · d12·d60 topology · Comlink · settlement |
| 2 (r 128–191) | **BUHR** | Surface & Intelligence — Realidream · Quin voices · MCP-in-Bron |
| 3 (r 192–255) | **TACT** | The World — Ship-Pilot · publishing · Grainphone · commerce |

Each equinox's four journeys and their quests are generated by the formula: journey `j` of an equinox runs rounds `64·e + 16·(j-4e)` onward; each journey is one 16-round arc opening with a charter and closing with a recursion baton (per the calendar). The **ranking(r)** emphasis runs underneath the theme, so (for example) round 0 opens SOON while tending `rankings[0]` = TAME_GUIDANCE, round 1 tends RADIANT_STYLE, and so on — the discipline rota woven through the thematic work.

| Equinox | Theme — sketch |

The same formula, rankings rota, and carry-over rule apply unchanged; only the four equinox themes differ.

## How this becomes runnable (the next lap, not now)

A small deterministic generator — `tools/gen/season/itinerary.rish round <r>` — would print any round's full itinerary from the formula above, reading `context/rankings.kyri` and the equinox table, with a witness proving: (1) every `r` in 0–255 yields exactly one coord tuple, (2) `ranking(r)` is a valid roster slot, (3) the four equinox themes cover the four journeys, (4) the carry-over field is present. That generator is the build lap; this document is the plan it implements.
