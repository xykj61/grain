## What the documentation field agrees on

People who write documentation for living software, and the projects other practitioners point to when they say the docs are good, keep four kinds of page apart.

Daniele Procida set the four down in a 2017 talk, "What nobody tells you about documentation," using Django's docs as the worked example. He later gave the map a name, Diataxis (the published spelling carries an accent on the second syllable; this page stays in plain ASCII). The Write the Docs community teaches the same four. A **tutorial** is for a person learning by doing. A **how-to guide** is for a person who already has a task. A **reference** is for a person looking one fact up: complete, terse, one place for each fact. An **explanation** is for a person who wants to know why the shape is the shape.

Excellent shelves split the same way under other names. The Rust book teaches. The generated rustdoc pages are the reference. A Unix manual page is a reference. Stripe's API reference is generated from the interface and stays information-shaped, with guides beside it. Anne Gentle's docs-as-code practice keeps those pages in the same repository as the program, reviewed the way code is reviewed. Donald Knuth's literate programming weaves the prose through the source itself. That is a different bet. A compiled shelf, written from a source that already runs, is closer to this tree than a woven source is.

The agreement is about kinds of page. It is not an agreement that every project needs a new prose register called professional or reference.

## What I would not add

A style named professional, and a style named reference, would each split a job that already has a name.

Reference is a kind of page. Bhakta at the Door is the voice of the shipping shelf, including the API reference. Gauge at the Door is the voice of the operator manual. Gauge at Meter is the voice of a bound, a witness header, and a ledger row. A reader who meets computing for the first time is already served. A reader who wants one fact in one place is already served by the reference kind, written in the voice of the shelf they opened.

Folding `manual/` into `docs-geode/` would also merge two visitors the two READMEs keep apart. The operator pages (encryption, a VPN, a phone, key cards) are not the same visit as the first hour with the product. `docs-geode/etc/` is a waiting room for a new shipping genre. It is the wrong destination for the operator shelf.

## The gap that is actually open

[`../../../.claude/rules/design-rooms.md`](../../../.claude/rules/design-rooms.md) files an essay in `active-designing/` when it would still be worth reading if the code were deleted. That test stays true after a meter ships. A fascia design is still an essay about a bound. What goes stale is a door that still reads as in progress after a witness is green and a shipping page exists.

The repair is a status and a crush, not a new directory and not a shed. When a surface stops moving, the design page gains a landed line that names the shipping page. The shipping page is crushed onto the shelf that matches the visitor: a lookup onto `docs-geode/api/` or `manual/reference/`, a first-run lesson onto `docs-geode/tutorials/` or `manual/tutorials/`, an operator task onto `manual/guides/`. The design essay stays where the design-rooms test put it. Dated testimony keeps its words. An erratum covers a sentence that no longer matches the living law.

For the fascia face approved in this session, the design stays in `active-designing/` until the integer meter is witnessed. After that, Sundial's emit line and a short crushed note are the reader pages. The grade is a `u32` from 0 to 1000000, printed with four decimal places, so 1000000 reads as `100.0000`. The file census is a separate `u32` with a ceiling of 1048576, which is 2^20. Today's meter still computes `fascia` as `100 - clutter` in [`../../../tools/fixtures/f/fascia_metric_v0.sh`](../../../tools/fixtures/f/fascia_metric_v0.sh). Scaling that whole number by 10000 would print zeros. The signals have to move before the face does. Neither number is a floating-point cell.
