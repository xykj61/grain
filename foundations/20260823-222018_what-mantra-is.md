**Mantra is the part of this project that hands out names, and keeps every promise a name makes.**

## The promise, in one sentence

**Ask for a name, and you get exactly the bytes you got last time -- forever.**

That is the whole of it, and everything Mantra does exists to keep that sentence true.

## Why a promise like that is worth a whole module

Think about what usually happens when you install something. You ask for a package by name. Two
months later somebody else asks for the same name and receives different bytes, because the name
pointed at *the latest*, and the latest moved.

That is convenient and it makes builds unrepeatable. It is why the same instructions produce a
working system on one machine and a puzzle on another, and why *it works on mine* has been a joke
for thirty years.

Mantra takes the other road. **A name is bound to the bytes, so the bytes cannot change under it.**
If you want different bytes, that is a different name.

## The chemical formula

This project writes its core operations the way chemistry writes a reaction -- what goes in, what
comes out, and what stays conserved.

```
name + bytes  ->  binding
binding + name  ->  bytes            (the same bytes, every time)
```

The conserved quantity is the pairing. Nothing in the notation lets a name be re-bound, because
nothing in the module does either.

**The weave** is what happens when many bindings are read together:

```
weave(name_1 ... name_n)  ->  bytes_1 ... bytes_n     (order preserved, n bounded)
```

A weave is a bulk read with the same guarantee as a single one, and its bound is named before the
read rather than discovered during it.

## What this buys, plainly

**A build that repeats.** Same names in, same bytes out, this year and next.

**A record you can check.** If a name resolves to what it always resolved to, a receipt naming it
stays meaningful indefinitely.

**A smaller thing to trust.** You do not have to trust that nobody edited the package. The name
would not resolve.
