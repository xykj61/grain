## The distinction the whole page rests on

**Simple and easy are two different measurements, taken on two different axes.**

**Simple** describes how a thing is *made*. Do its parts stand free, each about one thing, or are
they braided through one another? That is a fact about the object, and you can check it by trying
to pull one part out.

**Easy** describes how *near* a thing lies. How familiar does it feel, how quickly can you reach
it, how well does it fit the skills already in your hands? That is a fact about you and this
afternoon, and it changes as you learn.

A thing can be easy and tangled. A thing can be simple and unfamiliar. Knowing one tells you very
little about the other, and the two get confused constantly, because the easy thing feels good and
the simple thing feels right, and both feelings arrive as a sense that this is the correct move.

*Single-stranded* is the plain name for the property this page argues for: **of one fold -- about
one thing, so it can be drawn out and understood on its own.**

## Why this tree composes rather than braids

We build by **composing**: laying free parts side by side, so any one can be drawn out, understood,
and changed alone.

The reason is a fact about people rather than about software. **A person holds a few things in mind
at once.** Parts that stand free stay inside that budget, because you can pick up one and put down
the rest. Braided parts spend the budget on the connections instead, and past a certain point
nobody holds the whole thing -- so nobody changes it with confidence, and it hardens.

The easy path is nearly always the braided one, because braiding is what you get for free when you
stop paying attention.

## Reading this architecture for what stands free

**Each module is about one thing.**

| Module | The one thing |
|---|---|
| **Rye** | the programs |
| **Brix** | the composing language -- what a system is made of |
| **Tablecloth** | the data, structured and queryable |
| **Rishi** | the hand at the prompt |
| **Mantra** | the memory |
| **Tally** | the bounded living space |
| **Caravan** | isolation and supervision |
| **Pond** | one agent's enclosure |

Each stands free. The easy path would have been one tool doing all of it, familiar and near. The
simple path keeps each one about its own thing, and this tree takes it.

**They meet through one value model.** A value passes from one part to the next as itself, rather
than being flattened to text and parsed again on the other side. That shared model *is* how free
parts compose: they sit side by side, each still its own. The seam this tree declines -- the place
where a value must be marshaled across a boundary -- is exactly the braid it declines to tie. **No
seam, no braid.**

**The enclosure is a value.** A sandbox policy that stands free -- one value naming what may be
seen, what may be changed, what bounds hold -- can be read, asserted, and remembered on its own.
The familiar way scatters the same intent across string flags, which braids meaning into syntax.
This tree keeps the value.

**Pond composes two free primitives.** Caravan's isolation is about one thing. Tally's bounded
gardens are about one thing. Set side by side they make a wall, and each half stays reasonable
about, hardenable, and trustworthy apart from the other.

**Each gate answers one question.** Behavior, shape, and the gate's own trustworthiness are three
separate questions with three separate checks, rather than one tangled *is this alright* that
nobody could fully reason about. A gate about one thing is a gate you can believe.

**The history stays single-stranded too.** Each pass states one invariant, and accretion lays a new
statement beside the old ones rather than reweaving the whole. That is composition across time, and
it means any change stays a thread you can draw out and read alone.

## The choice returns every time

Simplicity is a choice offered at every turn, with the easy path standing right beside it. One
language for everything would be familiar. String flags would be quick. A grand rewrite would feel
decisive. Each is easy, and each braids.

So the choice gets made again: one module per thing, one value model, a policy that is a value, an
accretion rather than a rewrite. It is the hardest revision rather than the first attempt, and it
earns every pass of thought it asks for.

**The easy path never leaves.** It comes back at every decision wearing the face of speed or
familiarity, and it is written down here so the choice stays conscious -- so that when the easy way
beckons, you recognize it, weigh it honestly, and take the free-standing way on purpose.

## What it buys

**The freedom to change course**, which is the thing every builder wants and few keep. Because each
part stands free, you can swap one language while the others hold still, reshape an enclosure's
policy without unweaving the kernel, and strengthen one function while trusting the rest.

**Reliability**, from the same root: a fault has fewer places to hide when each part is about one
thing.

**Understanding**, which is just a mind keeping pace with a design that never asks it to hold too
much at once.
