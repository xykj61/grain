**Mantra is the part of this project that hands out names, and keeps every promise a name makes.**

## The promise, in one sentence

**Ask for a name, and you get exactly the bytes you got last time -- forever.**

That is the whole of it, and everything Mantra does exists to keep that sentence true.

## Why a promise like that is worth a whole module

Think about what usually happens when you install something. You ask for a package by name. Two
months later somebody else asks for the same name and receives different bytes, because the name
pointed at *the latest*, and the latest moved.

That is convenient and it makes builds unrepeatable. It is why the same instructions produce a
working system on one machine and a puzzle on another, and why *it works on mine* has been a joke
for thirty years.

Mantra takes the other road. **A name is bound to the bytes, so the bytes cannot change under it.**
If you want different bytes, that is a different name.

## The chemical formula

This project writes its core operations the way chemistry writes a reaction -- what goes in, what
comes out, and what stays conserved.

```
name + bytes  ->  binding
binding + name  ->  bytes            (the same bytes, every time)
```

The conserved quantity is the pairing. Nothing in the notation lets a name be re-bound, because
nothing in the module does either.

**The batch** is what happens when many bindings cross together:

```
batch(bolt, revision) + held  ->  manifest + bytes    (at most 16 leaves, order preserved)
```

A bolt is one named bundle of facts, a revision says which version of it, and `held` is the list of
things the receiver already has. A batch keeps the same promise a single read keeps, and it names
its ceiling before it starts: `max_batch_entries` is 16 in `mantra/resin_batch.rye`, and
`build_batch` answers `TooManyEntries` at the door, ahead of the first byte it would write.

## What this buys, plainly

**A build that repeats.** Same names in, same bytes out, this year and next.

**A record you can check.** If a name resolves to what it always resolved to, a receipt naming it
stays meaningful indefinitely.

**A smaller thing to trust.** You do not have to trust that nobody edited the package. The name
would not resolve.

## Two writers, one promise

The promise above holds for one writer, and it holds just as well for two. A fact's name carries
the name of the pier that wrote it -- a pier is one person's own machine, holding its own copy of
the record. Two piers therefore write under two different names, and their facts land side by
side. Each pier keeps the promise alone, because each pier owns every name it writes. Two piers
never contend for a name.

One thing does contend: a shared counter. The ledger numbers its rows %1, %2, %3, and a counter
has exactly one next value. Two piers writing in the same hour would both claim it. The answer is
Mantra-shaped. The row number becomes a name derived from the merged record -- keyed by each
row's stamp, computed at merge time -- rather than a value two writers race to claim. A derived
name is read off the record, so both piers compute the same one. The full design is
[the pen, the gossip, and the derived spine](../active-designing/date/20260825/20260825-205011_the-pen-the-gossip-and-the-derived-spine.md).

At a send, Mantra's role is the package. The round's facts are sealed and named before the
crossing. A re-integration -- a pull that brings the other pier's round home -- re-reads those
names and leaves every binding exactly as it was written.

The horizon reads the same way: when the constellation's facts travel by wire rather than by git,
the same names travel unchanged, because a binding outlives its transport.

## One promise, wearing two clothes

The two promises above read as two sections because they used to be two things: a name bound to
bytes, and a history that remembers every line a document ever held. They are one promise now.

Here is the seam. The weave's `current()` renders a document's present lines, in order, into one
string of bytes -- `mantra/src/weave_tablecloth.rye`'s `render_current` does exactly that, joining
each line's text with a newline, the same way the document was split apart in the first place.
Those bytes are bytes like any other, so they ask the catalogue for a name the same way any file on
disk would: `render_to_leaf` renders the weave and hands the result straight to `append_leaf` in
one call. A witness proved the two sides agree before anyone wired them together --
`mantra/weave_tablecloth_seam_witness.rye` hashed a rendered weave and a catalogue leaf holding the
same bytes, and the two SHA3-256 digests came back identical, character for character, because both
paths hash the same bytes under the same algorithm. They could not have come back any other way.

So the sentence that opened this page -- *ask for a name, and you get exactly the bytes you got
last time, forever* -- is now also true of a document's whole living history, at whatever point in
its story you ask. The weave remembers every line a document ever held; the catalogue remembers
every name anyone ever bound. Asking the weave for its present state and handing that state to the
catalogue is the same motion as naming any other file, because by the time the bytes reach the
catalogue, that is all they are: bytes, asking for a name.

## Where to read next

Mantra carries a second promise, named at its christening and now standing in code: the
**weave**, one structure holding every line a file ever held, whose merges succeed by
construction and whose conflicts are shown rather than thrown. It lives at
`mantra/src/weave.rye`. A line keeps a permanent name and a generation count whose parity says
whether it is present, so merging two weaves is a union over those names taking the higher
count -- an operation that has no failing case to throw, since the answer is arithmetic. Two
guards prove it by doing: `tools/m/mantra_weave_merge_witness.rish` merges three states of one
document in all six orders and gets one answer, and
`tools/m/mantra_weave_annotate_witness.rish` reads the same two weaves and says what each side
did to every line. What remains open is placing a line **between** two others -- every insert
lands at the end today -- and that gap is named in the module's own head. Why the shape is this
shape is
[Mantra was named for the weave](../active-designing/date/20260905/20260905-153729_mantra-was-named-for-the-weave.md).

The store that holds the bytes by their own content is
[Tablecloth](20260823-222020_what-tablecloth-is.md). The language that declares what a system is
made of is [Brix infuse](20260823-222019_what-brix-infuse-is.md). The receipt format that names a
payload by its bytes is `kyri/receipt.rye`.
