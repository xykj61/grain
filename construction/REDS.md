## Why this file, and what belongs in it

Own-reds-immediately has been a house law for a long time, and it worked: reds were named the moment they were found, out loud, without excuse. What the law never said is **where**. So the ones that happened to land inside a witness header or a spec erratum survived, and the ones that happened in a sentence did not.

Three fields per row, because a red with fewer teaches nothing:

- **What went wrong** -- stated plainly, no softening.
- **What caught it** -- a compiler, a stopwatch, a guard, a second look. Never "I noticed."
- **What it taught** -- the transferable rule, which is the only part that outlives the incident.

A red enters this ledger when it is found. Rows are never edited or removed; a later correction accretes as a new row pointing back.

## What the pattern says

Read down the *what caught it* column and almost nothing was caught by thinking harder. A compiler, a stopwatch, a file-type check, a guard's first run, seven witnesses at once, a pack catching its own author. **The machine caught nineteen of twenty.**

That is not a complaint about judgment; it is the argument for the whole apparatus. Witnesses exist because the author is the last person able to see their own gap, and this column is twenty lines of evidence for that claim rather than one more assertion of it.

Read down the *what it taught* column and four rules recur: **measure before claiming**, **scope before shipping**, **fixture rather than remember**, and **narrow the objection**. Those four have paid for themselves repeatedly in a single sitting.

**REDS %193 (`20260824.104946`) -- the seed projection rebuilds its directory in place, so anything reading it mid-run reads a half-answer, and one of those readers is the gate that clears it for publication.** *What went wrong:* the seed-cadence lap ran `tools/fixtures/sow_project.sh` while the standing roster was still climbing, and the roster's own `sow` guard **re-projects**. Only then did the concurrent `sow` guard explain it. **A number nobody can tell apart from a real fault is a false red waiting to be booked**, and this one took a card entry from the previous lap to refute. *What it taught, and the misread is the cheap half:* `seed/` is the **public face**. `sow_leak_scan.sh`, `tools/s/sow_witness.rish`, and `publish-seed.sh` all gate on what stands in that directory, and a gate reading a tree still being written has examined a set nobody chose. **`IDENT_CLEAN` over a partial projection is a true statement about the wrong corpus** -- the one direction the seed's whole discipline exists to make impossible. This is REDS %172's shape returned (*running the roster manufactured the artifact the next run reported*), moved from a scan's output to the public projection itself, which is where it costs the most. *Repaired:* `sow_project.sh` takes a **lock before it clears anything**. It **refuses rather than queues** -- a second projection exits **3** and names the holding pid, because a queued run would still hand its reader a number from a tree that changed underneath them. The lock is a **directory**, since `mkdir` is atomic on every POSIX filesystem where a two-step test-then-create is not; it is released on `EXIT`, `INT`, and `TERM`; and a lock left by a killed run names its dead pid so the next run **clears it rather than wedging forever**. The path is overridable by `SEED_LOCK_DIR` so a control never touches the real one, and `git check-ignore -v` was asked rather than guessed: `.gitignore:8:/*` already covers it. *Prevention* seated as the **48th** standing guard: [`../tools/s/sow_lock_witness.rish`](../tools/s/sow_lock_witness.rish) over [`../tools/fixtures/sow_lock_control.sh`](../tools/fixtures/sow_lock_control.sh) -- **six behaviors on real directories**, four refusals bitten and two honest readings free, the refusal shown from every side that matters: it happens, it names the holder, it exits 3 rather than 1, and it leaves the holder's lock standing rather than stealing it. **The standing pass runs four of the six and says so.** The full control takes **171 seconds**, because release-on-exit is only true if the script reaches its exit and reaching it means one real projection; the four refusals take about a second. Release-on-exit is gated all the same, by a different guard: `sow_witness.rish` runs the projection every roster pass, so a leaked lock makes that projection refuse with exit 3 and turns `sow` red.
