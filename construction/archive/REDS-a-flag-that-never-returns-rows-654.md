One row, and it holds a distinction the tree had not drawn: **a path that resolves and a command
that returns are two different facts.** A tutorial printed a flag that never comes back, and every
instrument aimed at that page read it as healthy -- the guard seated one lap earlier to gate
printed paths, and the grading card that scores a page's cited paths at 100. Both measure whether a
reader can *reach* what a page names. Neither measures whether what a page tells them to run ever
*ends*, and a newcomer meets the exit code rather than the path.


**REDS %654 (`20260908.225856`) -- a documented flag that never returns, on a page graded A with truth 100.** *What went wrong:* `docs-geode/tutorials/running-the-fleet.md` printed `sh tools/f/fleet_watch.sh --dry-run` as the third line of a block whose other two terminate, under the sentence *The dry run answers, on this tree today:* and one line of output -- the shape of a command that returns. It does not. `--dry-run` sets `dry=1`; `--once` sets `passes_max=1`; the flags bound different axes, so the printed form leaves `WATCH_PASSES` at its unbounded default and watches forever at one silent pass a minute. Measured: `timeout 25` returns **124**, and `--once --dry-run` exits **0** in under a second. The tool's own header carried the same three lines and the page copied them; its ENV table eight lines below stated the truth all along -- *`WATCH_PASSES` ... default 0, unbounded; `--once` sets 1*. `docs-geode` ships **template** through the manifest, so the hanging line reached the public seed verbatim. *What caught it:* a fire lap running every command the page prints rather than reading them -- the row that sees, asking what must stop. *What it taught:* **a path that resolves and a command that returns are two different facts, and this tree measures only the first.** `docs_command_path`, seated the lap before to gate printed paths at zero, read **green** on this page in the same cold pass; `qa_report_card` graded it **A, composite 94, truth 100 on 6 of 6 cited paths**. Both instruments read reachability; neither can read termination, and a newcomer meets the exit code rather than the path. The page knew the pattern -- 44 lines earlier it pairs `FLEET_DRY=1 LOOP_LAPS=1`, the same don't-act flag bound by the same pass count -- so the fault was one block forgetting what its own page had already said. *Standing:* both prose sites repaired, the page re-graded **A, 94**; a second quoted transcript on the same page was missing the `over_bound` field the tool now prints, and its counts are a live process snapshot, so it now names the field shape and says the numbers move. **One firing in living docs** -- `prin_matrix.sh` and `prin_ticker.sh` are the tree's only other unbounded loops and no living page prints either -- so a lantern rather than a loom, and no guard built. Whether a guard should read printed commands for termination is a reading for Keaton: it would have to run them. **BOOKED.**
