**REDS %205 (`20260824.183000`) -- the room bound and the pin bound cannot both hold, and no sentence anybody writes can make them.** *What went wrong:* two numbers were seated separately and never checked against each other. A room folds past **256 flat files** (`tools/r/room_bound_witness.rish`), and a living pin stays under **24,576 bytes** (`living_pin_max_bytes`). The index must hold one row per flat file, so at the room's own ceiling the pin must hold 256 rows. **A row costs about 123 bytes before it says anything** -- 21 for the stamp cell, roughly 97 for the title-and-filename link, 5 for the pipes -- so 256 rows need **~31,500 bytes**, above 24,576 with the meaning column entirely empty. The two bounds are incompatible by arithmetic rather than by neglect, and shortening a sentence cannot reach it. *What caught it:* doing the arithmetic while choosing a row bound, rather than picking a round number and shipping. The chain that led here is worth reading: REDS %204 found the pin 5,421 bytes over after a correct fold; Keaton's word was **shorter rows**; and deriving the row bound from the pin's own capacity is what made the second constraint visible. *What it taught:* **a derived bound tests the bounds it is derived from.** Two ceilings agreed with each other for as long as nobody computed the number that has to sit between them, which is the same shape as REDS %199 and %201 -- a constant that stays true until somebody reads it twice -- arriving now between two constants rather than inside one. *Repaired:* the row bound is seated at **192 bytes** and gated by [`../tools/in/index_row_bound_witness.rish`](../../tools/in/index_row_bound_witness.rish) over [`../tools/fixtures/index_row_bound_scan.sh`](../../tools/fixtures/index_row_bound_scan.sh), proven across seventeen behaviors on planted pins with the bound shown free at exactly 192 and bitten at exactly 193. The pin reads **7,563 bytes** for 36 rows, from 291,781 before the fold and 30,224 after it. **The incompatibility is named rather than papered over**, in the mark law and in this row: 192 bytes carries a **median** day -- 61 logs across 61 measured days, mean 75 -- while **15 of those 61 days ran past the ~116 rows the pin holds**, the peak at **223**. On such a day the remedy is a fold rather than a shorter sentence, and the fold is exactly what the room bound is for. *The choice, taken the same day:* Keaton's word was **raise the pin bound for this one page**. `living_pin_max_bytes[session-logs/README.md] = 57344` -- `256 x 192` rows plus 8,192 for prose -- accreted into the seated law beside the general 24,576, which is unchanged for every other pin. The argument for an exception rather than a new general number is that the two bound different readings: 24,576 is *a pin an agent reads in one breath* and bounds a page read **whole**, while an index is read from the **top**, which is exactly what a lap is instructed to do. [`../tools/fixtures/living_pin_max_bytes.sh`](../../tools/fixtures/living_pin_max_bytes.sh) now answers **per page**, so the exception costs no second reading to disagree with the first (REDS %199's own lesson, honoured rather than re-learned), and the five meters that measure a page were each taught to ask about the page rather than about the tree. Proven by seven new checks in [`../tools/fixtures/declared_ceiling_control.sh`](../../tools/fixtures/declared_ceiling_control.sh) -- 57 in all -- including both anchoring failures a substring match would have caused: a longer path borrowing a shorter page's bound, and a shorter one borrowing a longer page's. CLOSED.

**REDS %206 (`20260824.193000`) -- the roster of planted names held two, and the tree held forty-seven.** *What went wrong:* `DP_FIXTURE_BASENAMES` subtracts a name **built to match nothing** from the reference census, so a control's planted fixture is read as intent rather than as breakage. It was a **hand-written roster**, and a hand-written roster reaches the names somebody remembered -- REDS %187's shape, booked here for the sixth time. REDS %203 named the remainder and deliberately left it uncounted, because a first pass at counting it had returned real documents that had merely moved. Counted properly: **47 planted names stand in this tree against a roster of 2**, and **nine of them were being counted as lost references** -- the census reporting breakage where a control was doing its job. *What caught it:* taking the count REDS %203 declined to guess at, with a discriminator built from the failure that made it decline. *What it taught:* **two weak tests conjoin into a strong one when each closes the other's failure mode**, and neither is safe alone. *Named in code* alone returns a document that **moved** -- the first attempt returned a foundation cited at stamp `20260729.222500` whose sprig sits on disk under `20260729.224828` -- *named by stamp rather than reproduced as a path, because a row about a wrong path that contains the wrong path is a wrong path, which this arc has now proven three times.* *Sprig absent from disk* alone returns every document ever **deleted** -- 105 of 122 lost basenames. Together they return 47, and every one is a fixture by eye: `ghost`, `theta`, `moved`, `x.md`, `never-written`, `a-room-that-never-folded`. *Repaired:* `dp_discovered_fixture_basenames` in [`../tools/fixtures/dated_path_exclusions.sh`](../../tools/fixtures/dated_path_exclusions.sh) finds them in two passes and 0.13 seconds, and the two planted names that stood on the roster came off it, since listing what discovery finds is the duplication this round exists to end. **The census falls 186 -> 177.** *And the roster splits into two halves that are genuinely different.* **Discovered:** a name an instrument plants, which is a fact. **Listed:** a name the tree *deliberately* does not carry -- three files a debride removed on Keaton's word and one page a fusion retired -- which is a decision, named by no instrument, discoverable by nothing, and correctly still written down. Four remain. *Owned in the same breath:* the first working draft discovered **all six** roster entries including the four decisions, because **the roster file is itself a `.sh` and names every one of them** -- a list that reads itself discovers everything it lists. It is out of its own corpus now, and the control proves that from both sides by appending a name to the roster and watching discovery decline it. This is `declared_ceiling`'s own lesson in a new room: an exemption keyed on a file's **role** rather than its contents is what keeps the exemption from becoming the roster it exists to retire. *Prevention:* six new checks in [`../tools/fixtures/dated_path_exclusions_control.sh`](../../tools/fixtures/dated_path_exclusions_control.sh), on a real git repository in a throwaway pen -- a planting discovered, a moved document free, a deleted document free, a vendored mention free, the roster declined its own contents, and no scratch file left in the tree it read. CLOSED.
