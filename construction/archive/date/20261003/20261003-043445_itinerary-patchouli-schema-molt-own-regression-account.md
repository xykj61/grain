**PATCHOULI -- THE LANE'S OWN LAST COMMIT REGRESSED THE HEAD IT TOUCHED, AND NO LAP HAD RE-GRADED

[shelved](20261003-041504_itinerary-patchouli-fourth-family-and-control-plant-fix-account.md). A
seventh confirming sweep for `%765` and `%807` surfaced nothing new, so this lap re-graded
`mantra/src/receipt_offer.rye`'s module head with `qa_report_card.sh --setting door`, the same
habit named on this card's own fifth and sixth accounts. It read **composite=51 (F)**, reach
grade 16 against the Door ceiling of 9 -- below the elder A/93 reading that same account recorded
for this file three commits ago.

*What went wrong:* the commit landing REDS %765's fourth family (`20261003.040829`) rewrote the
head's third paragraph to separate `schema_v1`'s name from its value, and in doing so raised the
paragraph's own sentence count from six to eight -- crossing `prose_register_scan.sh`'s eight-
sentence floor from below to above. Below the floor, Reach is *reported* and the composite
defaults to a flat 75 regardless of grade level; at or above it, Reach is *scored* for real. The
new paragraph's grade level (16) had stood unscored and unnoticed the whole time; crossing the
floor made it count, and the commit that crossed it never re-ran the grading tool to check.

*What caught it:* re-running `qa_report_card.sh --setting door` against the current head rather
than trusting the card's own prior reading, after a first blanket sweep across every `mantra/` and
`tally/` file (passed `--service 0` by habit) printed suspiciously low composites nearly
everywhere -- a methodology error rather than a finding, since `--service 0` caps the composite at
75 whenever Register and Reach both already read 100, the same `(100+100+100+0)/4` arithmetic the
tool's own four-question Service scale states plainly. Re-run with a real Service estimate
(`--service 100`, matching this file's `living_citers=30 named_by_card=yes in_seed=yes`), the flat
reading cleared and the regression stood alone, genuine.

*The repair:* the three head paragraphs rewritten into eighteen shorter, affirmative sentences,
every path, bound, and backticked identifier held exactly -- `Log.refusal`, `fact_eql`,
`offer_fact_fields`, `error_of`, `AdmissionError`, `tally_receipt_refusal.rye`, `schema_v1`,
`grain.receipt-offer.20261003.040829`, `ReceiptState`, `stamp-and-name.md`, REDS %765,
`20261002.180446`. Register 0% negative of 18 sentences, Reach grade 8 against the ceiling of 9,
composite A+/100 at Door with Service rated at its real value. No code line moved -- `git diff
--stat` reads comment lines alone. Four touching witnesses re-run GREEN on metal:
`mantra_receipt_offer_refusal_chain_witness.rish`, `mantra_receipt_offer_snapshot_witness.rish`,
`mantra_consent_replay_witness.rish` (the neighboring %765 family), and
`tally_receipt_offer_bounds_witness.rish`.

*What it taught:* a comment rewrite that adds one more sentence can cross a scoring floor the
writer never watches, and a lane that fixes a module head once is not thereby done with it --
the next commit touching the same comment can undo the fix without anyone reading the number
again. The fix here is read-before-write: grade a module head's current state before trusting an
elder account's reading of it, whenever the file has moved since.
