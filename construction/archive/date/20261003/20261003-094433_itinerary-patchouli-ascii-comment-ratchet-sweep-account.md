**Shelved whole from `construction/ITINERARY.md` -- `20261003.094433`.**

The seventeenth sweep (`session-logs/date/20261003/`, seventeenth confirmation of an empty queue)
named the lesson plainly: repeating the same two `%765` grep nets every lap buys little, and the
next lap should widen to a fresh class of search before adding an eighteenth near-identical entry.

This lap took that instruction. Rather than re-running the chronological-header grep a fourth-teenth
time, it read `tools/fixtures/r/rye_comment_ascii_scan.sh` -- the ASCII-first comment ratchet
([`ascii-first.md`](../../../../.claude/rules/ascii-first.md)) -- scoped to this lane's own
`mantra/` and `tally/` files, since that ratchet is a standing TAME discipline this lane had never
checked on its own ground.

Two files carried real non-ASCII characters, four in total: `mantra/recall_batch_wire.rye` line 3
carried one `<=` sign written as its Unicode glyph (`\xe2\x89\xa4`), and `tally/gardens.rye` carried
three section-sign (`\xc2\xa7`) comment-header markers at lines 43, 58, and 243. Both are forms the
rule's own table and its own precedent already settle: the Unicode `<=` becomes the ASCII `<=`
exactly as the table names, and a section sign becomes the word `Section`, the same substitution
`ascii-first.md` itself records a prior sweep making by hand.

Both files are repaired, the scan's `CEILING` constant lowered `2625 -> 2596` to match (four
characters, zero slack, re-measured and confirmed exact), and the following checked GREEN on metal
after the edit:

- `tools/as/ascii_comment_witness.rish` -- GREEN, all three comment-syntax meters, including this
  one's own ratchet.
- `tools/t/tame_style_check.rish` -- GREEN, bans clean, nothing from this edit in the printed
  ratchets.
- `rishi/bin/rishi run tools/m/mantra_recall_batch_wire.rish` -- GREEN, the witness exercising
  `recall_batch_wire.rye` through its dependent `recall_batch_delivery.rye`.
- `tally/gardens.rye` built directly with `tools/fixtures/r/rye_build.sh` and run: `tally gardens:
  all facts held.`, exit 0.

`tools/w/width-check.rish` reads `verdict=authored_width_drift` both before and after this change --
confirmed pre-existing by stashing the three touched files and re-running the check unchanged
(`corpus_flagged_lines=1114` against `ceiling=1109` either way). That drift belongs to a different
lap; nothing in this sweep's own files moved it.

**What it taught:** a lane can run the same two grep nets honestly for seventeen sweeps and still
be sitting on live, agent-doable, lane-scoped work the whole time, because the nets were built for
one named family (`%765`) and never widened to the standing TAME ratchets that already apply to
every `.rye` file this lane owns. The next empty-queue lap should check a *different* standing
ratchet against `mantra/`-`tally/` before repeating this one -- `rye_written_ascii_scan.sh`,
`rye_spoken_ascii_scan.sh`, or the explicit-width corpus this lap found already RED for reasons
outside this lane.

another ship's own lane.
