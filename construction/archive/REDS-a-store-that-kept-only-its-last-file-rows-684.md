**REDS %684 (`20260910.003046`) -- `mantra add` on a second file deletes the first file's history, and reports `wove 2/2 file(s).` while it happens.** *What went wrong:* a `mantra-commit-v1` blob named **one weave** for a whole directory. `cmd_add` loaded that weave, diffed the next file's text against it, and applied the difference -- so weaving `b.txt` after `a.txt` recorded every line of `a.txt` as **removed**. `mantra status a.txt`, on a file nothing had edited, answered `2 added, 2 removed`, listing `a.txt`'s own lines as additions and `b.txt`'s as deletions. The `.brix` add-all route -- the tool's own advertised way to track a project of more than one source -- fired it on every run and printed a success line over it. *What caught it:* the earth rota's own gesture, taking in the concrete fact at the door before arguing with it: two files put through the built binary in a pen, and the tool asked the user's question rather than a function asked its own. **Six weave witnesses and the CLI-record guard all stood GREEN**, because every one of them proves a record's shape and none had ever added a second file. *What it taught:* **a path is what tells one document from another, and a record that omits it is not a record of documents.** The elder format could describe the whole store and could not describe a file, so no reader of it could be right. *Repaired (`20260910.003046`):* `mantra-commit-v2` carries one tab-separated `file` row per tracked path; `weave_for` looks a path up; `commit_files_with` carries every prior entry forward, replacing the one path it was handed. **Elder stores keep opening**: a v1 blob lifts to a single entry whose path is empty, which `weave_for` reads as *the weave a path inherits until it has its own*, so the frozen store at `tools/fixtures/m/mantra_elder_v1_store/` answers exactly as it did and the first commit onto it starts that file from the history already there. Tab rather than the elder space, since a tracked path may carry a space and v1's parser splits a row at the first one. *Proven:* `tools/m/mantra_multifile_witness.rish` over a scan of **nine readings** and a control of **six phases / five breaks**, each phase naming the one reading it moves -- a reader that ignores the path and a writer that drops the prior entries are told apart, and the elder dispatch and the empty-path fallback are told apart, since either pair read as one number would let half of it rot while green.
