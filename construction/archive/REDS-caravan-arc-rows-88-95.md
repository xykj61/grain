The exact-zero form is also *stronger than the finding it defends*: the rung's claim is that readiness converts a slot and never a domain, which is a claim about direction rather than about a count the operating system gets a vote in. **CLOSED the same round (`20260820.031500`), and the diagnosis moved the fix into the module rather than the assert.** Probing which slot readiness actually chose showed the failing runs differ at one turn: readiness reaps the **lowest-indexed** ready dependent, and when a sibling the head does not want finishes first, reaping it empties a slot the head still cannot use -- converting nothing and leaving the turn idle. That halved the failures rather than ending them, which named the second cause honestly: when the dependent the head waits on is **still working**, an idle turn is ordinary and no reaping order removes it. The exact-zero assertion had been counting both together. So the module now measures the number it can guarantee -- **`idle_key_ready`, a turn that stood idle beside a dependent already exited whose going would have opened the door** -- which is the claim the RED message was already wording. Eldest-first stands 1 such turn on the stagger lap every run; readiness stands 0 by construction. Measured on metal: **16 of 16 runs GREEN** where 2 of 12 were RED before, the raw idle counts still reported and asserted nowhere, and the choir sung twice through. Both RED paths proven on metal: invert the preference so readiness reaps a sibling that opens nothing and it stands 1 or 2 key-ready idle turns; silence the counter and the lap refuses its own precondition, since the eldest reading must stand idle beside a ready slot for the finding to mean anything. Released.

**REDS %88 (`20260820.002850`) -- two witnesses building at once corrupted each other, and the tree read it as three failing rungs.** *What went wrong:* every `tools/g/glow_run_worker.sh` invocation rebuilt `glow/bin/glow_run` and wrote `glow/.cache`, and it emitted straight to the final path. So a sweep running beside a hand-run gate wrote the same bytes from two processes: the lane that lost executed a half-written binary and reported RED **about its own logic** while nothing was wrong with it. A build killed midway left a truncated `glow_run` standing, which the next entirely clean run then trusted. *What caught it:* the Caravan `child` -> `dependent` molt round -- `caravan_glow_tend_limb1/2/3` went RED together and re-ran GREEN twice with nothing changed between them, and `aurora_wire_a1` and `mantra_gen_floor_a1` fell in the same breath. The Caravan choir's roster lists became per-run for the same reason. **REDS %89 (`20260820.002850`) -- every RED message in this tree was hiding its own cause.** *What went wrong:* Rishi's `assert <cond> else "<message>"` printed the message's **literal text**. `say "${x}"` had always interpolated; the assert message alone never did -- `do_assert` stripped the quotes and printed the raw bytes without ever calling `interpolate`. So `else "build failed -- ${build.err}"` reported `${build.err}` and named nothing. Measured across the tree: **1,632 such messages in 731 witness files.** *What caught it:* diagnosing #88. The Caravan choir's own failure line read `a per-rung witness went RED -- ${w}`, which named none of its 52 rungs, forcing a hand-rolled loop over every witness to find the one that broke -- and the answer, once found, was that nothing had broken. The bug's cost was almost entirely the diagnostic's silence. *What it taught:* **the message a failure carries is part of the failure.** A diagnostic that cannot render its own facts costs more than the fault it reports, and the gap hid in plain sight for as long as it did precisely because it only ever appeared on a path people were already unhappy to be on. Fixed in `rishi/src/main.rye`: `do_assert` now tracks whether the reason was quoted and renders it through `assert_message`, so a **quoted** message interpolates like every other string in the language, an **unquoted** reason is shown exactly as written, and a message that **cannot** render falls back to its own raw text rather than replacing the failure with a second one -- the assertion is the news. All 23 `rishi/tests` GREEN, the six `rishi_*` witnesses unchanged in behaviour. Released.
