So the refusal line a reader meets reads `field=value_unit value=97 ceiling=96 unit=ascii-byte reason=too-long`, and 96 is a number nobody chose for that field: it is the identifier's, wearing the value unit's name. *What caught it:* a water-row reading of the contract against the code it governs, on the rota's own instruction to read up close and run the actual thing. Not a guard -- nothing in this tree asks whether every field a contract publishes carries a ceiling that contract declares. *What it taught:* **an unnamed bound does not stay unbounded; it gets borrowed.** An implementation obeying *bound everything* must reach for some number, and the nearest declared ceiling is the one it reaches for -- so the gap closes silently, in the direction that looks compliant from both sides.
