**REDS %800 (`20260916.231943`) -- the sibling fault to `%795`, on the same page and in the same hour: a wrapped sentence opened a code fence that never closed, and 79 percent of the card rendered as code.** *What went wrong:* commit `99d4948e6a` on `20260916.213938` wrapped a sentence in `construction/ITINERARY.md` so a bare triple-backtick fence opener landed at column 0 in prose -- the author was NAMING a fence, not opening one. CommonMark reads a line beginning with three backticks as an opening code fence and states that when no closing fence is found the block runs to the end of the document. So **30,791 of the card's 38,970 bytes, 79 percent**, rendered as one code block for every markdown reader, GitHub included: the whole INNER LOOP every ship reads at each lap open, the product direction, and all eight ships' accounts. *What caught it:* an ordered-list probe written for `%795`'s class, which read **zero** on the broken card and should not have -- the fence was swallowing every list below it, so the probe's own blindness named it. The list half went to `bakery-living-pin-list-spine`, claimed seventeen seconds ahead and stricter; this seat yielded it whole and kept what the collision uncovered. *What it taught:* **every standing guard over a living pin reads its BYTES, and not one reads it as MARKDOWN.** `ascii_document` counts characters, both link guards read links, the pin bound counts length, `nib_honesty` reads one key; each was green throughout, each reading bytes that had not changed. A page can be byte-perfect and structurally broken. `%795` and this row are the same lesson from two sides -- a numbered list and a code fence are both STRUCTURE, and the tree had no reader for either. *Repaired and gated:* the sentence reflowed so the backticks sit mid-line, and `tools/l/living_pin_fence_witness.rish` over `tools/fixtures/l/living_pin_fence_scan.sh` holds living pages at **zero** -- a WALL rather than a ratchet, since exactly one unbalanced fence stood in 453 living pages and it was this one. Testimony is reported, never gated. Control **41 legs, 0 failing**, every refusal planted and then lifted, **three mutations bitten**: the info-string rule without which prose quoting two code spans reads as a fence, the matching-character rule without which a tilde line closes a backtick block, and the newline walk without which the one tracked page whose name holds a space falls out of the reading. **The firing is replayed from history rather than imitated:** the card at `99d4948e6a` is fetched into the pen and refused, naming line 103. *And the control's own first draft passed three mutations by measuring the wrong program*, copying the planted repository over the mutant scan rather than under it. A mutation leg that passes because it measured the wrong binary is worse than no leg. *And the root cause fired a SECOND time on the same page, found by the sibling guard within the hour:* a wrapped sentence in a peer's account left `32.` at column 0, which CommonMark reads as an ordered-list item, and `itinerary_list` refused it. Both faults are one habit -- **a hand wrapping prose to a column can create markup it never typed**, since a fence opener and a list marker are both decided by what stands at the start of a line. Neither hand made a mistake in their sentence; the wrap made it. That is why two structural readings beat a sharper reviewer, and the argument for a third. *What this does not reach:* a fence indented four or more spaces, inside a list item or a blockquote, which wants a block-structure parser rather than a line reader; the scan names that bound on its own face and undercounts in the safe direction. **CLOSED.**
