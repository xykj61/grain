**REDS %341 (`20260829.124742`) -- the ceiling test whose every bead was the same bead.** *What went wrong:* `mantra/spool.rye`'s ceiling block declared in its own comment *"Build a distinct pattern per byte so no two beads dedup -- the store bound is exercised in full"* and filled its 32,768-byte artifact with `wide[k] = @intCast(k & 0xFF)`. That expression has period **256**, and `spool_bead_size` **is** 256, so all **128** of the artifact's beads carried the identical byte sequence 0,1,...,255. The winding deposited **one** bead and deduped 127; `BeadStore.count` read **1 of its 256**. The block printed `rep_c.bead_count` -- 128 -- which counts beads **addressed**, never beads **stored**, and `tools/g/gism_spool_witness.rish` asserted that same 128. So the test exercised **1/128th** of the bound it named, and the line it printed read like the opposite. Two faults stood behind it, both unreachable while the store never filled. **`spool_content` deposited before it could know it would finish:** its loop calls `try beading.bead(store, resin, ...)` resin by resin, so a store filling part-way left that artifact's earlier beads in place -- held by no spool, named by no catalog, unreclaimable, since `BeadStore` only ever appends and publishes no removal. And **`pond/apps/spool_cloth.rye` advertises `max_large_artifacts = 4`** over a store that holds **two** full ones: a ceiling artifact costs 64 resins at 2 beads = 128 beads of `beading.max_store_beads` 256. Three comments reason about that relationship in three different scopes -- `beading.rye:51` sizes the store for one large artifact "with headroom for a second", `spool.rye:47` checks `max_resins * 2 <= max_store_beads` for a single spool, `spool_cloth.rye:40` reasons about catalog memory and never about beads -- and nothing multiplies the two numbers. *What caught it:* reading the ceiling block to size a different question, whether four full artifacts fit a 256-bead store, and noticing that the pattern the comment called distinct has the bead size as its period. Confirmed outside the tree before a byte was edited: 128 beads, **1 distinct**. *What it taught:* **a test that names a bound as its subject must assert against the bound's own reading, never against the count the caller handed back.** `bead_count` and `store.count` agree only when nothing dedups, which is exactly the condition this test existed to create -- so the two were equal in the passing case and the assertion could not tell the passing case from the failing one. That is REDS %311 one module over: there a needle the harness supplied could never red, here a count the report supplied could never disagree with itself, and both pass because the checker and the checked share a source. The sharper half: **a green test proves its assertions, never its comment**, and no meter reads a comment. *Repaired (`20260829.124742`):* `fill_distinct_beads` gives each bead its artifact's tag in byte 0 and its own index in the rest, so two beads agree only when tag and index agree; the ceiling block asserts `beads_deduped == 0`, `beads_deposited == bead_count`, and **`store_c.count == bead_count`** -- the reading a report cannot fake -- and prints all four numbers. `spool_content` takes `const store_mark: u32 = store.count;` with `errdefer store.count = store_mark;`, an exact rollback because every bead **this** winding deposits sits at an index at or above the mark, while one it deduped against was already below it. New `refusal_leaves_store_whole` winds a ceiling artifact and a half one to hold 192 of 256, proves the next ceiling winding refuses `StoreFull`, and proves `store.count` reads **192 on both sides of the refusal** with the earlier artifact still recalling byte-for-byte. Measured on metal: ceiling **128 deposited, 0 deduped, store holds 128 of 256** (was 1, 127, 1). Both mechanisms proven **by removal**: restore the elder fill and `assert(rep_c.beads_deduped == 0)` trips at `spool.rye:363`; delete the `errdefer` and `assert(store_f.count == held)` trips inside `refusal_leaves_store_whole`; each restored `cmp`-identical. *Two witnesses were already RED at HEAD and nobody had seen it* -- %328's own sentence, since neither is on the standing roster. `tools/g/gism_spool_witness.rish` pinned `SECURITY.md` at 2689 B and `context/TWO_ROOMS.md` at 6079 B; on disk they read **2659** and **6030**, both documents edited after the witnesses were written. Both now **read the sizes from disk** rather than spelling them, because a witness owns the behaviour it guards and never the byte count of somebody else's document; `tools/g/gism_spool_cloth_witness.rish` carried the same pins and takes the same repair. Both GREEN on metal. **CLOSED** -- the ceiling fills, the rollback holds, and both witnesses read from disk. *One finding rides out of this lap into another seat's room rather than staying live on a shelf:* `pond/apps/spool_cloth.rye`'s `max_large_artifacts = 4` stands over a store that guarantees **two**, and its three honest doors -- lower the catalog to the truth, raise `max_store_beads` to 512 (about 75 KB more per `BeadStore`, paid by every one in the tree), or publish a derived `guaranteed_full_artifacts` beside the advertised bound and name `StoreFull` in `store_large`'s doc comment, which today lists every refusal except the one a caller meets first -- are a line on `construction/ITINERARY.md` for the seat that owns `pond/apps/`. *A last reading, paid before this row shipped:* the row was first written WRAPPED at a hundred columns, and `reds_pin_capacity_rows.awk` reads a row as a LINE -- `/^\*\*REDS [%#][0-9]/` -- so the status marker sat on a line the reader never saw and the row read `PIN_OPEN=0`.
