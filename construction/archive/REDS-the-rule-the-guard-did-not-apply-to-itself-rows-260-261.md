# REDS -- the rule the guard did not apply to itself (rows %260, %261)

**Language:** EN
**Status:** Shelf -- immutable once written
**Voice:** Kyri

Two rows from one round, and they are the same fault at two scales. %260 is a fallback written
BSD-first, one lap after this tree wrote down why GNU must go first -- the rule stood in the date
functions' own comment rather than anywhere a `stat` author would look, so it did not travel.
%261 is a meter hunting for GNU-only idioms with a pattern that had no left boundary, one week
after the census beside it learned that a reference begins at a boundary. Neither rule was missing.
Both were written somewhere the next author would not pass.

**REDS %260 (`20260826.090745`) -- the fallback whose first leg half-worked, so both legs answered.** *What went wrong:* `tools/fixtures/ryekey_control.sh` read a build's modification time with `btime() { stat -f %Fm "$BIN" 2>/dev/null || stat -c %.Y "$BIN" 2>/dev/null; }` -- BSD's spelling first, GNU's behind an `||`. GNU reads `-f` as `--file-system`, so on this pier the first leg asked for the filesystem holding a file named `%Fm`, which fails, AND the one holding the binary, which succeeds: five lines of block and inode counts on stdout, exit status 1, and the `||` then appending the mtime underneath. Six lines where one was meant, on every GNU run since the control was written. *What caught it:* reading the site up close before gating its family, and running the pair by hand rather than trusting that a `||` means the legs are exclusive. The comparisons it feeds -- `[ "$(btime)" = "$t1" ]` -- passed anyway, because the five-line prefix was constant across calls, so nothing was ever visibly wrong. *What it taught:* **a fallback is only a fallback when the first leg refuses cleanly, and `-f` is `date -r`'s trap wearing another flag.** The rule was already written one lap earlier, for `date`: GNU goes first because GNU is the dialect whose refusal of the other's flag is clean. It was written in the date functions' own comment rather than anywhere a `stat` author would look, so it did not travel. It lives in `tools/fixtures/shell_portable.sh` beside `file_mtime` now, where the next dialect question will find it. *Repaired:* one call to `file_mtime`, GNU first, proven on metal by `prove-stat` -- the elder order reproduced at six lines on this host, the repair answering exactly one line on GNU and one more under a `stat` that refuses `-c` outright. The family is gated at zero. CLOSED.

**REDS %261 (`20260826.090745`) -- a flag inside a longer command name counted as the flag.** *What went wrong:* the `grep -P` advisory in `tools/fixtures/shell_dialect_scan.sh` matched `grep[[:space:]]+...-P` anywhere in a line, with nothing said about what may stand to its left. `pgrep -P "$super"` in `tools/fixtures/caravan_subscribe_poll_source_crash.sh` names a parent process id, is spelled identically on both piers, and was counted as a GNU-only site. The family read six where four lines carried it. *What caught it:* listing every site file by file before touching any, rather than acting on the count the previous lap's card carried. *What it taught:* **a meter's own pattern needs the boundary rule it measures others by.** `dated_path_scan.sh` learned in `20260824` that a reference begins at a boundary, and REDS %257 learned in the same week that a count which overstates a repair names a size no edit can reach; this is that sentence one layer down, inside the guard that hunts for dialect. Ask what the number instructs, and whether doing it would help anyone -- deleting a `pgrep` would help nobody. *Repaired:* the pattern begins at `(^|[^A-Za-z0-9_.-])` now, and the limit is named in the file rather than hidden: `zgrep -P` and `xzgrep -P` are read past too, and nothing in this tree writes either. CLOSED.
