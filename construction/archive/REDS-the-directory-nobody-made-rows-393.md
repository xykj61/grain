**REDS %393 (`20260831.035452`) -- a rostered choir builds into a gitignored directory it never creates, so it reds on every clone that has not built Mandate before.** *What went wrong:* `tools/o/operations_conformance_witness.rish` builds five Mandate binaries with `rye build mandate/$m.rye -femit-bin=mandate/bin/$m`. `mandate/bin/` is build output and `.gitignore` names it at line 191, so a fresh clone does not carry it, and `-femit-bin` into a missing directory fails the build. The witness then asserts `operations: a Mandate binary did not build`, which names the code and blames it for an absent directory. `tools/ac/acme_dx_witness.rish` runs that witness as one leg, so the choir rostered GREEN on the pier at `20260831.014630` -- 3s, measured on a bench that had built Mandate many times -- reds on a clone that has not. *What caught it:* this seat's own `--hot` close on the macOS bench: 108 guards, 104 green, four red, where two are the custody-gated pair the card names (`rule_twin` at gate %7, `pond_enclosure_door` at gate %5) and two were not. Running the same five builds by hand outside the witness built all five, which is the reading that tells a code fault from an environment one -- and the witness's own command then succeeded the moment `mkdir -p mandate/bin` had run. *What it taught:* **a witness that writes into build output must create it, because the one machine where a gitignored directory reliably exists is the machine that has already run.** That is `%360`'s stale-pin class turned over: there, unheard guards carried expectations pinned to a tree that had moved; here a heard guard carries an expectation pinned to a tree that has *worked*, and both are invisible on the bench that wrote them. A guard rostered from one clone carries that clone's history inside it until a second clone runs it, which is the argument for the fleet reading the same roster from different trees. *Repaired (`20260831.035452`):* one `mkdir -p mandate/bin &&` at the head of the build loop, with the reason beside it. Proven from a genuinely fresh state -- `mandate/bin` removed, then `acme_dx` GREEN end to end -- so the directory the repair makes is the only thing that carried it. *The fourth red is the same class at a custody edge and is named rather than taken:* `tools/co/commit_message_guard_witness.rish` asserts `SEED_PUBLISHER_ARMS 1` by grepping `publish-seed.sh`, which `.gitignore` line 8 keeps untracked at the root by design, so the guard cannot pass on any clone lacking the publisher -- including this one, whose seat forbids ever running it. **CLOSED.**
