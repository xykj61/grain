**REDS %725 (`20260912.005558`) -- a rostered ban guard pruned the gitignored rooms by name, named two
of the six git's own rules disown under `tools/`, and would false-RED the fleet on any file landing in
the other four.** *What went wrong:* `tools/fixtures/t/tools_py_ban_scan.sh` enforces this tree's ban
on Python under `tools/` by walking the filesystem, and pruned `tools/.cache` and `tools/.build` with
its reason written beside them -- *both stay gitignored; counting them would false-RED the living tree
on Framework*. So the guard had already met this fault once and paid for it. What a list of two names
cannot cover is the room nobody has opened yet: `.gitignore` disowns **six** paths under `tools/` --
`tools/.build/`, `tools/.cache/`, `tools/bin/`, `tools/glow/`, `tools/fixtures/.forge_view_bundle/`
and `tools/fixtures/session_logs_archive/_sandbox/`. Four stand absent on this disk today, so the
fault was latent rather than live. *What caught it:* the class meter this lap built,
`tools/fixtures/i/ignored_walk_scan.sh`, which reads every tree-rooted `find` in the 3,483 tracked
`.sh` and `.rish` sources under `tools/` and asks whether the file calls `git check-ignore`. It named
28 walks that do not, 19 of them walking a root that holds an ignored path on this disk right now.
Then proven on metal rather than argued: a file planted at `tools/bin/probe.py` -- a room `.gitignore`
names on its own line -- makes the elder spelling print `TOOLS_PY_BAD` and the repaired one print
`TOOLS_PY_OK`, and removing the plant returns both to green. *What it taught:* **a pruned name is a
claim about what somebody remembered, and the ignore rules are the tree's own statement of what it
disowns, in one place, kept current by whichever hand opens a room.** The elder line's own comment is
the proof: it names the two rooms that existed the day it was written, and nothing in it could grow.
The direction of the error is the expensive one, the same one `%722` named -- a red on every ship for
a file no clone holds is how a gate gets turned off. *Repaired (`20260912.005558`):* the walk asks
`git check-ignore --stdin` for the whole walk at once and subtracts what git disowns; the spelled
prune stays as the **no-git fallback**, since that script resolves its root by a deliberately git-free
upward walk so a copy runs in a pen outside any repository, and a copy reading every path as ignored
would refuse nothing. `TOOLS_PY_FILTER=git|spelled` is printed, because a silent fallback is the same
shape of fault this repair closes. Both directions hold: the living tree reads `TOOLS_PY_OK` and the
negative selftest's planted `tools/planted.py` still reads `TOOLS_PY_BAD`. *Walled:*
`tools/i/ignored_walk_witness.rish` holds the class at a ceiling of **27** that only falls, over 32
behaviors proven on real git repositories in a throwaway pen, every refusal planted and then lifted
and two mutations asserted to bite. **BOOKED** -- this instance is repaired and the remaining 27 are a
ratchet each lane turns on touch, with the four inert members and the 64 variable roots named in the
scan's own output rather than left for a reader to rediscover.
