**REDS %476 (`20260906.091039`) -- the probe declared its bound with an assert, and the build it ships under deletes asserts, so a walk 64x past that bound ran as undefined behavior and printed a plausible number.** *What went wrong:* `tools/fixtures/t/tlb_reach_probe.rye` gained an elder-sizes leg walking up to **524,288** nodes, while `build_chase` still declared `assert(n <= max_nodes)` with `max_nodes` at **8,192** -- the paired sweep's bound, correct for the paired sweep and 64x too small for the new leg. The probe is built `-OReleaseFast` by its own census, where `std.debug.assert` compiles to `unreachable`: the bound is not merely unchecked, it is a promise the optimizer is entitled to rely on. *What caught it:* reading the output rather than the exit code. The run did not crash and did not refuse -- it printed `elder kib=68` where **32768** was passed, and `cat -A` showed the bytes `^D^A` standing where three digits of its own working-set size should have been. Two readings above it were equally out of bounds and printed perfectly plausible numbers, which is the worse half: the third garbled visibly and the first two did not. *What it taught:* **a bound that exists only as an assert is not a bound in the build that ships.** TAME asks for two separate things -- *state the invariant* and *check at the edge, fail with a named error* -- and an assert satisfies only the first once a release build strips it. The distinction is invisible in a debug run, which is where a bound is usually exercised. *Repaired:* both measurement entry points, `measure` and `measure_elder`, now check their bounds at run time and print `refused ... bound=N` rather than asserting them; `measure` keeps the tighter paired-sweep bound, since its spread layout spends a whole page per node. Four further asserts widened to `max_elder_nodes`. Proven by re-running: the same leg now reads `elder kib=32768 nodes=524288` on metal, stable across four runs, and the census reports its attribution. *Ratchet, named and not swept:* every `-OReleaseFast` probe in this tree has the same property, including this lane's own `tools/fixtures/f/footprint_latency_probe.rye`, whose sweep is a compile-time constant so a violation needs a source edit -- lower risk, same class. **BOOKED** -- both instances in the probe that carried the fault stand repaired and proven on metal; what remains is the ratchet across the other release-built probes, which turns on touch, and door B is exactly that shape.
