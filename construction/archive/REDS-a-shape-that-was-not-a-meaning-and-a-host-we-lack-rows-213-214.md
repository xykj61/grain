**REDS %213 (`20260824.234500`) -- the instruction was to seat 456 labels, and 361 of them would have been false.** *What went wrong:* the invariant meter reported that **456 uncovered asserts already carry an unlabelled comment above them**, and named the remedy as *label-seating rather than reason-writing* -- cheap work, one pass, gap 468 to roughly 12. Keaton gave the word. **Reading the comments before stamping them showed 361 of 377 are not reasons at all.** They are test-case narration inside proof functions: *"VFS may read system paths, not write them"* above `assert(!table.allows("vfs", "/etc", right_read))`; *"The three rye paths in held order"* above `assert(resp.tokens_out == 3)`; *"The dark sheet lowers to Bark paper"* above a colour comparison. Seating `// invariant:` on those would have written **361 false invariants into the tree's most-cited room**, each one telling a later reader that a test's description is a contract's reason. *What caught it:* sampling the data before acting on the instruction, twice -- the first twelve looked wrong, and a second sample spread differently confirmed it rather than explaining it away. *What it taught:* **a count of a SHAPE is not a count of a MEANING.** The meter counted comment lines standing above asserts, which is a shape it can see; whether a comment is *about* the assert beneath it is a meaning only a reader holds. Every earlier correction in this arc moved a number that was wrong; this one would have moved a number that was right and made the tree wrong doing it. **The cheapest-looking sweep was the only one that could have done harm.** *The root, measured:* **361 of the 377 sit inside a `pub fn` that a proof entry in the same file calls** -- `caravan/regions.rye` exports `check_declared_access`, `check_reads`, `check_refusals` for a witness to call, and its own `run_self_test` calls them too. The reachability bin cannot reach them because of the **`pub` guard added at REDS %211**, which exists because a selftest calling the real API is what a selftest is for. That guard was right for `image/photos.rye` and is wrong here, and the two cases differ by something no in-file reading can see: **`crop` is called from other modules, `check_reads` is called from nowhere but its own proof.** *Not fixed, deliberately:* a cross-file reachability pass is the honest discriminator and it is a real change to a meter that has now been corrected nine times, several of which needed a second fix. It waits for a round of its own rather than a fast patch at the end of a long one. **Nothing was stamped.** *Landed instead:* the 16 genuine ones carry `// seam:`, TAME's own word for the inherited-std boundary, above asserts that guard exactly that boundary -- *bufPrint returns usize; it never exceeds the slice it wrote into*. The label pattern reads `seam` now, and the tree stands at **97%**, gap **453**. CLOSED.

**REDS %214 (`20260824.235331`) -- `rye build` could not find its own standard library on macOS.** *What went wrong:* `resolve_rye_lib` in `rye/src/main.rye` read `/proc/self/exe` and nothing else. macOS and the BSDs publish no such path, so the read returned `FileNotFound` and the binary printed *could not locate Rye's standard library ... set RYE_LIB to point at rye/lib*. This was the **first build a newcomer ever runs** -- fetch the toolchain, bootstrap `rye`, build something -- so the tree's own onboarding path failed on a first-class developer machine with a hint instead of a working default. The function's own comment said *"for hosts without `/proc`"* beside the environment override, which means the gap was seen at authoring time and answered with a manual step rather than a second reading. *What caught it:* Keaton ran it on his macOS clone and pasted the failure. No guard covered this, and none could have -- every witness in this tree runs on the Linux pier where `/proc` is always there, so the reading that fails is the one no local run exercises. *What it taught:* **a platform check that only the failing platform can run is not a check.** The repair is a **second reading** rather than a wider first one: `argv[0]`, the path the shell actually invoked, which every host provides. `rye/bin/rye`, `./rye/bin/rye`, and an absolute path all carry a separator and resolve the same way; a bare `rye` found on PATH carries none and still refuses rather than guessing at a lib. *Proven by doing:* [`../tools/fixtures/rye_lib_resolve_control.sh`](../../tools/fixtures/rye_lib_resolve_control.sh) blinds the `/proc` probe in a copy of the source, builds that copy, and runs it from a pen where only `argv[0]` can answer -- three legs green, the third being that a bare name still refuses. It cannot prove macOS behaves as simulated, and says so; that is the honest limit of a Linux pier. CLOSED.
