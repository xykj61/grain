**BAKERY -- ASKING WHETHER A BINARY IS CURRENT NO LONGER COSTS A BUILD.**
`rye key <file.rye> -femit-bin=<path>` prints `verdict=hit|miss|unkeyable` with both keys, exits 0
on a hit and 1 on anything meaning build, and writes nothing. The card's own ask, answered.
**THE ONE STRUCTURAL CLAIM:** it is the SAME computation, never a second one that agrees today.
`bridge_rye_tree` took a `stage` bool at the exact seam where reading becomes writing -- every line
above it reads and feeds the hasher, every line below writes -- and `bridge_to_zig` took a
`key_only` bool that skips the lock, the stamp delete, and the spawn. **Proven rather than claimed:**
the key asked BEFORE a build exists equals the key that build then writes, character for character.
**WHAT A MUTATION TAUGHT, and the reason to run them:** the first control proved "asking writes
nothing" by listing the pen before and after, and a planted staging walk stood GREEN through all
legs -- the defers delete each shadow, so staging and tidying up is indistinguishable from never
staging. The claim the listing proved was the weaker `leaves nothing behind`. That gap is not
cosmetic: a shadow is written BESIDE THE SOURCE in the shared namespace `%734` booked, and a reading
holding no lock would delete a concurrent build's inputs mid-compile. Leg 2b asks a READ-ONLY tree,
where a reading that writes cannot succeed at all; leg 17 plants a held lock. **40 legs, four
mutations bitten.** `%746`'s rebuild is now one cheap question rather than a full build.
