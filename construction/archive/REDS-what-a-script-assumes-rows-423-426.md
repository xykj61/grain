arms the public seed lived in a file the seed's own clone would not carry. An index counted the
interpreter that ran a witness as one of the witness's own readings. A control leg passed on the
tree that wrote it and nowhere else. A publisher named a branch its host had already chosen
differently. In each, the code was right about everything it looked at, and wrong about the one
thing it never looked at -- and in each, the ground varies by host, by clone, or by config, so
the assumption held perfectly right up until it did not.

The rows stand here exactly as they were written. A closed row leaves the living pin so the pin
holds what is still open; nothing about the row itself changes in the move.

The script is **untracked at the root by design** (`.gitignore` blanket-ignores `/*`), so a clone is born without it, and the Dallas pier was. `tools/fixtures/c/commit_message_guard_scan.sh` greps that script for one line and read **`SEED_PUBLISHER_ARMS 0`**, whose own refusal says it plainly: *a fresh seed/.git would publish unguarded.* The guard has sat red behind custody gate `%1` since the pier was born, and the gate field made that red look parked rather than repairable. *What caught it:* Keaton asking for a seed push, which made the projection real work rather than a horizon, and the projection made the missing publisher visible where a rostered red had been reading as a gate. *What it taught:* **a gate is a claim about why a red cannot move, and a claim like that goes stale silently.** `%374` seated the gate field so a red parked at a maintainer's decision would stop costing the receipt; the risk it carries is the mirror image, which arrived here first -- a red that was **not** a custody decision at all, only a missing file, wearing a gate's clothes and drawing no attention for six days. The field is honest and the claim behind it needs re-reading, which nothing does automatically. *Repaired (`20260905.124031`):* the publisher is reconstructed from the rule and the guard's own greps, which is exactly what `.claude/rules/git-signing.md` says to do when a clone lacks it -- second time, after `20260827`. It projects, proves, arms and commits, and **its bare invocation cannot publish**: the force-push updates two public repositories irreversibly, the card says an autonomous agent stops at that gate and never crosses, so `--push` is a separate word typed at the moment it is meant. Proven end to end twice: `SOW_OK copied=7472 scrubbed=1215 withheld=135`, `IDENT_CLEAN`, `NO_PERSONAL`, `SOW_WITNESS_GREEN`, one parentless commit of 7,706 files authored `grain-ww` and unsigned, then a stop. **And the gate field came off in the same lap**, which is the half worth writing down: a gate standing over a green guard would excuse the NEXT red, and a future `SEED_PUBLISHER_ARMS 0` -- the publisher deleted again, or its one line edited away -- must red rather than read as parked. `commit_message_guard` **GREEN**; gated guards 4 -> 3. **CLOSED.**

**REDS %424 (`20260905.124857`) -- the library index counted the interpreter a witness runs under as proof of the room it belongs to.** *What went wrong:* `docs-geode/libraries/README.md`, the generated index a newcomer meets, published **1,770** witnesses for `rishi/` and **1,313** for `rye/` against a tree holding **1,801** witnesses in total -- two rows naming more proofs than exist, one of them for a room of **two** Rye modules. The cause is one function: `witness_count()` in `tools/fixtures/g/geode_libraries_scan.sh` ran `xargs -0 grep -lIE "(^|[^A-Za-z0-9_])$1/"` over every witness, and **every Rishi witness opens `rishi/bin/rishi` while every Rye witness builds with `rye/bin/rye`**. Measured on metal: of the 1,770 rows credited to `rishi`, **1,764** carried no other mention of it; of `rye`'s 1,313, **1,224**. The honest counts are **6** and **89**. *What caught it:* reading the page on a fire rota lap and setting its two largest numbers against the tree's own witness total -- 1,770 of 1,801 credited to a two-module room is a number that cannot be true. Nothing measured it, and the control said so in its own words: *"WHAT IS NOT PROVEN. Whether the witness count is right."* The module count beside it had four pen cases proving it both ways; the witness count had none, and an accurate disclaimer is not a guard. *What it taught, twice:* **first, a repair aimed at one direction of a wrong number should be measured in both.** This is `%169` overshooting into its own mirror image -- the filename glob read a confident wrong **zero** for `image` and `lotus`, and the reference test that replaced it read a confident wrong **1,770**. The second is harder to see, because a large number reads as health where a zero reads as a fault. **Second, and sharper: the instrument that found it was itself wrong, in the direction that books a false red.** `grep` inside this harness's Bash tool is a shell function shimming to **ugrep 7.8.4**, while every script, scan, and witness in this tree runs `/run/current-system/sw/bin/grep`, **GNU grep 3.12**. Under ugrep the ERE `(^|[^A-Za-z0-9_])` -- the spelling `%240` seated *for portability*, since `\b` is absent from BSD grep -- anchors the whole pattern to line start, so ` rye/bin/rye` does not match at all. Probing per file through the shim read `rye/` at **27** where the real instrument reads **1,313**; probing through `xargs` read 1,313, because `xargs` execs the real binary and escapes the function. Two readings from what looked like one tool, and the shimmed one was three minutes from being written into this ledger as a defect of the tree. **A measurement an agent takes is taken with the harness's tools, not the tree's** -- name the binary when the number matters. Three other tracked scans carry that boundary spelling (`declared_ceiling`, `invariant_coverage`, `shell_dialect`, four occurrences), each correct under GNU grep and each worth reading on the lap that next opens it. *Repaired (`20260905.124857`):* `witness_count` no longer greps per room. `tally_witnesses` reads every witness **once**, removes `rishi/bin` and `rye/bin` from each line with two `gsub` calls, then scans the line for `<word>/` tokens and looks each up in a hash of room names -- one fixed pattern per line rather than thirty-eight dynamic ones, with the hyphen-boundary rule kept by testing each suffix that begins after a `-`. The first draft did keep the per-room dynamic regex and measured **33.9s** against the elder's **2.3s**; the token scan reaches the same answer, byte for byte, in **1.9s** -- faster than the shape it replaced, so the correctness repair costs nothing. Thirty-six of the thirty-eight rooms are unmoved, which is what bounds the cut. Six new pen cases in `tools/fixtures/g/geode_libraries_control.sh` prove the rule both ways -- the interpreter and the compiler each counting zero, a genuine path into each room counting one, an ordinary room unaffected, and the hyphen boundary surviving the change of mechanism -- and pointed at the elder scan the control refuses on exactly those two, leaving the other eight free. `tools/g/geode_libraries_witness.rish` asserts all ten and is GREEN on metal in 2.5s. *What this does not reach:* whether a witness that names a room proves anything **about** it. This counts references honestly; it does not read them. **CLOSED.**

Not a guard -- a peer, doing the thing the fleet exists to do. *What it taught:* **a control leg whose safety depends on the checkout's basename is safe on one tree and dangerous on another**, and the tree that wrote it is exactly the tree that cannot feel it. Every leg in that file had been proven, on one pier, by the hand that wrote it -- and the one property it needed was that it be provable **anywhere**. **REDS %426 (`20260905.143057`) -- the publisher named a branch the host chose, and both doors serve a different one.** *What went wrong:* the reconstructed `publish-seed.sh` called `git init -q seed` and then pushed `main`. `git init` takes its default branch from the host's configuration, and on this pier that is **`master`** -- so the fresh seed repository had exactly one branch, named `master`, and the push asked for a branch that did not exist. The dry run answered `error: src refspec main does not match any`, and both doors refused. *What caught it:* running the dry run first. That step is in the script's own printed instructions and in the handoff written an hour earlier, and it existed precisely because the act behind it is irreversible -- so the one habit adopted for safety is the habit that caught a fault safety had nothing to do with. *What it taught:* **an unnamed default is a decision the host makes for you, silently, and a different host makes differently.** `git init` has taken its branch name from configuration since 2.28, so the same script produces `master` here and `main` on a machine whose global config says so -- and the reconstruction inherited that variance without naming it, in a script whose entire design principle is *anything a wipe would disarm is armed in the script*. The branch name is exactly such a thing and it was the one line that trusted the environment. *Repaired (`20260905.143057`):* the init names the branch -- `git init -q -b main`, with a `symbolic-ref` fallback for a git too old for the flag -- **and every push spells `HEAD:main`**, so the remote is correct whatever the local branch is called. Belt and brace on purpose: the second half alone would have worked, and it leaves a repository whose branch name still disagreed with both doors. Proven by dry run against both remotes before the real push, then published: `grain-os/grain` and `grain-ww/grain` both stand at `5a54c2f2c81e`, one parentless commit of **7,706 files**, author `grain-ww`, unsigned by design, projected `SOW_OK copied=7472 scrubbed=1215 withheld=135` and proven `IDENT_CLEAN` / `NO_PERSONAL` / `SOW_WITNESS_GREEN`, with an independent sweep for eight name and key patterns reading zero on the exact staged bytes. **CLOSED.**
