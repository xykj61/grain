**REDS %173 (`20260823.171000`) -- a machine with no screen was reading as a broken tree.** *What went wrong:* two rungs from the `%171` random draw were both filed as module drift, and only one was. `pool_isolation_witness` genuinely called `table.add_child` after `linengrow/capabilities.rye` renamed it `add_dependent`, unbuildable for five weeks and repaired in two sites. `pond_ring_lantern_witness` builds a Wayland terminal, and this pier carries no `libwayland-client` or `libxkbcommon` on any path the linker searches -- so the rung reported a **fact about the machine** in the voice of a defect. *What caught it:* running the second repair and reading the build's own error instead of trusting the row that filed it, which is `docs-implementation-sync`'s rule applied to a ledger row rather than to a document. *The shape underneath:* `pond_build_drawn_terminal.sh` printed **"assuming host link seams on metal"** at prepare and handed that guess to a compile that discovered the truth at link time. A guess made in one phase and paid for in another is the same shape `%172` retired hours earlier, where a scan guessed which rooms are generated instead of asking git. *What it taught:* **a witness owes its reader the difference between a broken tree and a machine that was never asked to run this**, and the place to draw that line is the phase where the requirement is known rather than the phase where it is discovered. *Repaired:* `tools/fixtures/display_seam_probe.sh` asks the paths the **linker** searches -- deliberately not the whole filesystem, since `/nix/store` here holds `libwayland-client.so.0.25.0` and Zig still refused, so a probe that found it would promise a link that cannot happen. It exits 3, and only 3, naming the absent seam. **Six callers now share it**, and `setu_desk_hold_wayland_witness` gates only its `look` half so its host-free selftest still runs and says so. `rt` stays outside the check because it lives inside glibc. *Proven both ways* by `tools/fixtures/pond_display_gate_control.sh` over eight cases -- and the open side is the one that matters, since a gate proven only shut cannot be told from a bypass: with stub seams on `LIBRARY_PATH` the build proceeds into compile and its ordinary failure exits **non-3**. *One more red rode along, caught by the pen:* the first guarded call was an unguarded command substitution under `set -e`, so the script died at the assignment and printed **no** explanation, leaving only the exit code -- the gate silently doing the exact thing the gate exists to prevent.
