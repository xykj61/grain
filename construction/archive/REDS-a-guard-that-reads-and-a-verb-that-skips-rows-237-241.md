Five rows about the same thing seen five ways: what a guard actually reads, and what runs it. A
default that contradicted its own documentation across fourteen callers; a meter that inferred a
choir's reach and overstated it by 111; a lap that starved the roster it stood on; a page that
shipped thirty-eight zeros because its guard rendered through the function it checked; and a verb
that makes commits without ever firing the wall placed at the other one.

**REDS %237 (`20260825.235254`) -- fourteen guards read a folded ledger as if it were whole, and the fold-aware repair had fixed the other function.** *What went wrong:* `tools/fixtures/reds_ledger_monotone_scan.sh` defaults to `construction/REDS.md` alone when called with no arguments. Since the first fold that file holds a **suffix** of the spine -- 3 flat rows against 232 -- so every bare caller read `expected row 1, found 230` and answered `verdict=not_monotone` over a ledger that is perfectly whole. **Fourteen** `tools/fixtures/equinox_*_scan.sh` files call it bare. The scan's own header has said *"pass every file that holds rows"* since `20260811.143500`, and its witness passes the archives and the pin explicitly, so only the default was ever wrong. *What caught it:* the leaf sing, through `e113_fascia_health` -- one of the two limbs holding `instrument_suite_scan.sh` at 8 of 10, which in turn held e132, e134, and e135. *What it taught:* **a default that contradicts its own documentation is a trap rather than a convenience.** REDS %231 repaired exactly this shape a lap earlier for `reds_row_present` -- 19 sites, one shared fixture -- and the sibling function beside it kept the fault, because the repair was aimed at the call sites it had found rather than at the class. **A lantern that fires twice becomes a loom:** the fix belongs in the tool, where one edit repairs fourteen callers and every caller yet to be written. *Repaired:* the no-argument default now unions `construction/archive/REDS-*rows-*.md` with the living pin, an unmatched glob leaves a never-folded tree read exactly as before, and an explicit argument list still overrides -- which is what the witness's planted single-file pens depend on. Bare, the scan read `rows=232 gaps_or_dupes=0 verdict=ok` at the moment of repair, before this lap's own rows were booked.

**REDS %238 (`20260825.235254`) -- a meter that infers a choir's reach overstates it by 111.** *What went wrong:* `tools/fixtures/witness_reach_scan.sh` learns what a roster row reaches by reading source: a Rishi choir's `let ... = [ ... ]` literals, and calls in command position. The first repair taught the meter to expand the choir's glob -- and that glob selects **144** equinox witnesses where the choir sings the **33** that chain nobody, so the ceiling would have fallen by 242 for work that carried 47. *What caught it:* reading the number before trusting it. `unreached` fell 1,201 -> 959 on a change that rostered one guard, which is too large a fall for one row and was the tell. *What it taught:* **a number that says more than it measured is worse than a number that admits a blind spot** -- and the honest way to learn what a discovering choir sings is to ask it. A choir now declares a `# reach-list:` enumerator on one line; the meter runs it, takes the printed paths, and a choir that changes what it sings changes what it reports in the same edit, because the enumerator and the sing read one list. *Repaired:* `season_leaf_choir_scan.sh --list` prints exactly the set the sing runs and runs none of it; the meter asks rather than infers; `unreached` reads **1,154**, a fall of 47 -- the 33 sung leaves plus the 14 those leaves reach -- and the ceiling moved to match.

**REDS %239 (`20260825.235254`) -- the lap starved the roster it was standing on, and the roster reported the starvation as four tree reds.** *What went wrong:* a cold `standing_equipment_run.sh` was 52 guards into its 64 when this lap copied the whole repository into `${TMPDIR}` to test a repair on a throwaway tree. The run card read `guards_red=4` and `run_verdict=guard_red` with `tree_moved=no`, which is exactly what four genuine tree reds look like. *What caught it:* re-running all four by hand on the same unmoved tree after clearing the pen; all four read GREEN, and the tree digest `048537bc345a` was identical at open and close. *What it taught:* **the card says hold still while the roster runs, and a pen is motion.** The runner already refuses a tree that moved under it; it has no reading for a *machine* that moved under it, and a starved guard is indistinguishable from a broken one in its output. It is a machine fact rather than a tree red -- the class the loop prompt names -- yet it arrived wearing a tree red's clothes, so it is booked here rather than waved off. A pen the size of the repository is never the cheap way to test a string replacement: the replacements in this lap each assert their own match count and refuse rather than misfire, which is the check that was actually wanted. *Repaired:* the pen removed, all four re-proven GREEN individually on metal, and the authoritative reading for this round is the **hot** roster over the tree the commit ships, which is what REDS %174 seated the hot pass for.

**REDS %240 (`20260826.001630`) -- a generated page shipped thirty-eight zeros to the anointed remote, and its own guard agreed with it.** *What went wrong:* `tools/fixtures/geode_libraries_scan.sh` counts a room's witnesses through `xargs -a FILE -d '\n' grep -l`. BSD xargs carries neither `-a` nor `-d`, so on the macOS bench that pipeline yields nothing, `wc -l` answers 0, and all thirty-eight rooms read zero witnesses. `docs-geode/libraries/README.md` was regenerated and pushed to `xykj61` in that state on `20260825`, and `tools/g/geode_libraries_witness.rish` stood GREEN on that bench while it happened, because the guard renders through the very function it checks. *What caught it:* a rebase. This pier pulled the anointed remote at `20260826.000301`, met a content conflict in that page, and read both sides side by side -- one carrying real counts, one carrying a column of zeros. *What it taught:* **a guard that renders through the function it checks proves the two agree, never that either is right.** This is the third time the class has cost this tree a number: REDS %169 was a glob answering zero for the same thirty-eight rooms, and REDS %226 was two guards speaking one host's awk dialect -- the same fault in a different tool. A lantern that fires twice becomes a loom. *Repaired:* the counting function reads `tr '\n' '\0' | xargs -0`, which both dialects carry, and spells the word boundary as an ERE alternation rather than `\b`, which BSD grep does not promise. The page renders byte-identical on this pier and every witness count is unchanged, so the repair is proven to move nothing but portability. `tools/fixtures/shell_dialect_scan.sh` and `tools/s/shell_dialect_witness.rish` seat the class: **12 gated sites across 7 files** held under a ceiling that only falls, four further GNU-only families counted and printed without gating, and the mechanism reproduced on metal -- a two-line `xargs` refusing `-a` and `-d` as BSD does, under which the elder form answers 0 and the portable form answers 1.

**REDS %241 (`20260826.001630`) -- `git rebase --continue` makes a commit, and the wall that keeps generated pages fresh never fires.** *What went wrong:* `tools/hooks/pre-commit` regenerates `README.md`'s metrics block and `docs-geode/libraries/README.md`, and it fires at `git commit`. A commit created by `git rebase --continue` runs no `pre-commit` hook at all. This round rebased onto the anointed remote, whose three commits had added two `.rye` modules, and the commit that came out of the rebase carried `1898` Rye modules where the tree holds `1900` -- a number this pier had itself been right about one commit earlier. *What caught it:* rendering the page and reading the diff rather than trusting the earlier render. The earlier render was the trap: `tools/r/readme_metrics.rish` and `tools/g/geode_libraries.rish` both print to stdout and write only when handed `write`, so a run that prints the right number and touches nothing reads exactly like a run that fixed the page. *What it taught:* **a wall placed at one verb does not cover a second verb that does the same work.** The twice-pulled sync rota was seated `20260825.210819`, one day before this round; every round now opens by rebasing, so the path around this wall went from rare to routine in a day, and no row named it. *Repaired:* both pages written with `write` and folded into the same commit by a single amend, so no commit in this tree's history carries the regressed number. The roster's `readme_metrics` and `geode_libraries` guards read the live pages rather than the hook, and would have refused the next lap; the gap this row names is the window between a rebase and the next roster run, and the rota's own rule -- re-verify a package after it moves -- is what closes it.
