**REDS %216 (`20260825.030641`) -- the library index counted a build cache as tree content.** *What went wrong:* `tools/fixtures/geode_libraries_scan.sh` counted each room's modules with `find "$room" -maxdepth 2 -name '*.rye' -type f`, which asks the filesystem rather than the repository. The `glow` room keeps a `.cache` directory of **108** generated `.rye` files that `.gitignore:209` excludes, so the figure the page published was the **130** the tree keeps plus whatever the last Glow compile had left behind. The page on the shelf read **235**, a fresh render read **238**, and no commit in between had added a module. *What caught it:* the cold roster at the head of this lap -- `geode_libraries red`, and `generated_page_freshness red` beside it for the same stale page. Nothing else could have: `tools/hooks/pre-commit` regenerates the page when a **staged** change adds or deletes a `.rye`, and an ignored file is never staged, so the hook is structurally blind to this drift rather than merely unlucky. *What it taught:* **a number derived from the filesystem moves when somebody builds.** This page exists to be trusted rather than checked -- that is what an index is for -- and its largest room's figure was a function of build state. Ask the system the question you actually mean: `git check-ignore` answers *does this tree keep this file*, where `find` answers only *is this file here*. **The tree already held the right method** -- `tools/fixtures/readme_metrics_scan.sh` counts the root page's modules with `git ls-files '*.rye'` and has been right the whole time, so this was one meter disagreeing with another about what a module is rather than a question nobody had answered. *Repaired:* `module_count()` pipes the same `find` through `git check-ignore --stdin --non-matching --verbose` and counts the `::` lines it prints for paths git does **not** ignore. `glow` reads **130**; the other 37 rooms are unchanged, measured rather than assumed. A sweep of every room found exactly one other with ignored `.rye` on disk -- `seed/`, the public projection, which the census already excludes by name. Proven both ways on real git repositories in a throwaway pen by the new [`../../tools/fixtures/geode_libraries_control.sh`](../../tools/fixtures/geode_libraries_control.sh): four readings -- an ignored module stays out, the same files count when nothing ignores them, a module written this minute counts, and a room holding only ignored modules leaves the index. Pointed at a copy carrying the old rule it **refuses three of the four and passes exactly the one that should pass**, so the control is proven to bite rather than assumed to. Wired into `tools/g/geode_libraries_witness.rish`, GREEN on metal. CLOSED.

**REDS %217 (`20260825.030641`) -- a sweep edited 110 pages by path, and two of those paths were mirrors.** *What went wrong:* commit `e9582afd36` gave every room README a three-line `Where this sits` block naming the root README, the first-hour tutorial, and `SOURCE.md`. Two of the 110 -- `spellbook/README.md` and `biochemistry/README.md` -- are **mirrors** declared in `context/document-mirrors.brix`, whose own law reads *edit the canonical, run the write, commit both -- never edit a mirror by hand*. Both drifted from their canonicals the moment the sweep touched them. The same three lines carried `docs/README.md` from 39 lines to **42** against the **`<=40`** its own header declares. *What caught it:* the cold roster, `document_mirror red` and `declared_ceiling red`, standing four commits after the sweep landed. *What it taught:* **a sweep that selects by path has to ask what each path is.** To a `for f in */README.md` loop a mirror and a page carrying a declared ceiling look exactly like an ordinary README, and both were treated as one. The tree already holds the answer for each -- a Brix descriptor naming every mirror, and a `**Ceiling:**` header on every bounded page -- so both questions were askable and neither was asked. *Repaired:* the block was written into `context/SPELLBOOK.md` and `context/CHEMICAL_FORMULAS.md` at the positions the sweep had used, and both mirrors regenerated with `sh tools/fixtures/document_mirror_scan.sh write`. The scan reads `links_unresolved_from_a_home=0`, so the block's three relative links are **proven** to resolve from both homes rather than assumed to (REDS %176's reading, doing its job). On `docs/README.md` the block was set on one line, matching that page's own header style, and the page holds the 40 it declares with no content lost. Both guards GREEN on metal. CLOSED.
