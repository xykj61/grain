# REDS -- rows %276 to %280, folded from the living pin

**Folded:** `20260826.214701` -- **Status:** Archived, complete, never edited
**Living pin:** [`../REDS.md`](../REDS.md) -- **Law:** [`.claude/rules/reds-first.md`](../../.claude/rules/reds-first.md)

*Five rows about instruments: a meter pointed at a class of artifact it was never shaped for, a
guard reading one file of a growing family, a character class that belongs to one awk, a lock that
belongs to one kernel, and a card advertising commits a rewrite had already removed.*

Read together they say one thing twice. **A meter is a claim about the world, and every claim it
makes rests on something it never checks** -- the dialect of the shell it runs in, the class of
artifact it was handed, the roster it was born knowing, the object store its hashes point into.
Three of these five fired on a second host on one afternoon, and the sharpest pair are opposites:
`%277` read *less* than the tree held and called it green, while `%278` read *everything* and would
have called a clean tree dirty. Both are the same fault -- a reading nobody proved against a known
answer -- and the repair in both cases was an exact number the meter could be held to.

The rows stand here exactly as they were written. A closed row leaves the living pin so the pin
stays the length a reader will actually read; the lesson travels forward in the guards these rounds
built, and the row itself stays one click away.

**REDS %276 (`20260826.180052`) -- the report card read a program's code as its prose, and threw away the comments.** *What went wrong:* `tools/fixtures/q/qa_report_card.sh` grades any path it is handed, and both counted readings -- Register and Reach -- skipped every line whose first non-whitespace is `#`. That is exactly right for Markdown, where `#` opens a heading. In a shell, Rishi, or Rye source `#` and `//` open the **only** prose the file has, so the rule inverted: it discarded the comment head and graded the code. Measured on `tools/fixtures/r/reds_fold.sh`, whose head is plain English written for a first reader, Reach read 209 "words" of `[ -f "$PIN" ] || fail ...` and returned a **reading grade of 86 against a ceiling of 9**, flooring Reach at **0** and the card at **C**. The prose was fine and the instrument was reading the wrong half of the file. *What caught it:* grading the loom built this same lap, under the standing habit of grading what you touch -- two new tools came back C and B with `register=100`, a combination that cannot happen to real prose, since a page that leads perfectly with what is does not also read at postgraduate length. *What it taught:* **a meter pointed at a class of artifact it was never shaped for reports a fault in the artifact.** This is the second time in one day: `docs/COMPASS.md` read **C** at the `door` setting hours earlier because a pointer card's cross-references met a prose budget, and read **A** at `meter` where they belong. Both readings were the setting rather than the page, and a card that manufactures a fault invites a repair that makes the artifact worse -- the same shape the index-declaration comment in this file already names. *Repaired:* the card classifies the artifact once, ahead of both readings, and feeds a program its comment lines with the marker stripped and the shebang dropped; Markdown is untouched and its readings are byte-identical, checked on three pages across all three settings. The same loom's files now read grade **8** and **9** against the ceiling of 9. The sibling `prose_register_scan.sh` needed nothing: its roster is `*.md` plus four named root documents, so the markdown rule is correct in its own domain and the fault lived only where the card widened the input past what the rule was written for. CLOSED.

**REDS %277 (`20260826.182619`) -- the guard written for the lone apostrophe read one launcher while four existed.** *What went wrong:* `tools/fixtures/l/loop_prompt_parse_scan.sh` was written after REDS %232, where three lone apostrophes in a single-quoted prompt flipped every later character out of quoting and both printed launch lines died on the next parenthesis. It reads the recipe by running **`tools/l/launch-claude-chapter.rish`, named once, by hand**. On `20260826` the tree grew three more printers, one per running star, and none was measured -- so the guard had been blind to three of four launchers from the lap they landed. *What caught it:* writing `(Keaton's word 20260826)` into the Dream launcher's prompt this lap, the very fault %232 booked. The printed line stopped parsing and the scan still answered `lines_that_do_not_parse=0`; a hand comparing the rendered line under `sh -n` saw it, then planted the apostrophe deliberately and watched the scan read zero twice. *What it taught:* **a roster discovered from the tree grows when the tree does; a roster typed by hand grows when somebody remembers.** This is REDS %231's shape in a second room -- there, nineteen guards kept asking a page the fold had left; here, one guard kept reading the one file it was born knowing. The blast radius was the sharper half: the unmeasured launcher is the one the pier runs unattended overnight, so the first sign would have been a loop that printed a syntax error every twenty seconds until a hand looked. *Repaired:* the scan discovers `tools/l/launch-*-chapter.rish` and reads every one, printing `launcher_read=` per tool so a reader sees the roster it actually measured; runnable lines went **6 to 7**. **REDS %278 (`20260826.211500`) -- the ASCII meter's own character class read every character as non-ASCII on the second pier.** *What went wrong:* `tools/fixtures/r/rye_comment_ascii_scan.sh` and `tools/fixtures/s/shell_comment_ascii_scan.sh` each count a comment's non-ASCII characters with `awk` and the regex `substr(s, i, 1) ~ /[^\x00-\x7F]/`. The `\x` hex escape is a **GNU awk extension**. The BWK awk macOS ships parses `\x00` as literal characters, so the bracket range names none of the bytes it was written for, the negated class matches every character alive, and the meter counts a whole comment line as non-ASCII. Measured on the macOS bench `20260826.211500`: the living Rye reading came back **16,131,707 characters across 1,900 files against a ceiling of 4,338** -- `under_ceiling=no`, a guard that would have refused the tree on the next lap that ran it. *What caught it:* `tools/fixtures/r/rye_comment_ascii_control.sh`, which plants four prose files carrying one character each and asserts the total is exactly four. It read `chars=97` -- the character count of the four planted lines -- and refused by name. **The sibling shell control stayed green through the same fault**, because it asserts only whether each planted line *was* counted, and a class that matches everything answers yes to every one of those. *What it taught:* **a control that asks whether a reading fired cannot see a reading that fires too often.** An exact total is what separates the two, and only one of the two meters had one. The dialect half is the BSD family's sixth firing (`%240`, `%249`, `%250`, `%270`, `%277`), and this instance is the inverted one: the earlier five read *nothing* and called it green, where this one reads *everything* and would call a clean tree dirty. *Repaired:* both scans spell the range in POSIX octal, `[^\001-\177]`, which every awk parses identically -- the same move `tools/fixtures/l/living_card_ascii_scan.sh` already made when it dropped `grep -P` for a C-locale byte range, cited beside the change so the two repairs read as one lesson. The proof is arithmetic rather than argument: the repaired macOS readings are **4,338 across 369 files** and **505 across 153 files**, character for character the numbers the Linux pier recorded on `20260825` for the same two meters. `ascii_comment` GREEN on metal, control total four, shell ceiling proven from both sides. CLOSED.

**REDS %279 (`20260826.212000`) -- the Glow build lock reached for a tool macOS does not ship, and forty-four witnesses refused.** *What went wrong:* `tools/g/glow_run_worker.sh` serializes its builds behind `exec 9>"$BUILD_LOCK"` and `flock -w "$BUILD_LOCK_WAIT" 9`. `flock(1)` is util-linux; macOS ships no such binary, so the line dies on `flock: command not found`, the `||` branch fires, and the worker prints `FAIL: glow build lock not acquired within 1800s` and exits 3 **without having waited at all**. Every witness that reaches this worker refuses on that bench: **44 tree-wide, 7 of them Caravan rungs**, so the Caravan choir could not go green on the macOS pier for a reason with nothing to do with Caravan. *What caught it:* the choir itself, run as the first gesture of the widened Sound lane's core-first law -- `caravan_suite` named `tools/ca/caravan_c4_exit_meanings_eq_witness.rish` RED, and running that rung alone printed the missing tool by name on the second line. *What it taught:* the lock's own comment already names the three false REDs a racing build bought, so the mechanism is right and only the **tool** was local. A dependency on a binary one pier lacks is the same seam as a flag one dialect lacks, and it is louder rather than quieter -- which is the honest good luck here, since a refusal that names its missing tool costs one reading where a silent zero costs a chapter. *Repaired:* `lock_acquire` and `lock_release` join `tools/fixtures/s/shell_portable.sh` as its sixth named dialect question, built on `mkdir`, which is atomic on every POSIX filesystem, with the same bounded wait that refuses by name. The one property a descriptor lock has for free -- release on process death -- is restored by writing the owner's pid inside the lock and letting a waiter that finds a dead owner reap it, so a killed build costs one retry rather than a bounded hang. The lock is renamed `.build.lock.d`, because the elder spelling left a zero-byte **file** at `.build.lock` and `mkdir` over a plain file fails forever: a new mechanism under a new name makes that residue irrelevant on every clone, with no special case to maintain. The blocked rung reads GREEN on metal, exact case and both neighbours. CLOSED.
