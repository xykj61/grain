**REDS %408 (`20260904.174748`) -- the mount that could only happen once it had already happened, so every jailed Claude met the onboarding it was meant to remember past.** *What went wrong:* `tools/ag/agent-jail.sh` mounts the host's `$HOME/.claude.json` into the jail **only when `loops/claude/dot-claude.json` already exists** -- and under `--private-home` that file is written by exactly one process, the jailed Claude, into a tmpfs the jail exit discards. The condition could therefore never come true on a fresh pier, and the failing direction is silent: a bind-mount whose source is absent is skipped, not refused. Claude Code keeps `hasCompletedOnboarding`, the chosen theme, and per-project trust in `~/.claude.json` -- a FILE beside `~/.claude/`, not inside it -- so the mount that DID land (`loops/claude` onto `~/.claude`, carrying `settings.json` with `{"theme":"dark"}`) delivered the preference and not the record that the question had been asked. Onboarding ran on every jailed launch, and its first screen is the theme picker, which previews a light scheme on the operator's dark terminal: *"some text is completely invisible."* *What caught it:* a maintainer reporting the display fault against **NixOS** and asking for a rebuild, and measuring the two candidate explanations instead of taking them. Inside the jail against outside, on metal `20260904`: `ai-jail` drops `TERMINFO_DIRS` and `LOCALE_ARCHIVE` from the environment, which reads exactly like the cause -- and both are harmless here, `infocmp tmux-256color` resolving through ncurses' compiled-in path and `printf 'e-acute + a CJK glyph' | wc -m` reading **2** inside and out. `TERM=tmux-256color` and `COLORTERM=truecolor` both survive, so the color depth is whole. What did not survive was one file: `[ -f ~/.claude.json ]` answers **ABSENT** in the jail and PRESENT on the host, 42 KB carrying `hasCompletedOnboarding: True`. The NixOS configuration is not at fault and no rebuild was needed. *What it taught:* **a conditional whose condition only the guarded process can satisfy is a branch that never runs.** The elder shape is visible one file over and reads as a courtesy: `tools/e/enclosure.conf.example` says *"Optional: copy host ~/.claude.json to $CLAUDE_STATE/dot-claude.json for quieter Claude starts"*, and `nixos-guide/20260808-041912_3-cli-agents-in-ai-jail.md` tabulates the same mount as `(optional seed)`. That is the sharper half: **a workaround written into the documentation is a red somebody already found.** The three sibling mounts in the same block take the opposite shape and are correct -- `CLAUDE_STATE`, `CURSOR_AGENT_STATE`, `CODEX_STATE` are each `mkdir -p`'d and then mounted unconditionally, and the codex one carries a comment explaining precisely why (*"hence a repo-local durable dir, so login is done once per pier rather than once per lap"*). The rule was written, argued, and applied to three of the four things it governs. *Repaired (`20260904.174748`):* the file is **seeded** rather than the mount skipped -- `printf '{}\n'` when absent, then mounted unconditionally, matching its three siblings.
