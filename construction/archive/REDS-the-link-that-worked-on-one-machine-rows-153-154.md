**REDS %153 (`20260823.002511`) -- twenty-six living references survived a breach behind an untracked symlink, and the guard that watches for broken links was reaching through it.** *What went wrong:* the `work-in-progress -> crux` breach of `20260815` repointed 902 references and missed twenty-six, spread across `MAP.md`, `context/LEXICON.md`, `context/TAME_GUIDANCE.md`, `docs/COMPASS.md`, `docs/CRYPTO.md`, `foundations/README.md`, `expanding-prompts/README.md`, four `gratitude/` pages, four module READMEs, two `context/specs/` pages, and a `manual/` tutorial. The broken-link duty of `tools/l/living_docs_lint.rish` tests a target with `[ -e ]`, and a symlink satisfies `-e`, so a reference that breaks in every fresh clone read as a reference that works -- and the lint's own roster named `work-in-progress/TASKS.md`, `ROADMAP.md`, and `ITINERARY.md`, so the guard was reaching *through* the artifact that blinded it. *What caught it:* the council rota. Reading `foundations/20260729-224828_reds-first-and-the-allocation.md` for row 2 surfaced a `**Ledger:**` header pointing at `../work-in-progress/REDS.md`; following it found a real file, and `git ls-files` found nothing. *What it taught:* **a filesystem answers whether a path is here on this machine, and a reader who clones asks whether it is in the repository.** Those are different questions, and only the second one is a promise. An untracked artifact at the root of a working tree can silence a whole class of guard without ever appearing in a diff.
