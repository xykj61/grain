**REDS %590 (`20260907.210632`) -- a named ceiling the operation could not serve, standing since the module's root commit.** *What went wrong:* `mantra/src/weave.rye` declared `max_weave_lines: u32 = 1 << 20` and checked it at the edge of every operation, which is TAME's bound rule kept exactly. The bound was honest about MEMORY and silent about TIME: `union_into` and both `annotate` folds walked the held side for every incoming line, so a merge cost |self| x |other| identity comparisons. Measured on this pier in ReleaseFast, two disjoint sides of equal size, one merge each: 16,384 a side **387ms**, 32,768 **1,522ms**, 65,536 **6,004ms**, 131,072 **24,310ms** -- rising **3.95x** then **4.05x** per doubling, the quadratic the shape predicts. At the largest merge the bound PERMITS, 524,288 a side for a union of exactly `max_weave_lines`, the walk **did not finish inside ten minutes** and was stopped there. So the module's declared ceiling named a merge no caller could ever wait for, and the ceiling had been in the file since the root commit with four rostered witnesses green over it the whole time. *What caught it:* the air rota row, whose test is to press each boundary and see whether the hand goes through -- then a harness that timed the merge at rising sizes rather than reasoning about it. Nothing in the tree was measuring this: a witness proves a law and says nothing about the seconds it took. **The module had written its own falsifier and nobody had run it** -- `merge`'s doc read *"a map earns its place when a measurement asks for one rather than before"*, which is exactly the right sentence and an inert one until somebody asks. *What it taught:* **a bound is two claims, and checking one of them is what makes the other invisible.** A ceiling that passes at the edge reads as a bounded operation, so the guard that would catch the second claim is the guard nobody writes. *Repaired (`20260907.210632`):* the folds search rather than walk -- the held side arrives in identity order and `std.sort.binarySearch` reads it, costing one sort plus |other| x log |self|. `LineId.order` is the one comparison in the file now, with `eq` and `less_than` both derived from it, so a sorted list and a search over that list cannot come to disagree. The bound did not move; the fold did. Re-measured at the same ceiling: **162ms** release, **1,376ms** checked, against a walk that ran past ten minutes -- and at 131,072 a side, 24,310ms -> **28ms**. All nine merge claims and all eleven annotate claims GREEN, both controls `ok`. **The control's own identity plant had to move with the law**: it narrowed `LineId.eq`, which the fold no longer calls, so it went on matching a real line and proving nothing -- caught because the control read `break_not_caught` rather than because anybody remembered. **CLOSED**
