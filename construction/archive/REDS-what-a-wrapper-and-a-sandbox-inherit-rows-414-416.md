**REDS %414 (`20260905.011715`) -- the sandbox and the agent both own `--verbose`, and the loop counted eight refusals as eight laps.** *What went wrong:* Claude Code refuses `--output-format stream-json` without `--verbose` -- *When using --print, --output-format=stream-json requires --verbose* -- and **ai-jail owns `-v, --verbose` itself**. Its guard fires on a known flag appearing after the command **even when `--` was passed**, which `tools/ag/agent-jail.sh` had been passing all along; the refusal reads *put sandbox flags before the command or use --*, advising the thing already done. So every jailed lap died instantly on `x flag --verbose after command would be passed to the child`. *And the loop had no way to tell that apart from a lap that ran and failed.* It counted each refusal, slept twenty seconds, and opened another -- eight of them in under a minute apiece across the pheromone and petrichor trees, against an eighteen-hour deadline of doing nothing at all. Keaton launched both ships and watched them spin. *What caught it:* Keaton running the two commands this seat had handed him and pasting what came back. Nothing in the tree could have caught it: the smoke test that passed hours earlier was `claude --effort max -p '...'` with no `--verbose`, and `loop_prompt_parse` proves the printed command PARSES rather than that the sandbox accepts it. *What it taught:* **a wrapper inherits its wrapper's namespace.** Every flag the agent needs must survive a second argv reader that has its own opinions about the same words, and `--` is a promise only when the program keeps it. The general form is worth more than the instance: any flag shared between a sandbox and the thing it sandboxes is a collision waiting for the lap that first needs it, and the collision surfaces at launch rather than at review. *Repaired (`20260905.011715`):* **the flags move inside.** `tools/l/fleet_lap.sh` runs within the enclosure, reads the baton and the seat stanza from the files directly, and spells every flag claude needs where only claude reads them; `agent-jail.sh` gains a `lap` command whose jail argv is `sh .../fleet_lap.sh <seat>` with **not one flag in it**. That also retires the giant `-p` argument riding through two shells, so the apostrophe that stranded Silence's loop on `20260829` has nowhere left to bite. *And the loop learned to stop:* **three consecutive laps dying in under ten seconds each break the loop** with a message naming the fault as an invocation failure rather than a lap that failed, and offering the by-hand command and `FLEET_BARE=1`. Proven in a throwaway pen against a launcher stubbed to exit 9. Verified live: a jailed lap now reaches Claude Code with `permissionMode: bypassPermissions` and streams. **CLOSED.**

**REDS %415 (`20260905.014249`) -- `claude login` writes to the host's home, and `--private-home` is exactly the thing that replaces it.** *What went wrong:* a jailed lap answered `Not logged in - Please run /login` on two trees, and typing `claude login` at the pier shell did not help, however many times it was run. The login writes to the **host's** `$HOME/.claude/.credentials.json`; the jail runs `--private-home`, whose whole purpose is to replace `$HOME` with a tmpfs, and only `loops/claude` is mounted in. So a login typed at the pier reaches **no tree at all, whichever directory it was typed in** -- `cd` changes the working directory and the credential follows `$HOME`. Measured: the host carried a 509-byte credential, `grain-incense/loops/claude` carried the same 509 bytes and worked, and `grain-pheromone` and `grain-petrichor` carried **none**. *What caught it:* Keaton running the launch, reading `Not logged in`, logging in, running it again, getting the same line, and saying so. The tree could not have caught it: incense had a credential from an earlier in-jail login and every guard that touches the launcher reads mounts and flags rather than whether the thing behind a mount is present. *What it taught:* **a sandbox that replaces a directory replaces everything anyone ever put there**, and an instruction that works outside it can fail inside it while looking identical from the keyboard. The sharper half is that the answer was already written in the same file: `agent-jail.sh` has seeded cursor's browser login from the host into the state room since it was written, with a comment saying private-home would otherwise drop it. **The same seam, the same fix, and only one of the two agents ever got it.** Kin to `%408`, where a mount for claude's own config was conditional on a file only the jailed claude could write -- twice now, the claude seam has been the one left half-done. *Repaired (`20260905.014249`):* the launcher seeds `loops/claude/.credentials.json` from the host when the tree has none, **and refreshes it when the host's is strictly newer**. The refresh clause is what cursor's line does not need and this one does: a token refreshes, the jailed agent writes its own back into the tree's room, so the tree's copy is newer after a working lap and is never clobbered -- while a fresh `claude login` on the pier makes the host's newer and every tree picks it up on its next launch. Whichever hand moved last wins, which is the only rule that stays true without a hand remembering it. **One login per pier rather than one per tree**, which matters at six ships and six expiry clocks. Proven in all three states with mode `0600` preserved: seeded when absent, left alone when the tree's is newer, refreshed when the host's is. *What this is not:* no credential leaves the machine, none is written anywhere tracked (`loops/` is gitignored and a closed stack), and nothing here creates, holds or moves a custody key -- it carries the maintainer's own already-granted session between two directories of his own pier, which the cursor line beside it has done all along. **CLOSED.**

**REDS %416 (`20260905.072118`) -- a ratchet passes on a low number, so a broken instrument and a healthy tree print the same green.** *What went wrong:* `tools/fixtures/u/unheard_guard_scan.sh` ran both of its awk passes as `... > FILE 2>/dev/null || true`, discarding awk's words and its exit. The two halves fail differently and only one would ever have been noticed. The first feeds a transitive closure, so an empty result stops the walk early, `unheard` reads **high**, and the ceiling reds -- loud, and wrong in the safe direction. The second feeds `choirs`, and **a ratchet passes on a low number**: an empty result reads `unheard_choirs=0` against a ceiling of 37, which is the greenest number on the page. A guard whose instrument had died would have reported the healthiest tree it ever measured. *What caught it:* Keaton's word to take the refusal reflex across every scan, after `%413` found the same shape twice in one repair. *What it taught, and it is the half worth carrying:* **an empty answer from a broken instrument is byte-identical to an empty answer from a clean tree, and every ratchet in this tree reads the second one as good news.** The direction matters: a gate at zero fails safe when its instrument dies, and a ceiling fails **unsafe**. This tree holds far more ceilings than gates. *And the measurement corrected the repair before it was written.* The broad signature -- any instrument with `|| true` -- matched **20 sites across 9 files, and exactly 2 were faults**. `grep` exits 1 when it finds nothing, so `grep p f > out || true` is right rather than a swallow; an awk carrying `END { exit !found }` is a **predicate** whose non-zero IS its answer. A meter with 90% false positives is a meter somebody turns off, so the reading is narrow by construction: an **output-producing** pass, redirected to a file, whose failure is discarded, not led by grep. *Repaired (`20260905.072118`):* both passes check their status and refuse with `instrument=failed`, `detail=name_pass_refused` or `detail=choir_pass_refused`, and awk's own last five lines. Proven by planting a syntactically broken program into the generated instrument and watching the refusal replace the count. *And made checkable:* `tools/fixtures/i/instrument_refusal_scan.sh` reads 676 tracked scans and gates the narrow shape at **zero from birth** rather than ratcheting down, since the known faults were repaired on the same lap. Its own first run found a **third** site, `counsel_census_scan.sh`, which turned out to be a **documented deliberate toleration** -- one dangling symlink among six thousand paths fails the `cat`, and the fifty-six megabytes that DID read are the census. That is a decision rather than a swallow, and **the difference between them is whether anyone wrote it down**, so a `# instrument-tolerated: <why>` comment exempts the next line and nothing else. Eleven behaviors proven in a throwaway git repository, every refusal shown from both sides and every welcome asserted as hard -- including that the meter **obeys the law it enforces** and refuses `instrument=failed` when it cannot reach the tree it was pointed at, which its first draft did not. **CLOSED** on `tools/i/instrument_refusal_witness.rish`, rostered at `tier lap` the lap it was written.
