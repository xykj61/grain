# Red and Error over Bug

**Canonical:** `context/GAUGE_STYLE.md` -- the *Words to reach for* table already reads "a red, an error, a fault | a bug, a gremlin, a glitch"; chosen as a standing rule `20260828.233241` on Keaton's word.

In living prose, rules, commit messages, and session logs, choose **red** or **error** over **bug**. The tree already has both words seated, each carrying more than the word it replaces:

| Form | Meaning |
|------|---------|
| **red** | something wrong -- it books the allocation and enters the ledger (`reds-first.md`, `construction/REDS.md`) |
| **error** | a code-level fault -- Rye's own named errors are errors, and a failure path speaks the language's word |
| **fault** | the neutral engineering word where neither ledger nor code is the register |

## What this does not retire

- **debug / debugging / debugger** are different words and stay -- the choice reaches the standalone word *bug* only.
- **Teacher quotes and vendored text** keep their words (a study of an upstream bug tracker names it plainly).
- **Dated testimony and commit history** keep every word they wrote.
- The REDS ledger already speaks this way -- the rule makes the wider habit match the ledger's own word.

## Accrete-never-break

Sweep living surfaces on touch; this rule governs what is written from here forward.
