## The two-season developer experience

The new developer experience takes the **design-over-build finishing edge** and makes it the calendar itself: two dedicated seasons, each whole, run in order.

- **Season One -- Design.** The full Acme developer UX is *designed* before a line of its infrastructure is built: the onboarding path, the first-hour witness, the interfaces and operations surface, the shape of "build your first module on Grain." Four equinoxes of design, each a journey, each a quest -- the itinerary pre-generated and deterministic, the way `tools/gen/season/itinerary.rish` already lays a season's rounds.
- **Season Two -- Development.** The designed experience is *built*, exactly to the plan the design season laid. Interfaces, infrastructure, operations -- the running whole a developer meets. No design invented mid-build; the design season already answered those questions, so the development season only ships.

Two seasons, one clean seam between them -- design settles, then development runs. This is the finishing edge written large: name the whole thing first, then build the one real thing all the way.
