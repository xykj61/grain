## The synthesized intention, as it stands now

The rule got written, and writing it raised a question the rule could answer only for itself:
**which kinds of tracked content does the guard roster actually read?** Keaton's next word turned
a repair into a program, and the program turned out to have one subject all the way down.

> audit the roster for blind classes

> **Every claim the tree makes about itself gets a meter, or gets named as a belief.**

## The one red this lap booked

`%172`. The roster's cold run answered **30 green, one red**, and the red was self-inflicted:
`phantom_path` named `linengrow/lib_session_root_nest_cue_jam.rye`, a symlink into `glow/.cache/`
that two witnesses **create while they run**, with `.gitignore` line 196 naming it. So running the
roster manufactured the artifact the next run reported.

The scan already carried two hand-written guesses about which rooms are generated -- `seed/`, and
any path with a dot-segment. It asks git now: `git check-ignore -q`, on the handful of literals that
resolve here and stand untracked. Ten control cases, three refusals bitten and seven honest readings
left free, including a pair that builds the exact shape twice -- once with the ignore rule and once
with it lifted -- so the exemption is proven to be the ignore rule rather than the path's name.
