# The two endurance runs

**Stamp:** `20260912.144043` (EDT, `-0400`)
**Language:** EN
**Style:** Gauge, Field setting
**Voice:** Kyri
**Status:** Living terminology design -- mixed room: command behavior is checkable; the endurance frame is design

The standing roster has two endurance-running exercises. Neither is a doorway that merely admits work. Each is a sustained run over the proof course, meant to reveal whether the tree can keep its form under duration, accumulated cost, and changing footing.

## Cold endurance run

The **cold endurance run** begins before a lap changes the tree. It takes the whole declared course without borrowing warmth from the lap's own staged work. Its purpose is baseline stamina: prove that the inherited tree, toolchain, guards, and environment can complete the standing course as received.

Cold does not mean hostile, and endurance does not excuse waste. The run remains bounded, measured, and subject to improvement. Content-keyed compilation may avoid rebuilding identical inputs while every proof still executes. A remembered verdict never substitutes for the run unless a separately seated law and a miss-side witness authorize it.

## Hot endurance run

The **hot endurance run** begins after the lap's work is staged. It exercises the moved tree and asks whether the proposed change can carry the same course while the new footing is present. Hot names the recent movement, not weaker rigor. It reads the staged closure, detects a tree that moves beneath it, and refuses a proposal whose proof no longer corresponds to its bytes.

The command flag `--hot` remains the compact machine interface. Human output, comments, assertions, and living design use the full name **hot endurance run**.

## The training law

- Endurance running is exercise, not punishment: measure cost and improve the course without skipping truth.
- The cold run establishes inherited stamina; the hot run proves the proposed stride.
- Rishi should fuse discovery, dependency closure, compilation, execution, and receipts so only what moved is rebuilt or reselected while every owed proof still runs.
- POSIX `.sh` remains the portable starting block. On touch, orchestration and typed decision logic climb into `.rish`; shell is not erased by a conversion campaign.
- Timing remains a pin. A faster run earns trust only when miss-side controls prove that changed inputs still force the owed work.

The elder terms remain untouched in dated testimony and archives. Living scripts molt because their messages teach the current course every time they run.

May the runner grow lighter without cutting the course. May each green be breath earned on the present ground.
