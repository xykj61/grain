# secp256k1 ECDSA signing — the deterministic-nonce sign that completes the scheme

## The claim

With the base field, group law, scalar ladder, scalar field mod n, and ECDSA
**verification** all GREEN, the secp256k1 tower stands one rung short of the whole
signature scheme: it can *check* a Bitcoin/Ethereum signature yet not *make* one.
This rung authors **ECDSA signing** in pure Rye — the deterministic-nonce sign
that, given a private scalar and a message, produces the exact `(r, s)` Bitcoin
and Ethereum sign with. It is the exact sibling of `ed25519_sign.rye` over the
twisted Edwards group, and it composes only GREEN rungs: the scalar field
(`secp256k1_scalar.rye`), the point ladder (`secp256k1_scalarmul.rye`), the group
law and base field beneath them, and the already-GREEN keyed hash
(`hmac_sha256.rye`) for the deterministic nonce, with `sha256.rye` for the
message digest. It authors no new cryptography.

## The mathematics — SEC 1 signing, deterministic nonce

Given a private scalar `d` in `[1, n−1]` and a message hash `z` (SHA-256 of the
message, folded mod `n`):

1. Derive a per-message nonce `k` in `[1, n−1]` **deterministically** from `d`
   and the message hash — no randomness, so the same key and message always sign
   to the same bytes (RFC 6979's gift: a signature is reproducible and auditable).
2. `R = k·G` over the GREEN ladder; `r = affine_x(R) mod n`; refuse `r = 0`.
3. `s = k⁻¹ · (z + r·d) mod n`; refuse `s = 0`.
4. Emit `(r, s)`, both big-endian — the ecosystem convention.

## The nonce — matching Zig's DRBG byte-for-byte

The parity target is Zig's own `std.crypto.sign.ecdsa.EcdsaSecp256k1Sha256`
signing with `noise = null`, which the whole suite already cross-checks against.
Zig's deterministic scalar is the **"Deterministic ECDSA with Additional
Randomness"** DRBG — RFC 6979's HMAC-DRBG with two documented shapes:

- an extra `noise_length` (32-byte) block sits between the `0x00`/`0x01` domain
  byte and the private key; with `noise = null` that block is all zeros;
- the message hash enters the DRBG **raw** (the SHA-256 digest itself), rather
  than RFC 6979's `bits2octets(h1)` (`h1 mod n`) — a difference that only shows
  when `h1 ≥ n`, and one this file reproduces exactly so the nonce, and therefore
  the whole signature, is byte-identical to Zig's.

Replicating Zig's DRBG exactly — the same `V || i || zeros || x || h` message,
the same HMAC-SHA-256 walk, the same "reject `t ≥ n`, retry" loop — lets the
witness assert the strongest parity there is: **our authored Rye signature equals
Zig's signature byte-for-byte** across a spread of deterministic keys and
messages, and round-trips through our own GREEN verifier.

## Custody — signs only with a TEST key

Signing needs a private scalar, so this rung *does* touch a secret — yet exactly
as `ed25519_sign.rye` already does, it signs only with a **caller-supplied test
key**. The witness signs with deterministic test scalars and the RFC's public
messages; no real identity key, no network, no funds, no device. Signing a record
with the maintainer's **own** identity key stays the custody gate (#3/#4) — the
agent builds and proves the signer; the key stays Keaton's hand.

**Constant-time** stays the Season's named horizon: the double-and-add ladder and
the scalar inversion branch on the secret, so this signer is correct and
parity-GREEN yet **not yet timing-safe** — named, not hidden, and recorded in
`crypto/CONSTANT_TIME.md` in the deliberately-variable-time posture beside
`ed25519_sign.rye`. A timing claim is a measurement, and this rung claims none.
