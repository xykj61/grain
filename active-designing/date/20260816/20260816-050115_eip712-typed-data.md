# EIP-712 — hashing a tree of typed data a wallet will sign, end to end

## The claim

EIP-191 personal_sign reads the signer of a flat string. Yet the signatures that
carry real value on Ethereum are almost never flat — a token approval, a DeFi
order, a gasless meta-transaction, a typed Sign-in-with-Ethereum all sign *typed
structured data* under **EIP-712**. Where personal_sign frames one string, EIP-712
hashes a **tree** of typed fields against a **domain separator**, so a signature
for one contract on one chain can never be replayed against another. This rung
authors that hashing scheme as a **composition** that adds no new cryptography —
only the EIP-712 encoding over three already-GREEN rungs: Keccak-256, ecrecover,
and the address derivation.

## The composition — an encoding over proven hashes

The building blocks are small and general, so a caller assembles any typed message
from them:

- `type_hash(encode_type)` — the Keccak-256 of a canonical type string.
- `word_from_address` / `word_from_u64` / `encode_string` — a field's 32-byte word:
  an address right-aligned, a uint256 big-endian, a dynamic string as its hash.
- `hash_struct(type_hash, fields)` — `keccak256(type_hash ‖ field₀ ‖ … ‖ fieldₙ)`,
  the one assembly every EIP-712 hash is built from (the domain, each nested struct,
  the message).
- `eip712_domain_separator(name, version, chainId, verifyingContract)` — the domain
  hash that binds a signature to one app on one chain at one contract.
- `eip712_digest(domain_separator, struct_hash)` — the value a wallet signs:
  `keccak256(0x19 0x01 ‖ domain_separator ‖ struct_hash)`. The 0x19 sentinel can
  never begin a valid RLP transaction; 0x01 is the EIP-712 version byte.
- `recover_typed_signer(digest, sig)` — splits the 65-byte `r ‖ s ‖ v`, recovers the
  public key with the GREEN ecrecover, resolves it to a twenty-byte address with the
  GREEN eth_address.

Every hash is the GREEN `crypto/keccak256.rye`; every recovery the GREEN
`crypto/secp256k1_ecrecover.rye`; every address the GREEN `crypto/eth_address.rye`.
This rung contributes only the EIP-712 byte layout over them.

## Custody — typed recovery is non-gated

Like verify, ecrecover, and personal_sign, EIP-712 recovery touches **no secret**.
The typed data, the digest, the signature, and the recovered address are all public
by construction — recovery reconstructs a public address from public data. So the
composed variable-time arithmetic leaks nothing already public. It answers *who
signed this typed message, for this app, on this chain?*, never *sign this*: signing
with the maintainer's own identity key stays the custody gate (#3/#4).

## The witness — three independent references, one bound to the world

`tools/crypto_eip712_witness.rish` asserts `GREEN crypto-eip712` three ways runnable
today:

- **A published known-answer bound to the world.** The EIP-712 spec's own canonical
  *Ether Mail* example (Cow → Bob) is assembled from these building blocks, and the
  spec's own published 65-byte signature recovers exactly Cow's own published wallet
  address `0xCD2a…D826` through our GREEN ecrecover. A one-bit encoding error would
  break the recovery — so this binds our byte layout to Ethereum's own reference, not
  merely to our self-consistency.
- **An independent construction.** Our digest equals a second digest built entirely
  from Zig's own `std.crypto` Keccak-256, byte-for-byte — a direct witness of the type
  hashing, word encoding, struct concatenation, and 0x1901 framing.
- **A full round-trip.** Our GREEN prehashed signer signs a typed `Permit` digest with
  a TEST key across six deterministic keys; the correct `v` recovers;
  `recover_typed_signer` returns exactly that key's own Ethereum address; and a
  one-byte tamper of the digest never recovers the true signer.

Registered in `crypto_suite_witness.rish` after `eth_personal_sign` as the sixth
composition — the count guard's bijection stays whole at forty files.

## Why this rung matters

The crypto wave named a *Kumara login against an Ethereum key* as the door the
recovery rungs open. EIP-191 opened it for a flat login message; EIP-712 widens it
to the typed data the Ethereum world actually signs — permits, orders, typed logins.
With this rung GREEN, Grain can verify any EIP-712 signature a wallet produces, and
build any typed message a hand will be asked to sign, without ever holding the key.
One composition, serving every permit and typed authentication the tree will meet.
