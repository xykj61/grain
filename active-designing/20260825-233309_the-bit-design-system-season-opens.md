## What Linengrow offers a design system

Linengrow's README (`linengrow/README.md`, last updated 2026-07-11, commerce steward demo nib 419) is a vision document for a civic social-commerce platform, and five of its habits read directly as design-system inspiration:

- **The visible receipt.** "Every sponsored post carries a visible label, every data sale carries a visible receipt, every contract carries a visible expiration." Honesty there is a surface property, so the design system inherits components whose whole job is disclosure -- the label, the receipt, the expiration -- drawn as first-class elements rather than fine print.
- **Transparent mechanism, private person.** "The mechanism is transparent; the individual is private." A surface that keeps both truths needs two registers: loud and legible for the room's rules, quiet by default for the person, with opt-in reveals the person controls.
- **The SLC ladder.** Linengrow grew receipt -> sealed delivery -> escrow -> reputation one lovable complete lap at a time, each lap closed by a numbered witness (152 through 209 in its own table). The design system can grow the same way: one component proven end to end before the next is named.
- **One spine.** State is a pure fold over an append-only log, and "the projection that folds a log into a view folds transactions into a verifiable receipt and a balance." A Bit component dresses a projection's output and leaves state to the log.
- **Trust by construction.** "Correctness by construction in the kernel becomes trust by construction in the platform." The design-system version already runs here: `tokens.rye` asserts its six palette invariants at construction, and Bit can keep that habit -- every design rule a checked bound rather than a style-guide sentence.

## First questions for DJINN's first sitting

Three questions, each drawn from something the modules measurably lack today:

1. **Typography.** Brushstroke holds one typeface, `font8x8_data.rye`, an 8x8 bitmap. Does Bit name a type scale, and what does a scale ask of a cell-grid paint target?
2. **Palette.** `tokens.rye` seats four named colors under six asserted invariants (warm hue, low blue, gentle lightness spread, paper hierarchy). Does Bit keep, extend, or replace them -- and which invariants should the constructors assert from here forward?
3. **Spacing and the first component.** The token sheet carries weight, space, and elevate fields, yet the Photos-journey modules place their chrome by hand-set coordinates. Which spacing scale does Bit seat, and which component earns the first pass -- the strip, the facet header, or the receipt card the Linengrow reading suggests?
