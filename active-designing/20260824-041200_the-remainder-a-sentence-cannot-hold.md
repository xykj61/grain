## The question

A defect is found, fixed in the places you can reach, and **partly left open**. How should the
open part be written down?

The obvious answer is: name it in the record, beside the fix. This tree did exactly that, and this
essay is about what happened next.

## What happened

A ledger row (REDS %175) recorded that the tree's dated-name test required an underscore where the
naming law makes that part optional. It repaired two places and closed with a sentence:

> *Open, and named:* **eight more scans carry the same narrow pattern** -- `one_clock_shape`,
> `dated_path`, `tracked_link`, `exec_bit`, `room_bound`, `prose_register`, `seed_link`,
> `tool_path_repoint`.

Careful, specific, honest, and countable. Every name in it was correct.

A later round set out to close the eight, and ran a search for the three spellings the tree writes
stamps in. It found **nineteen sites across fifteen files**: the eight, and eleven more the sentence
had left for someone else to discover.

**The row that recorded a fault about working from memory named its own remainder from memory.**

## The general shape

A remainder is a **measurement of the world** in exactly the way the defect count is. It has all the
properties that make a measurement worth taking:

- **It is checkable.** A search returns a count, and anyone can run the same search.
- **It moves.** Every commit after the row can add a twentieth, and the sentence stays at eight.
- **It is load-bearing.** A later round sizes its work from that number, so the number decides how
  much of the class that round reaches.

A sentence offers a different set of properties. It is written once, by a person who has just spent
hours on the fix and is reasoning from what they remember touching. It stays as written. And it
reads *exactly* as authoritative on the day it drifts as on the day it was true, which is the
property that does the damage.

> **A number that must stay true belongs to something that can be run again.**

The tree already knows this in another register. Its ledger headline once recited a count that had
stopped moving as rows accreted, and the repair was to **derive** it from a measurement rather than
recite it. Its front page carries generated numbers with a guard that reddens when they drift. Its
own naming law says to count a total with `git log` rather than carry it inside a name. This is the
same rule, arriving at the one place still open to it: the description of what is *left to do*.

## The counter-argument, at its strongest

A remainder written as a script costs more than a sentence. Somebody has to write the search, decide
its scope, and prove it refuses. For a small remainder that is genuine overhead, and a ledger
demanding a script for every open line would slow every closure down.

That is a real cost and it points at the boundary rather than at an exception. The test that seems
to hold:

**Write the remainder as a sentence when it names *specific things you have already looked at*.**
*The two rungs still open today are X and Y* is a claim about two objects, and it stays true or
shows plainly that it has changed.

**Write it as a script when it names a *class*.** *Eight more scans carry this pattern* is a claim
about every file in the tree, present and future, which is a claim larger than a sentence holds.

The tell is the word **more**, or **remaining**, or **other**. Each one quietly makes the sentence a
statement about everything beyond what you looked at.

## What it costs to get right, measured

Writing the guard for this class took roughly the same effort as fixing the eight sites by hand --
a scan, a control building real repositories, and a witness, against nineteen small edits. What the
guard bought beyond the edits:

- **The correct count.** Enumerating the class is what found the other eleven, and only a search
  over the tree enumerates a class.
- **The twentieth site.** It reds on the lap it arrives rather than in whatever future round happens
  to grep for it.
- **A second finding.** Two of the eleven unnamed sites carried a consequence past a miscount: one
  was the guard that refuses edits to dated artifacts, which could not see the very files it exists
  to protect. A sentence naming eight would have left that standing indefinitely, with every reader
  believing the list complete.

## The finding beside it

One more thing this round is worth recording, because it is the sort of result that repeats.

Widening the pattern on the **right** side -- accepting a name with no sprig -- immediately exposed
a looseness on the **left** that had stood since the meter was written: the stamp was free to begin
anywhere, including inside a longer filename. Twenty-four apparent losses turned out to be
substrings of retired names.

That fault had been unreachable, and specifically **because** of the narrow right side. The pattern
required an underscore after the stamp; the elder names put theirs *before* it; so every case that
would have revealed the left-hand looseness was excluded by the right-hand one.

> **Two constraints can hide each other. Loosening either one is how you find out.**

The practical form: after widening any filter, read the **new** matches individually rather than
only the count. The count says how much changed. The rows say what the filter had been passing
over, and that is where the older fault is waiting.

## What this asks of the next round

When a fix closes partly, look at the sentence you are about to write. If it contains *more*,
*remaining*, or *other*, it is describing a class, and the honest form is a script that can be run
again -- ideally one that gates at zero, so the remainder closes itself.
