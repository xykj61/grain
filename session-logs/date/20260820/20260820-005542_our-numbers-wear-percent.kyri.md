title Our own record numbers wear percent, and the commit messages are rewritten behind them
prompt Seat a molt breach deep debride replacing the number sign in REDS #89 with a percent sign as Glow terms do, unless a better character offers itself; GitHub autolinks any #NUMBER as an issue or PR and that is not what we mean; update the rules if I agree
think Checked the premise before acting on it, because half of it turned out to be wrong in a way that changes the work. GitHub's own documentation says plainly: autolinked references are not created in wikis or files in a repository. So REDS #89 inside crux/REDS.md was never a broken link. Only commit messages, issues, pull requests, and release text linkify. Saying so was worth more than agreeing quickly.
think The other half is not only right, it is worse than described. xykj61/grain carries pull requests numbered to #82, so a commit body saying REDS #80 has been rendering as a live link to an unrelated equinox PR. Measured rather than assumed: 230 of our own numbered references fall in #1 through #82, spread across 249 commit messages. That is real damage on a real surface, and it is the whole of the harm.
think On the character, I looked for a better one and did not find it, so the honest answer was a better reason rather than a different sigil. In Glow, as in the Hoon it descends from, % marks a constant term -- a value that is exactly itself and never varies. A REDS row number is exactly that: an immutable name for a fact recorded once and never edited, which is the ledger's own first law. The sigil says what the number is rather than merely dodging a renderer.
think Weighed the alternatives honestly. REDS-89 is plainest and collides with nothing. REDS89 would match the seated waymark-rung style (STOA345, JABS3). A bare REDS 89 reads ambiguously -- eighty-nine reds, or the eighty-ninth. The modulo objection against % is weak on inspection: every %digit in this tree is an expression like t%8 or r%27, bound tight with no space, never the shape REDS %89.
think The blast radius was much larger than REDS alone. gate #N, errata #N, OQ #N, study #N, red #N, rows #N are all our own numbering and all linkify the same way; PR #N is the one family that must keep its hash, because there the reference is true. Sampling the bare #N first was what saved this: 2,188 of them include SVG hex colors and url fragment references, so a blind sweep would have silently broken artwork.
think That sampling set the method. Every replacement is anchored to a family word, so the pattern can never reach a color or a fragment, and a continuation run -- gates #2/#4, Rows #1, #2, and #6, studies #55-#57 -- is converted only where it directly follows a converted head. Verified after the fact by grepping the diff for stop-color, stroke, fill, and url: nothing.
think Split the molt by tier rather than sweeping. 279 living files converted; 447 dated files -- session logs, counsel, waymarks, dated design notes -- left exactly as they recorded themselves. Since files never autolinked, converting them buys consistency rather than safety, and consistency is worth having on living surfaces so a row quoted out of a ledger and into a commit message arrives already safe.
think Scoped the history rewrite to commit messages alone, for the same reason. Rewriting historical file blobs would cost a far larger pass and fix nothing that was ever broken. The messages are where the links live, so the messages are what the debride spends itself on -- and PR #N is excluded by the same family anchoring the working-tree pass used.
obs The first attempt to build the file list returned zero, because git grep -E is POSIX and rejects a non-capturing group. Reading the count rather than trusting the command is what caught it; a silent zero is the most expensive kind of pass, since it looks exactly like a finished one.
obs This round is the third to lean on REDS %89's own fix. The assert-message repair from the last round is what made every verification here legible, and the habit it enforces -- report the fact, never a placeholder -- is the same habit this rule asks of a citation. A reference that points at the wrong thing and a message that names nothing are the same failure wearing different clothes.
obs A second history rewrite in one day is a real cost and is named as such: every downstream clone must re-clone again. It is spent here because 230 live links to unrelated pull requests is not cosmetic, and because the alternative -- leaving them and fixing only the future -- would leave the record pointing at work it never meant.
