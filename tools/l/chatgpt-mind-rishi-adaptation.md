## Same public boundary

The Rishi launcher carries `print`, `check`, `once`, `loop`, and `stop`, the
same arming and numeric ceilings, repository-local state, STOP and CUSTODY
gates, single-instance ownership, clean-tree and `xy` divergence checks,
gitlink preservation, the outer `ai-jail` plan and live write fence, and the
inner `codex exec --sandbox danger-full-access` call. It keeps user and project
rules while model selection and publication remain operator actions. It accepts
a completed lap only when exactly one descendant commit is clean and its
signature reads good or valid-but-untrusted.

The launcher canonically resolves the standalone installer's complete Codex
symlink chain before either planning or execution. The same absolute regular
executable path is the exact `ai-jail` map source and the enclosed argv path.
The launcher accepts the real Seatbelt plan only when full plan lines grant
read access and deny write access to that one canonical literal; basename,
prefix, alternate-destination, noncanonical-symlink, and read-write spellings
do not satisfy the proof. The isolated project-local `CODEX_HOME` reaches Codex
as the already-validated repository-relative `.mind-state/codex-home`. Codex
can canonicalize that short path wholly inside the allowed project subtree,
while the absolute path stays available to the supervisor for ownership checks
and operator messages. A bounded enclosed `codex --version` probe proves that
the jail can execute the program mapping without contacting a model. Before
`check`, `once`, or `loop` can pass, an argv-only, byte-bounded, enclosed `codex
login status` must confirm the same relative state; its output remains in
private preflight files. Login and execution receive only
`TMPDIR=/private/tmp`, an already-allowed private temporary root, so Codex does
not need metadata access to the broader `/var` ancestor during startup. The
outer jail's companion compatibility rule grants metadata on the literal
`/Users` node only, enough to canonicalize the already-authorized checkout;
it does not grant child reads, enumeration, or writes. Execution inherits the
repository root that `ai-jail` already establishes instead of asking Codex to
canonicalize the same checkout again through an absolute `--cd` argument. A
failed supervised lap
returns a bounded phase and reason such as Codex output, Codex exit, custody,
or Git postcondition while the detailed log stays private and retains the child
exit code.

The durable MIND seat is a full standalone clone: its worktree Git directory
and common directory must both resolve to the repository-root `.git` directory.
Linked-worktree indirection, alternates, and external common administration are
not launcher inputs. Every supervisor Git probe uses the canonical regular
Homebrew Git 2.53.0 executable at
`/opt/homebrew/Cellar/git/2.53.0_1/bin/git`. The outer plan maps that literal
read-only beside the canonical Codex executable, and the enclosed environment
receives the same executable in `GRAIN_MIND_GIT` and first on its explicit
PATH. Apple `/usr/bin/git`, `/var/select`, basename decoys, prefix mappings, and
read-write mappings do not satisfy the boundary. The project-local non-secret
Codex config is a regular mode-0600 file; authentication remains a separate
operator act.

The implementation differs only where the language makes the boundary more
explicit. The shell elder renders Arbor through its Brix descriptor; the pure
Rishi printer reads the descriptor's canonical `.arbor` tile directly. Their
complete prompt output is compared byte for byte. The public handoff follows
the neighboring Dream launch convention while keeping every live act in the
operational launcher. Its commands resolve the current checkout with Git,
quote every repository path, and change into that root before Rishi begins.
The shell live fence uses one small shell body; Rishi makes separate argv-only
`touch` probes inside and outside the same deny-by-default jail plan. Rishi
streams child input and both output lanes through declared byte ceilings, and
its runtime owns lock cleanup across normal return, refusal, explicit exit,
HUP, INT, and TERM.

The operational launcher opts into bounded live relay at both supervision
layers. Codex progress reaches the operator on stderr as it arrives and its
final stdout reaches stdout, while the identical accepted bytes remain in the
separate mode-0600 lap and supervisor files. The prompt stays on child stdin
only. A one-megabyte wall still governs each Codex stream; the supervisor has a
separate sixty-four-kibibyte margin for its own bounded status and refusal text,
so a stream at the exact wall cannot erase the typed phase that follows it.
