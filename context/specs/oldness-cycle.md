## The Question This Answers

A tree that keeps everything eventually holds documents that were true and quietly stopped being so. Immutability protects them from careless edits, which is right; yet immutability alone offers a reader no way to tell a page that still governs from a page that merely survives. And a shred — Amphora's parity-proven cut, which stays refused until a circled yes — must never be the thing that discovers which is which.

So two mechanisms answer together. A **safe list** names what no shred may touch. A **relevancy marker** lets any file say, in its own head, that it is still true.

## The Safe List

`SAFE.md` rests at root, append-only, and every shred consults it before it moves. Each row names a path, its founded stamp, the reason it is protected, the cycle through which the protection holds, and the word standing behind it. Any shred whose plan touches a listed path **refuses whole and loudly**, naming the row that stopped it — since a shred that silently skips a protected file and a shred that quietly destroys one look identical in a log.

The list carries a bound with its why: **at most sixty-four rows**, because a list a reader cannot review in one sitting stops being a safeguard and becomes a formality. Past the bound, protection consolidates by directory rather than by file, and the consolidation itself earns a row.

## The Cycle

Each shred commencement opens with an **oldness census**: count the rows, print each path's age from its founded stamp, and flag every row whose file carries no relevancy marker within the current cycle. The census is a printout, never an action — it informs a word rather than replacing one.

At the close of the shred, the safe count **re-baselines**. Every row is re-affirmed by Keaton's word, or it moves to a **review** state where it stays fully protected while awaiting attention. Nothing leaves the list by silence, and nothing leaves it by expiry — a row departs only by an explicit word, and its departure appends rather than deletes. Protection re-earned each cycle beats protection assumed forever, and the cost of re-earning it is one reading.

*Counsel's reading of "the safe count resets at the end of every shred commence" is the re-baseline above. If Keaton means something sharper — a hard zeroing, with every row re-added from scratch — one word corrects it, and the shape holds either way.*

## Founded, and Still True

The founded date already exists and needs nothing invented: every dated artifact carries its stamp in its own filename, which is exactly the founding date Keaton describes. What the convention lacks is the second date — the one saying *this is still true*.

Two paths reach it, and they differ sharply in cost.

**The accretion path, recommended.** The file's head gains one line — `current-as-of: {stamp}` — appended each time a reader confirms the page still governs, with the elder confirmations kept beneath rather than overwritten. The living-vs-dated spec already permits a living header on a dated file, so this needs no breach at all. Every inbound link keeps working, the filename keeps meaning what it always meant, and the file's own head tells its whole story: founded then, confirmed since, by these words.

**The rename path, available by declared breach.** The visible stamp advances to show current relevancy while the head carries `founded: {original stamp}`. This costs a declared breach, since `dated_guard` holds dated filenames immutable, and it costs every inbound link unless a pointer stub stays behind at the old name. In a tree as densely cross-linked as this one, that price is real and recurring.

Counsel recommends the accretion path plainly. A file that says *founded 20260730, current as of 20261115* tells a reader more than a renamed file does, keeps every link alive, and needs no breach spent. Where a rename genuinely serves — a name that has become misleading rather than merely old — the breach is available, and it wants a stub left behind so nothing ever rots.

## Queuing for Shred Readiness

A shred becomes ready when four conditions hold together: the safe list is censused and re-affirmed; every path in the shred's plan is named explicitly rather than matched by pattern; the fascia meter stands healthy enough that the tree is current rather than drifting; and Keaton's circled yes exists for that specific cut. Absent any one of them, the shred stays refused — which is the standing state and the safe one.

Amphora's cut is parity-proven, so a shred is never a synonym for a rename and never a synonym for a deletion. It carries parity, it verifies, and it restores. **Build nothing that destroys** governs here as everywhere.
